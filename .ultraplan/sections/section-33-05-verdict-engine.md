# Section 33-05: Verdict engine: geometry, image score, ledger

> Part of: WP-33 (Verification corpus and README gallery) · Items: none (TR-2 closes in 33-14) · Risk: red · Batch: 33.5 (alone) · Depends on: 33-03, 33-04, 33-02, 33-10 · Blocks: 33-08, 33-09, 33-14 · Tasks: 5, 1 commit · Case-id prefix: Q3305 (none used)

## Overview

With twoway's SVG, rc and message (33-03) and dash's SVG, rc, message and view dump (33-04) for each example, the corpus still has no verdict. The audit asks for "ticks, labels, titles, keys, glyph counts/extents and colours, with a known-differences ledger" (TR-2 Fix); Q18 puts geometry first and an image score second; [B §2.2] measured that SSIM alone is weak ("a picture with the legend in the wrong place still scores about 0.78", and 0.7785 for a plain twoway/dash pair).

After this section, `python3 scripts/corpus/verdict.py --run <run>` writes `<run>/verdicts.jsonl`: for each example its rc pair, a verdict (Same / Close / Differs), the measured differences (each tagged with the GAPS4 id that explains it, when the ledger has one), the image score, the glyph colours (judged within an RGB tolerance the calibration records, DECISIONS A-25), whether the gallery shows it, and a one-line summary for the caption (Q56) that names the differences in Stata terms -- "x-axis ticks", "legend keys", "marker symbol" -- never by GAPS4 id or by a check name containing an underscore (`titles` and `colours` are both a check name and the Stata term), which stay in the row's other fields (A-24). The verdict follows the architect's ruling A-4: geometry -- with the colour check A-25 adds -- decides Differs; the image score can only move a geometry-clean pair from Same to Close; there is no calibration stop rule, and the thresholds are recorded, not gating. Thresholds and tolerances, the colour tolerance among them, are measured by `scripts/corpus/calibrate.py` on a committed calibration set and written to `test/fixtures/corpus_verdict_rules.json`; the known differences live in `scripts/corpus/ledger.tsv`, compiled by `scripts/corpus/ledger.py` into `test/fixtures/corpus_ledger.json`, keyed by GAPS4 id (A-10: a row of a documented or partly closed item stays after the item closes, as a known difference). Examples twoway refuses, or dash refuses as a documented difference, are judged and kept as data, never shown in the gallery (P4-10). One function, `judge`, turns one example's two records into its verdict row; `run`, 33-09's guard and 33-14's first run all call it (the Published interface below).

**Test order and commit rule.** 33-05-01 writes the unit tests red and saves `<scratch>/33-05-01-failure.txt`; 33-05-02 the geometry readers, comparison, ledger and verdict rule; 33-05-03 the image score and `judge`/`run`; 33-05-04 calibration, the ledger and the one Makefile line; 33-05-05 asks the maintainer to confirm the calibration labels (the measured thresholds are shown, not asked about), after which the one commit is made: `Add the corpus verdict engine, its calibrated rules and the known-differences ledger (WP-33 33-05)`.

### Section decisions

- **D-33-05.a (verdict rule, A-4; replaces PD-14's T_close clause).** Let U be the differences outside tolerance that no ledger row explains, E those a ledger row explains, s the image score. Both rc nonzero: the checks are `rc` (the two codes) and `first_line` (the first lines after collapsing blanks); U and E empty -> Same; U empty -> Close; else Differs. Exactly one rc zero: the check `rc` differs (`twoway r(<a>)` / `dash r(<b>)`); explained by the ledger -> Close, else Differs. Both zero: the checks of D-33-05.b (geometry and colours, A-25); U not empty -> Differs; else E not empty -> Close; else, when the rules' `T_same` is `null` (D-33-05.d), Same with no image step; else s >= T_same -> Same; else (s < T_same, or s missing) -> Close, with the difference `{"check": "image", "twoway": null, "dash": s, "within_tol": false, "gaps4": null}` listed (its text `image score <s> below <T_same>` or `image score unavailable`). The image score never makes a Differs and never makes a Same alone; T_close is recorded only.
- **D-33-05.b (checks).** For both-rc-0 pairs, per figure (a by() graph compares its first panel only, recorded as `panels: "1 of <n>"`): `x_ticks`, `y_ticks` (tick values; equal when the counts are equal and every value matches within `tick_rel` x the axis span); `x_labels`, `y_labels` (label texts, blanks collapsed, U+00A0 read as a space -- svg_truth's rule); `axis_titles`; `titles` (title, subtitle, note, caption texts, order kept); `legend` (key labels in order); `glyphs` (marker count per layer when the twoway SVG's markers can be grouped by colour; else the total); `glyph_extents` (the data-space box of the drawn markers: twoway's marker centres inside the plot region, from `svg_layer.markers` over `svg_layer.svg_elements` and `svg_truth.svg_plotregion`, mapped to data linearly through `svg_truth.svg_axis_reading(path, axis)["fit"]` -- `v = low + (p - p_low) * (high - low) / (p_high - p_low)`, where `low`/`high` are the fit's edge values and `p_low`/`p_high` are `svg_plotregion`'s `left`/`right` on x and `bottom`/`top` on y, the edges `svg_axis_reading` hands `fit_axis_mapping` in axis order (svg_truth.py:557, :581), so `low` sits at `p_low` whenever the fit is not reversed; dash's union of the `x`/`y` `[min, max]` of its `Scatter` renderers; equal within `extent_rel` x each axis span; not measured, and no difference, when either side has no markers or either fit is missing, log10 or reversed (`fit["reversed"]`, an `xscale(reverse)`/`yscale(reverse)` axis)); `marker_shape` (the set of `svg_layer.marker_shape` values of twoway's marker groups inside the plot region against the set of dash's Scatter `marker` values, Bokeh's names read through `{"cross": "plus", "inverted_triangle": "v"}`, every other name as itself; compared only when both sides have markers); `frame_aspect` (plot-region width/height; equal within `aspect_abs`); `colours` (A-25; Q18 lists colours among the checks): twoway's set is the distinct `fill` and `stroke` colours (`none` and absent left out) of the `svg_layer.svg_elements` records whose `center` lies inside `svg_plotregion` (edges included), less the plot region's own background (a `rect` whose fill is `svg_plotregion`'s `fill`), less every `line` element of a grid or axis line, less every other horizontal or vertical element (all its `points` share one y, or one x) whose own `extent` is at least 0.95 x the region's width or height, and less a `fill` whose `fill_opacity` is 0 or a `stroke` whose `stroke_opacity` is 0. A grid or axis line is judged as a group, because stcolor draws a grid line as dash segments (measured on test/fixtures/svg_truth_smoke.svg: 260 `#f0f0f0` `<line>` segments inside the region, each 64.8 units long against a region 3752.8 wide, so no single segment reaches 0.95): `svg_truth.line_groups(svg_truth.svg_lines(path)["h"], "y1")` and `svg_truth.line_groups(svg_truth.svg_lines(path)["v"], "x1")` (svg_truth.py:413) group the horizontal and the vertical `<line>`s by off-axis position, stroke and width; a group whose span (`span_to - span_from`) is at least 0.95 x the region's width (h) or height (v) is a grid or axis line (measured on the smoke SVG: its grid and axis groups span 1.00 of the region, its tick marks 0.012-0.018); a `line` record of `svg_elements` belongs to it when its two points share the group's `px` (their y for h, their x for v, rounded to 2 places as both readers round), its `stroke` is the group's `stroke` and its `stroke_width` the group's `width`. Dash's set is the distinct `fill` and `line` colours of the dump's renderers (TR-33-04.2), each read as written: a string as it is, `{"value": c}` as `c`; a `{"field": ...}` or `{"expr": ...}` colour is counted in `unread` (its per-row colours are not in the dump); a `null` colour is left out; so is a fill colour whose `fill_alpha` is 0 (`0` or `{"value": 0}`), a line colour whose `line_alpha` is 0, and every colour of a renderer whose `visible` is false (an alpha given as a field counts as not 0). dash keeps real colours on glyphs it hides -- hollow markers' `fill_alpha` 0.0, the area patch's `line_alpha=0.0` with Bokeh's default line colour `#1f77b4`, the contour extent's invisible scatter (33-04's TR-33-04.2 cites the lines) -- and `#1f77b4` is 75 from stcolor's `#1a85ff` in blue, so without these rules every area and contour pair would carry a false `colours` difference. `rgb(text)` reads each as `(r, g, b)` -- `#rgb`, `#rrggbb` or `rgb(r, g, b)` with integers 0-255, either case; a colour it cannot read is left out of both sets and counted in the row's `colours.unread`. The sets agree when every colour of each has a colour in the other whose three channels each differ by at most `colour_tol` (D-33-05.d); otherwise the difference `{"check": "colours", "twoway": [<twoway colours with no counterpart>], "dash": [<dash colours with no counterpart>], "within_tol": false, "gaps4": ...}` (each `#rrggbb`, lower case, sorted) is listed. Not compared, and no difference, when either set is empty. The row still reports both full sets (`colours: {"twoway": [...], "dash": [...], "unread": n}`).
- **D-33-05.c (calibration set).** `scripts/corpus/calibration.tsv`, committed, 32 rows `id<TAB>label<TAB>mutation`, ids chosen from the de-duplicated examples.jsonl (33-02): 10 `Same` rows from the help examples of plain `scatter`, `line`, `connected`, `lfit`, `bar` with no option the audit flags; 10 `Close` rows whose only difference is an open GAPS4 item that one of D-33-05.b's checks sees (three histograms -> AX-4, `x_ticks`; two `by()` scatters -> AX-2, `x_ticks`, and VF-2, `axis_titles`; three `yscale(range())` beyond the data -> AX-1, `y_ticks`; two `a(b)c` labels crossing zero -> DG-3, `y_labels`); 12 `Differs` rows that are Same rows with a mutation applied to the dash command only (`title("Mutated")`, `msymbol(T)`, `yscale(log)`, `xlabel(none)`, `legend(off)` on a two-layer graph, and `mcolor(red)` on a one-layer scatter, two each). Every mutation changes a judged check (`titles`, `marker_shape`, `y_ticks`/`y_labels`, `x_labels`, `legend`, `colours`: Stata's red is 255 0 0, far outside any measured `colour_tol` of stcolor's first colour #1a85ff). PIC-1 (a missing area outline) is left out of the set: no check of D-33-05.b sees an outline (the `colours` check compares colour sets, and an outline in its fill's colour adds no colour), so a default `area` pair can only come out Same or image-score Close, never Close through a ledger row. The maintainer confirms the labels (33-05-05's one question).
- **D-33-05.d (thresholds from data, recorded; A-4).** In this order: `tick_rel` = 1e-6; `extent_rel` = 0.01; `aspect_abs` = min(0.05, the smallest multiple of 0.005 not below the maximum |aspect difference| over the rows labelled `Same` in calibration.tsv); then the **clean Same rows** are the rows labelled `Same` in calibration.tsv -- read from the file, before and whatever any GW-6 or `colours` ledger row below explains -- whose out-of-tolerance checks at these tolerances, `colours` left out, are none or `frame_aspect` alone, and that have an image score; then `colour_tol` (A-25) = the smallest integer not below the largest distance at or below 32 over the clean Same rows, a distance being a readable colour's distance to its nearest colour on the other side, the largest of the three channel differences; a distance above 32 is left out of that maximum -- so one Same row with a real colour difference cannot widen the tolerance for every pair, and the tolerance comes from colours that agree (A-25) -- and is a known colour difference: that row gets a `colours` ledger row (D-33-05.e) and is judged Close through it (below). When no such distance exists (no clean Same row has readable colours on both sides, or every distance passes 32), `colour_tol` is 0 with the printed line `calibrate: colour_tol 0: no clean Same row has a readable colour within 32 of the other side`. 32 (an eighth of a channel's range) is the bound so that a palette change (stcolor's #1a85ff against red, 229 apart) can never be read as agreement. `T_same` = the largest multiple of 0.005 not above `numpy.percentile(<s over the clean Same rows>, 5)` (numpy's default linear interpolation) when there are at least 3 clean Same rows; with fewer, `T_same` is `null`, `write_rules` prints `calibrate: T_same null: <n> clean Same rows with an image score, fewer than 3`, and the checkpoint and the commit body state that line. `T_close` = the largest multiple of 0.005 not above the minimum s over Close rows with a score (recorded only), or `null` when none has one. When the rules' `T_same` is `null`, D-33-05.a's image step is skipped: a both-zero pair with U and E empty is Same, its s still recorded. A Same row whose `colours` difference remains at that tolerance gets a `colours` ledger row naming the GAPS4 item the measured colours belong to (D-33-05.e; if GAPS4.md names none, stop and report it as a difference the register lacks), and is judged Close through it. A Same row whose aspect difference passes 0.05 gets the ledger row `GW-6<TAB>frame_aspect<TAB>*<TAB>*<TAB>default plot-region margins differ (45-04)` and is judged Close through it (AC-33-05.2); its label in calibration.tsv stays `Same` (what the pair is once 45-04 lands), so the row still counts as a Same row above. There is no stop rule: `thresholds` never raises, on an empty set included; the checkpoint shows where the Differs rows' s fall against T_same so the maintainer sees what the image score adds.
- **D-33-05.e (ledger, A-10).** `ledger.tsv` rows: `gaps4_id<TAB>check<TAB>plottype or *<TAB>when (a Python regex on the twoway command, or *)<TAB>note`, `gaps4_id` one of `<id>` (an open item to be fixed), `<id> (documented)` (a Kind Document item, or a difference its ruling documents: it stays after the item closes Documented), `<id> (residual)` (the residual of a Partly item: it stays after the item closes Partly). An item's state comes from GAPS4.md's Tracked lines (`ledger.gaps4_states()`: `open`, `closed`, `documented`, `partly`). A row is live when its form and its item's state agree: `<id>` with `open`; `<id> (documented)` with `open` or `documented`; `<id> (residual)` with `open` or `partly`. A difference is explained by the first live row whose check matches, plottype matches (or is `*`) and `when` matches (`re.search`, or `*`). Any check of D-33-05.b may be a row's `check`, `colours` included: a known colour difference is a ledger row like any other (A-25), e.g. `<id><TAB>colours<TAB>*<TAB><when><TAB><what differs, in RGB>`. `test_every_ledger_row_is_live` fails on a row that is not live, so every item's closing commit (Fix, Document or Partly) deletes its plain rows, and a Document or Partly item's `(documented)`/`(residual)` rows survive its closure (BRIEF's ledger bullet, refined by A-10).
- **D-33-05.f (image score).** Both SVGs are drawn by Chrome (one `CorpusProbe` of 33-04, opened on `<run>/raster.html` -- a blank page `<!doctype html><meta charset="utf-8"><title>raster</title>` that `run` writes -- with `ready="document.readyState === 'complete'"`, since the blank page loads no Bokeh) onto a white W x H canvas (W, H of D-33-04.b), converted to luminance `round(0.299 r + 0.587 g + 0.114 b)`; SSIM is Wang 2004 with a Gaussian window (sigma 1.5, `scipy.ndimage.gaussian_filter(..., truncate=3.5)`, K1 0.01, K2 0.03, L 255), averaged over the image less a 5-pixel border (scikit-image's crop) [B §2.2].
- **D-33-05.g (fixtures).** Both JSON fixtures carry `_meta` with the five keys of test_fixtures_are_committed.py `META_KEYS`: `stata_version` from `<run>/stata_version.txt` (33-03), `born_date` and `extracted` the run's date (`%d %b %Y`), `dash_commit` from `git rev-parse HEAD` (subprocess list arguments, never `shell=True`), `source` the generator's repo path. They are added with `git add -f` and given GENERATORS rows.
- **D-33-05.h (gallery eligibility, P4-10).** A row's `gallery` is true only when twoway drew it (`rc_twoway == 0`) and it is not a dash refusal explained by a `(documented)` ledger row (`rc_dash != 0` with its `rc` difference explained by `<id> (documented)`); every other example stays in the verdicts (and in 33-08's corpus.json) with both answers. ## Risk: [red] -- the verdicts the README shows

**Why.** A wrong rule publishes Same where twoway differs, or buries real agreement under noise (PRD §10 risk 5). **Risk factors.** SVG reading across schemes; colour reading (translucent and unreadable colours, a grid or axis line taken for a glyph); by() and multi-axis pages; SSIM's weakness; default margins differing everywhere (GW-6, VF-4); ledger rows outliving fixes. **Mitigation.** The geometry and colour checks alone decide Differs, so SSIM's weakness cannot hide a difference (A-4, A-25); every calibration mutation is caught by a named check (AC-33-05.2), a colour mutation among them; thresholds are measured and shown at the checkpoint, never forced; the ledger is tied to GAPS4.md's states by a test.

## User stories

- US-33-05.1 As the README reader, I want each pair labelled Same, Close or Differs with the differences named in Stata terms so that I can trust the gallery.
- US-33-05.2 As the maintainer, I want known differences tied to their GAPS4 items so that a fix shows up as a better verdict and a documented difference stays known.

## Business requirements

- BR-33-05.1 Every example with both records gets exactly one verdict by D-33-05.a's rule; a skipped one gets its skip reason.
- BR-33-05.2 A verdict of Same is never given on the image score alone, and the image score never makes a Differs.
- BR-33-05.3 Thresholds and tolerances are measured on a committed set and recorded with their date and commit.
- BR-33-05.4 A known difference is listed with the GAPS4 id that explains it; a fixed item's differences stop being explained, a documented one's stay explained.
- BR-33-05.5 Only examples twoway draws, and not dash's documented refusals, are marked for the gallery.
- BR-33-05.6 Each glyph's fill and line colour is judged against twoway's within a tolerance measured on the calibration set and recorded; a known colour difference is listed like any other (A-25).
- BR-33-05.7 The one-line summary a reader sees names each difference as a Stata user would ("x-axis ticks", "legend keys", "marker symbol"), never by a GAPS4 id or a check name containing an underscore; `titles` and `colours` are both a check name and the Stata term (A-24).

  let s = "";
  for (let i = 0; i < out.length; i += 8192)
    s += String.fromCharCode.apply(null, out.subarray(i, i + 8192));
  return btoa(s);
})
