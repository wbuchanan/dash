- **D-35-05.a One generated table.** `scripts/gen_value_refusal_table.py` writes `_dash_tw_value_tab()` (dash_parse.mata, between `// BEGIN tw_value` and `// END tw_value`) from value_truth.json and value_codes_truth.json: one row per (option, types, class) with twoway's rc and its first line, `%v` standing for the value as typed. `_dash_validate_value` looks a refusal up there before printing dash's sentence; a refusal with no row keeps dash's sentence (listed in the commit body as the residual set; expected empty for the fixtures' probes).
- **D-35-05.b Classes.** A failing value is classed `nan` (not a number), `nonint`, `below`, `above`, `missing` (`.`), `huge` (beyond Stata's double range); the class is what the rule's check already computes.
- **D-35-05.c Lifted bounds draw twoway's picture.** For each lifted value the extractor records whether twoway's SVG equals a reference (`jitter(-3)` and `jitter(abc)` vs no jitter under the same seed; `barwidth(-1)` vs no barwidth(); `aspectratio(-1)` vs none; `msize(1e400)` vs none; `lwidth(-1)` on scatter vs none; `msangle(400)` on line vs none; `jitterseed(-1)` -- a new seed each draw, so only rc). - **D-35-05.d Where-drawn bounds.** `lwidth()`/`mlwidth()`/`msangle()` bounds apply only on the types where twoway draws that element: a type list per option from the fixture's per-type probes, written as `@type|type` on the rule token (the `alwidth` token's form, dash.ado:3704).
