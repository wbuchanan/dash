## Overview

**What is wrong today.** Seven environment items of the audit's package 2 (audit :91-114; appendix :2268-2340) are true and undocumented or mis-documented. dash has run only on console StataNow 19.5 on macOS arm64; the browser opener, the `os.name == "nt"` branches and the POSIX-sh runners have never run elsewhere (plat:PT-5, with TR-20 and ECO-17). dash refuses Stata 18.5 and older, r(9), where twoway runs on Stata 8 and later (plat:PT-2). It needs Python 3.11+ with bokeh 3.8-3.9, numpy and pandas (plat:PT-11). Its hash-pinned lock covers Python 3.11-3.14 on five platform tags, so Python 3.15 and Windows ARM64 fail there (plat:PT-12). `saving()` expands only a leading `~/` and only from `HOME` (dash.ado:756-763), so `~\dir\x.html` on Windows is a relative path (plat:PT-6). The help says the page "works offline in any modern browser" (dash.sthlp:172-174) and Differences item 1 says it can be "opened in any browser" (:814), where only Chrome is tested (plat:PT-16). A million rows take about 6-8 s and 1.4 GB of Stata's memory (the audit's measurement at `7dced3a`), and the page holds its numbers as JSON lists (plat:PT-14).

**What will be true after.** Ruling M8 (Q31, Q33, Q46, Q47, Q49, A1): each item is resolved by documentation, with no code change. The help and README state that dash is run only from the console and that Windows, Linux, Intel macOS and Stata's graphical interface have not been run; the drop-in claim is for Stata 19 and later; the Dependencies section lists what dash needs and says nothing else is needed; dash_setup's help states the lock's coverage and that Python 3.15 and Windows ARM64 are not covered; the saving() paragraph states the `~` rule; the Description says dash is tested in Chrome and problems in other browsers are not dash's to solve; Resource limits states the large-data timings as re-measured at this batch's base. The existing tested-release sentences of dash.sthlp, dash_setup.sthlp, README.md, dash.pkg and CHANGELOG.md stay exactly as they are (M2, DECISIONS A-2): every new sentence is added beside them, and `test_version_floor.py::TestTheStataFloor::test_every_stata_declaration_agrees` keeps pinning them, unflipped. Each documented item has a help-claim test and, where measurable, a probe that dash does what the sentence says.

**Test order and commit rule.** Seven items, seven commits, in the manifest's order (plat:PT-5, plat:PT-2, plat:PT-11, plat:PT-12, plat:PT-6, plat:PT-16, plat:PT-14).
