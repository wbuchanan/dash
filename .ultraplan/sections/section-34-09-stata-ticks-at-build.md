## Overview

**What is wrong today -- AX-3.** At export dash asks Stata's `_natscale`/`_tsnatscale` only for counts {5} plus any `#N` matched by `[xy]\d?(label|tick)` (dash_render.py:41832-41838), only over variable ranges, and skips histogram, kdensity, function, scatteri, pci and pcarrowi layers (`_DASH_STATA_TICK_SKIP`, :41811-41812). Every other axis is ticked at build by dash's fitted natscale model, so the model's misses reach the first drawing (AX-3, measured): by() y on price -- twoway 5,000 10,000 15,000, dash 0(5000)15000 (B2 `scatter price mpg, by(foreign)`, C42 `by(rep78)`, B6 `by(foreign, yrescale)` panel 1); `kdensity price, by(foreign)` x likewise (B4); `line close date, xlabel(#4) xscale(range(14700 15600))` -- twoway half-yearly 01jan2000 ... 01jul2002, dash yearly (E2); `ymtick(#4)`/`ymlabel(#4)` never asked (N3, N4, visually identical); `qfitci mpg weight, stdf || scatter mpg weight` -- twoway y 10(10)40, dash 0(10)40 (TR-5, cause unproven); and the colour key: `line mpg weight, colorvar(trunk) zlabel(#3) sort` -- twoway keys 0 20 and draws two colours, dash keys 0 10 20 and draws three (CV-13), because the colour-key tick calls made at build pass no table (:16773, :29216/:29224, and zlabel(#N)'s count in `_dash_apply_z_options`, :56929-56930, the call CV-13's `zlabel(#3)` takes). `_dash_cvar_ticks` (:52420/:52422) passes none either, but it runs only after a served filter move (the filter callback's step 3c, :71393-71395), so it is no cause of the build-time CV-13 drawing and is left on the model (D-34-09.k). **What stays open -- plot:PT-13.** After a filter move the saved page and the served app run without Stata, so they keep placing ticks with the model, which misses 3 of 264 measured axes (auto price #4, trunk #2 and #3). **After this section**, wherever dash builds a page inside Stata (every `dash` route goes through `_dash_do_render` -> `main()` in Stata's Python): every axis count tick placed at build -- variable ranges, by() panels at their reduced count, `xmtick(#N)`/`xmlabel(#N)`, histogram midpoints, kdensity and function grids, fit grids and bands, immediates, range()-widened `#N` axes, date axes and every colour key -- is Stata's own answer for exactly the range dash draws, in both modes: the saved render asks Stata as it places each tick set; the served route runs one figure pass in Stata before writing the app and embeds the answers, and the served app's axes, colour keys and minor counts read them from the figure they draw on (DECISIONS A-16), so the served app's first drawing is the same. - **D-34-09.b. - **D-34-09.c. Stata is asked with numbers only.** `_return hold <name>`, then `capture _natscale %.17g %.17g <n>` (or `_tsnatscale ..., <unit word>` from `_DASH_STATA_TS_WORDS`), then `scalar <rcname> = _rc` (a fresh `__dashrc<hex>` name), then r(min), r(max), r(delta), r(n) through `sfi.Scalar.getValue` and r(list) through `sfi.Macro.getGlobal("r(list)")`, then `capture scalar drop <rcname>` and `_return restore <name>`. ## Risk: [red] -- the renderer calls Stata at build time for many axes, and the served route builds its figures twice

**Why.** A wrong command, an r() clobbered, a slow loop over by() panels, or an answer recorded for the wrong range changes every build; the served pre-pass doubles a served build's figure time.

**Risk factors.** 1. r() of the caller (dash's own programs read r() after `_dash_do_render`?). 2. `sfi` stand-ins in tests (`_FakeSfi`, other modules' fakes) lacking `SFIToolkit`. 3. by(rep78) with yrescale: 6 panels x 4 axes x counts. 4. TR-5's cause may be twoway's range rule, not the model (the audit could not prove it). 5. `render(page=False)` must build exactly what `render()` builds. 6. Saved and served must stay identical (parity guard). 7. A colour key that read a table in the served refit would restore Stata's ticks after a move back to all rows, where the saved page's relevel keeps the model; one that read none at build would draw the model in the served app where the saved page draws Stata's.

**Mitigation.** 1. `_return hold/restore` around every call, pinned by a fake-sfi unit test of the command order; 2. the oracle catches every exception and is off unless `main()` turned it on; 3. cscript timing cases (Q3409-7: under 1 s added on by(rep78, yrescale); Q3409-10: the served pre-pass on 1,000,000 rows, measured and documented); 4. the 34-09-02 checkpoint (matching only, A-16) and 34-09-03's match with its own regression test; 5. a unit test that `render(page=False)` leaves the same figures (tick lists) as `render()`; 6. parity CORPUS entries built from a spec carrying the oracle's rows, colour keys included; 7. the table is read from the drawing figure, stamped before the layers at build and absent from the served refit's throwaway figure (D-34-09.k), pinned by a served-against-saved test at build and a served move test, and by Q3409-9 live.

    asked while dash builds the page inside Stata (WP-34 AX-3), or None:
    off outside main() in Stata, past _DASH_STATA_ORACLE_MAX calls, for a
    range of no width, or when Stata gives no answer (a non-zero rc, a
    missing or absent value).  Numbers only reach Stata (%.17g); r() is
    held and restored around the call.  Each answer is appended to the
    build's rows; the funnel keeps it in the asking graph's table."""
    st = _DASH_STATA_ORACLE
    if not st.get("on"):
        return None
    try:
        lo, hi, n = float(lo), float(hi), int(n)
    except (TypeError, ValueError, OverflowError):
        return None
    if not (math.isfinite(lo) and math.isfinite(hi)) or lo >= hi \
            or not 1 <= n <= 99 or unit not in _DASH_STATA_TICK_UNITS:
        return None
    key = (lo, hi, n, unit)
    if key in st["cache"]:
        return st["cache"][key]
    if st["calls"] >= _DASH_STATA_ORACLE_MAX:
        return None
    st["calls"] += 1
    ticks = None
    try:
        import sfi
        tk = sfi.SFIToolkit
        tag = secrets.token_hex(4)
        hold, rcname = "__dashrh" + tag, "__dashrc" + tag
        tk.stata("_return hold " + hold)
        try:
            if unit == "":
                tk.stata("capture _natscale %.17g %.17g %d" % (lo, hi, n))
            else:
                tk.stata("capture _tsnatscale %.17g %.17g %d, %s"
                         % (lo, hi, n, _DASH_STATA_TS_WORDS[unit]))
            tk.stata("scalar %s = _rc" % rcname)
            rc = sfi.Scalar.getValue(rcname)
            sv = [sfi.Scalar.getValue("r(%s)" % k)
                  for k in ("min", "max", "delta", "n")]
            listed = sfi.Macro.getGlobal("r(list)")
        finally:
            tk.stata("capture scalar drop " + rcname)
            tk.stata("_return restore " + hold)
        bad = (rc is None or sfi.Missing.isMissing(rc) or rc != 0
               or any(v is None or sfi.Missing.isMissing(v) for v in sv))
        if not bad:
            ticks = _dash_stata_ticks_of(unit, lo, hi, sv[0], sv[1], sv[2],
                                         sv[3] if math.isfinite(sv[3])
                                         else 0, listed)
    except Exception:  # noqa: BLE001 -- no answer: the model draws
        ticks = None
    st["cache"][key] = ticks
    if ticks:
        st["rows"].append([lo, hi, n, unit, list(ticks)])
    return ticks
