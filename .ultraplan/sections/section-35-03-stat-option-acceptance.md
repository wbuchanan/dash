## Overview

**What is wrong today.** Six spellings or values twoway takes on its statistical types are refused (audit package 11; appendix type-options-stat and syntax-data):
- **stat:PT-7/syn:SD-6** `lowess mpg weight, m` (twoway_lowess_parse.class:38-39 declares `Mean`, minimum m; the serset equals `mean`'s: mean 21.29768, sd 3.895097) is refused `option m not allowed` / `twoway does not take this option here.`, because dash.ado:1274 declares `MEan` (the comment at :1664-1671: one letter longer to avoid `Msymbol()`).
- **syn:SD-5** `bwi(#)` on lowess, kdensity, lpoly, lpolyci (each parse class declares `BWidth`, minimum bw; `bwi()` = `bwidth()` by SVG md5) is refused `option bwi() not allowed`: dash.ado:1266 declares `BWIDth(string)` and :1318 an exact `BW(string)`.
- **stat:PT-13** contour/contourline: `i()`/`int()` (interp), `colorl` (colorlines), `clp()`/`clw()` (clpatterns()/clwidths()) -- twoway_zyx2view_parse.class:61-62, 76-80, 89-106; twoway_contourline.sthlp:44, 53, 58 -- are refused or read as clpattern()/clwidth(); dash.sthlp:599-601 says they must be typed in full.
- **stat:PT-6** `function y = t^2, subchar(t)` draws t^2 in twoway (serset 0, .25, 1, 2.25, 4; twoway_function_parse.class:55-71 `SUBChar(name)`, passed as `x()` to twoway__function_gen); dash gives r(111) `error in expression: t^2` because dash.ado:10448 hard-codes `x(x)`; `subchar(1t)` is rc 0 with a note where twoway gives r(198) `1t invalid name`.
- **stat:PT-9** `mspline bands(-1)` (Bands(integer -1), the default sentinel), `fpfitci n(0)` (n is not used), `lfit n(-1)` (an empty fit) are rc 0 in twoway and r(198) in dash with its bound sentence.
- **syn:SD-7** `ty()` on lfitci/qfitci/fpfitci/lpolyci: twoway's CI parsers declare `TYPE` in capitals (twoway_lfitci_parse.class:34-37, twoway_lpolyci_parse.class:38), so only the full word `type` is refused; `ty(line)` is rc 0 and draws (320 vs 319 lines). dash.ado:3248-3252 refuses any value bound to `TYpe`/`RECASTAs` there.
