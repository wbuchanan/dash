# Section 47-02: varlabel and varformat reach every type; mlabel(t*); emptied-layer names

> Part of: WP-47 (Plot-option fidelity, P15) · Items: MS-2, MS-3, MS-5, basic:PT-3, DG-7 · Risk: yellow · Batch: 47.2 · Depends on: 47-01 · Blocks: 47-04 · Tasks: 6, 5 commits · Case-id prefix: Q4702

## Overview

**What is wrong today.** Five text defects in titles, keys and marker labels (audit package 15; appendix "series-lists-merges" MS-2..MS-5, "type-options-basic" PT-3, "data-values-edges" DG-7, "tracking-tests" TR-6):

- **MS-2 (with TR-6).** `yvarlabel()`/`xvarlabel()` are ignored on scatteri, pci, pcarrowi, function, kdensity and histogram. twoway: scatteri and function are titled Q/R, "kdensity mpg, xvarlabel("M") yvarlabel("D") is titled D/M", "histogram is titled 'D/Density' on y and M on x", pci's y is 'Q/R' and x 'S' + '/xb'; `function y=x, range(close) yvarlab("y=x")` keys 'y=x' (TR-6). dash draws the fixed texts: `_dash_layer_series` returns before reading `_yvl`/`_xvl` in those branches (dash_render.py:58096-58118). The help says "the axis titles and the legend keys take them" (dash.sthlp:4760-4763, Appendix B HR-13).
- **MS-3 (with MS-4).** `yvarlabel("")` gives the key 'scatter' and no y title; twoway uses the variable's name ("scatter mpg weight, yvarlabel("") is titled 'mpg'"). And twoway relabels a variable in every plot -- "the last yvarlabel given for mpg wins in every plot" ((scatter mpg weight, yvarlabel("A")) (scatter mpg length, yvarlabel("B")) keys B,B with y title B) -- where dash applies it per layer.
- **MS-5.** `xvarformat()`/`yvarformat()` do not reach marker labels of the plotted variable: twoway labels `mlabel(mpg) yvarformat(%9.2f)` "22.00, 17.00"; dash draws "22, 17".
- **basic:PT-3.** `mlabel(t*)` naming several variables draws labels; twoway draws none ("scatter mpg price weight in 1/5, mlabel(t*) draws no marker labels: 12 <text> elements, the same as without mlabel"). dash expands the pattern with unab (`_dash_mlabel_list`, WP-31 C10b) and draws LabelSets for trunk and turn. The help contradicts itself (dash.sthlp:1238-1240 says dash refuses it; :3389-3393 says "as in twoway"), and BUGS C10b was closed from serset rows, not the picture.
- **DG-7.** Titles and keys of emptied or unfittable layers: `lfit mpg weight if price<0` is titled 'mpg' by twoway ("the fit variable is left unlabelled when regress cannot fit"), `lfit y x` on no observations 'y', `histogram mpg if price<0` x title 'x'; dash writes 'Fitted values' and 'Mileage (mpg)'.

**After this section.** Every type takes `yvarlabel()`/`xvarlabel()` as twoway does; `yvarlabel("")` means the variable's name; a variable's last `yvarlabel()`/`xvarlabel()` in the graph relabels it in every plot; marker labels of the plotted x or y variable take that layer's `xvarformat()`/`yvarformat()`; an `mlabel()` pattern naming several variables draws no labels; an emptied fit is titled and keyed by its y variable's name and an emptied histogram's x axis 'x'. Both modes (all of it is shared Python: `_dash_layer_series`, `_apply_mlabel_opts`, dash.ado's mlabel reader).

**Why together.** All five are the text of series and labels, decided in `_dash_layer_series` / `_dash_axis_default_titles` / `_dash_legend_key` and `_dash_mlabel_list`; one extended truth script measures them.

**Test order and commit rule.** 47-02-01 extends the truth script and writes MS-2's failing tests (no commit); 47-02-02 fixes MS-2 and commits; 47-02-03..06 each write the item's failing tests first (saved failure text), then fix, then commit, in the order MS-3, MS-5, basic:PT-3, DG-7. No full suite inside the section.

### Section decisions

- **D-47-02.a — Branch texts (MS-2).** In `_dash_layer_series`: scatteri `(Ly("y"), Lx("x"))` with `Ly`/`Lx` falling back to `"y"`/`"x"`; function `(Ly(<yname>), Lx("x"))`; kdensity `(Ly(<"kdensity <var>">), Lx("x"))` -- the strings replace the whole text; histogram y `Ly + "/" + <scale word>` when a yvarlabel is given (measured 'D/Density'), else the scale word; histogram x `Lx(var)`; pci/pcarrowi y `pair` of the first two yvarlabel strings (default 'y/yb') and x `Lx + "/xb"` (measured 'S' + '/xb'; 47-02-01 records whether that is one line or two and the code follows the measurement). Each exact text comes from the fixture, never typed.
- **D-47-02.b — "" (MS-3).** A quoted `""` in `yvarlabel()` means the variable's name (not its variable label), in keys and titles. The measured `xvarlabel("")` rule (no x title, varlabel.x_empty) stays. `_dash_legend_key`'s fall-back to the plot-type word stays only for a spec with no y variable at all (hand-written specs); it is unreachable from Stata after this change.
- **D-47-02.c — graph-wide relabel (MS-4).** New pure function `_dash_graph_varlabels(plots)` -> `{"y": {var: text}, "x": {var: text}}`: plots in draw order, each plot's k-th yvarlabel string mapped to its k-th y variable (data layers `yvar`; range `yvar1`, `yvar2`; pc `y1var`, `y2var`; rangept the three), its xvarlabel to `xvar`/`x1var`; a later plot overrides an earlier for the same variable. `Ly(name, k)` reads it before the variable label. Fit layers keep their own first string as today (their y is a generated variable, not `name`); 47-02-01 measures `(scatter mpg weight, yvarlabel("A")) (lfit mpg weight)` and `(lfit mpg weight, yvarlabel("Q")) (scatter mpg weight)` and the rule follows the measurement. Plots with different if/in (the verifier's caveat) are measured (`(scatter mpg weight if foreign) (scatter mpg weight if !foreign, yvarlabel("B"))`).
- **D-47-02.d — formats on labels (MS-5).** In `_apply_mlabel_opts`, when no `mlabformat()` is given and `mlabel_var` is the layer's own y (or x) variable and the layer has `yvarformat()` (or `xvarformat()`), the labels are written through `_mlabformat_column` with that format. `mlabformat()` wins over the varformat (measured in 47-02-01: `mlabel(mpg) yvarformat(%9.2f) mlabformat(%9.1f)`).
- **D-47-02.e — patterns (basic:PT-3).** `_dash_mlabel_list` keeps unab's expansion for a pattern that names exactly one variable; a pattern naming two or more draws no labels for the y's its names would cover -- or for the whole layer, as 47-02-01 measures (`mlabel(t*)` on 1 and 2 y's, `mlabel(make t*)`, `mlabel(t* make)`, `mlabel(tr*)`, `mlabel(make-foreign)`). The record of C10b in BUGS.md gets one appended sentence: `Corrected by WP-47 basic:PT-3: a pattern naming several variables draws no labels.`
- **D-47-02.f — emptied layers (DG-7).** New pure function `_dash_empty_layers(plots, df)` -> set of plot indices whose rows (the plot's `qual_col` and the graph's, the y and x columns finite, weights above zero where weighted) number zero, for the fit types (`_DASH_FIT_TYPES`, `_DASH_CI_TYPES`) and histogram only. `_dash_layer_series(plot, ..., empty=False)` returns `(name("yvar"), Lx(xvar))` for an empty fit (key and title) and `(<scale word>, "x")` for an empty histogram. Callers pass `empty=i in empties`. Emptiness is judged on the build rows -- qualifiers applied, no filter widget -- the same in both modes (the saved page's `self.df` and the served template's `g_df`, which arrives qualified, hold the same rows: both before any widget move); a filter move never changes a title or a key, in either mode, whatever rows it leaves (twoway draws one picture; the move is dash's own). The one call `_dash_empty_layers(plots, self.df)` sits in `_make_figure_body` just before `_dash_axis_labels` (dash_render.py:63392) and in the served template's twin line (the `_dash_axis_labels(plots, go, var_labels,` literal near :70281); see Notes for the R12 claim.

## User stories

- US-47-02.1 As a Stata user, I want `yvarlabel()`/`xvarlabel()` honoured on every plot type so that my titles and keys read as in twoway.
- US-47-02.2 As a Stata user, I want `yvarlabel("")` to show the variable's name and a variable relabelled once to be relabelled in every plot, as twoway does.
- US-47-02.3 As a Stata user, I want `yvarformat()` to format the marker labels of that variable so that `mlabel(mpg) yvarformat(%9.2f)` writes 22.00.
- US-47-02.4 As a Stata user, I want `mlabel(t*)` to draw what twoway draws (nothing) so that my graph is not cluttered differently.
- US-47-02.5 As a Stata user, I want an empty fit or histogram titled as twoway titles it.
