# Section 37-01: One zero-observation check copying twoway per case

> Part of: WP-37 (Statistical and computed layers) · Items: DG-1 · Risk: red · Batch: 37.1 · Depends on: none · Blocks: 37-02 · Tasks: 4, 1 commit · Case-id prefix: Q3701

## Overview

**What is wrong today.** The audit (package 12, DG-1, audit :640-642; appendix :3254-3259): "contour over zero observations crashes with a Python traceback, r(7102)". `twoway contour price mpg weight if price < 0` draws an empty plot with the axis titles and a colour key titled 'Price', rc 0 (re-measured 20oct2026: the SVG holds the texts `Mileage (mpg)`, `Weight (lbs.)`, `Price`, the key's axis line and no key box). dash prints a traceback ending `RuntimeError: dash_render: failed to build figure '': lower_level and upper_level cannot be NaN` and writes nothing: with no rows `map_contour` (dash_render.py:24309) gets `zmin = zmax = nan`, `_dash_contour_cuts` returns `[nan]`, the not-drawable branch builds `lv = [0.0] + [nan] + [1.0]` and `fig.contour(..., levels=fl)` (:24424) raises. Ruling D40 for package 12 asks for one Stata-side zero-observation check, after the qualifiers and before Python, for every plot type.

**What twoway does (research [S] §3, 400 probes, StataNow 19.5).** twoway draws an empty graph, rc 0, for 34 of 40 data types in every case (a plot's `if 0`; one empty plot among several; a graph-wide `|| if 0`; an `in`/`if` selecting nothing; an all-missing y; one empty by() panel). It refuses only: lpoly/lpolyci r(2000) `no observations` (also on an all-missing y); fpfit/fpfitci r(198) `observation numbers out of range` after `(note:  fracpoly could not fit model)` (not on an all-missing y); mband/mspline r(198) `bands must be between 1 and 200` (not on an all-missing y); and a by() graph whose every panel is empty, r(198) `nothing to graph`, for every type, function, scatteri, pci and pcarrowi included. dash already matches 389 of 400 probes: the 11 gaps are contour's crash (7 cases) and by() + `if 0` on function, scatteri, pci and pcarrowi (dash draws).

**What will be true after.** Ruling M9 / PD-15 / C1: one program `_dash_zero_obs_check` runs at export on every route (the one-line form, `dash build`, `dash serve`), after every working column is made and before `_dash_write_data` and Python, and applies a Mata rule table copying twoway's answer per type and case; it catches samples a build-time re-evaluation empties, which reach Python today. Where twoway refuses, dash prints twoway's words first and then one line naming the plot's number and type; the registration-time refusals of `_dash_process_segment` and `_dash_plot`'s by() block, which stay (PD-15), print the same second line; the by() block refuses an all-empty graph of literal types as twoway does. Where twoway draws, dash draws: `map_contour` draws an empty layer and the titled key with no rows, in both modes.

**Test order and commit rule.** One item, one commit. Task 37-01-01 writes the extract script and fixture and every failing test and the S01 block, saves the failure text, no commit; 37-01-02 adds the rule table, the check and its wiring; 37-01-03 fixes `map_contour` and the by() literal gate; 37-01-04 flips pins, edits the help, closes DG-1 and commits once with the subject ending `(WP-37 DG-1)`.

### Section decisions

- **D-37-01.a Cases the rule reads, and their order.** A by() graph is judged by `byempty` alone, also when `_N == 0`, literal types included: no row of the panel base -- the graph's qualifier, or with one plot and no graph qualifier that plot's -- has its by() variables present (unless `missing`), counting the Total panel's twin column under `total`; its per-plot cases are the renderer's (panel dropping). A graph without by() is judged per plot: `nodata` when the dataset has no observation (`_N == 0`; for a framed graph its own frame's count, below), else `none` (no row passes the plot's and the graph's qualifiers) or `allmissing` (rows pass, none has every plotted variable present and, weighted, a weight above zero); the literal types (function, scatteri, pci, pcarrowi) take no per-plot case (REVIEW R3-3). Answers: lpoly, lpolyci → r(2000) `no observations` on nodata, none, allmissing; fpfit, fpfitci → r(198), the note line then `observation numbers out of range`, on nodata and none; mband, mspline without `bands()` → r(198) `bands must be between 1 and 200` on nodata and none; histogram → r(198) `observation numbers out of range` on nodata only; every type → r(198) `nothing to graph` on byempty; everything else draws. The fixture holds [S] §3's 400 probes and no other (DECISIONS P5-2: no empty-dataset probe set, no by()-on-an-empty-dataset probe set); it is the truth for the `none`, `allmissing` and `byempty` rows, and Q3701-1 proves the table equals it. The `nodata` answers are the ones the registration-time refusals PD-15 keeps already give on a dataset with no observation (histogram's `_N == 0` exit, the fpfit/mband/mspline count and the lpoly count, dash.ado:6890-6923 at f81cd31), and Q3701-3 and Q3701-6 compare them with twoway run live on the same emptied data, as Q3701-3 compares a by() graph on such data with `byempty`'s answer. "The dataset" is the data the graph is exported from: for a graph registered in another frame under Stata's own prefix, `frame <F>: dash ..., name()` (33-07; DECISIONS A-17: dash takes no `frame()` option), in a multi-frame build it is that graph's own frame (P4-4), so `nodata` there means `frame <F>: count` is 0, whatever the stack's `_N` (TR-37-01.3).
- **D-37-01.b The second line.** One-line form: `dash: plot <k> (<type>) has no observations.`; a named graph: `dash: plot <k> (<type>) of graph '<name>' has no observations.`; by(): with one plot `dash: plot 1 (<type>) of graph '<name>' leaves no by() panel.`, with several `dash: no by() panel of graph '<name>' holds an observation of plot 1 (<type>), plot 2 (<type>), ...` naming every plot of the graph in order, at most the first five, then `and <m> more` (DECISIONS A-12: a by() "nothing to graph" refusal's second line names the plots; REVIEW R3-19); " of graph '<name>'" is left out on the one-line form. The per-panel refusals of fpfit/fpfitci and mband/mspline under by() (dash.ado:9077-9087) name their plot with the one-line or named form. k is the plot's 1-based place in the graph's plots, the number dash's other plot messages use (dash_render.py:60912). Ruling M9 is in the index; RESEARCH C1's "plot-named line superseded" is overruled by it (reported).
- **D-37-01.c Where the export check stands.** After the last of `_dash_qual_gen`, `_dash_sort_gen`, `_dash_tsop_gen` and the weight-expression generator on each route (the plotted variable may be a `__dasht<k>` column and the weight a `__dashw<k>` column), before `_dash_write_data`, and in the frame `_dash_write_data` writes from on that path: the user's frame on the usual path; 35-08's temporary working frame (its `frame `_dash_xf' { ... }` block, when `_mv_plan` is `frame`, D-35-08.b) on either route; and 33-07's stack after `_dash_frames_stack`, under `frame `_dash_stk':` (TR-33-07.5), on a multi-frame build. The working columns exist only in that frame, and only there do the qualifier columns select the graph's rows. PD-15's anchor ("right after `_dash_qual_gen`") names the same gap between qualifier evaluation and Python; the working columns are dropped before it exits, as every error path there drops them.
- **D-37-01.d The empty contour.** No rows: the band renderer is built over the stub grid with levels `[0.0, 1.0]`; the key is a ColorBar titled with the z variable's label, no tick and no label, its strip invisible (`scale_alpha = 0`). twoway's key axis line is not drawn (the axis-style key is 42-03's, CV-3). Titles and keys of an emptied layer beside other layers stay as they are (DG-7, 47-02).

## Risk: [red] -- a refusal on every route, before Python, for every graph

**Why.** The check runs for every graph of every build; a wrong rule refuses a graph twoway draws, and the build route never re-counted before.

**Risk factors.** 1. The Mata walker reads machine-written JSON; a plot record it misreads would refuse wrongly. 2. The literal family (function, scatteri, pci, pcarrowi) reads no observation and must never be refused per plot. 3. by(, total) graphs have a data-order column `qual_col_total`. 4. The registration-time messages gain a line: pins comparing whole message blocks move. 5. `_dash_process_segment` is a hot block (R12): 37-04 edits its fit block (:7214-7240) in this batch. 6. 33-07's multi-frame build and 35-08's working frame export from a frame other than the user's, and the stack's `_N` counts every frame's rows. 7. `$dash__zo` is a global: a value left by a direct `_dash_process_segment` call (test_parser.cscript:111-325 calls it so) would name a plot in a later, unrelated refusal.

**Mitigation.** 1. The walker splits records by brace depth outside strings, returns the byte offset of the `]` that closes the plots array, and the graph's own keys are read only from the text after it (REVIEW R3-1); `_dash_json_get_str` per record, as every other spec reader does; Q3701-1 runs it over every probe's spec and Q3701-5 over a two-plot graph with its own qualifier and by(). 2. The rule returns "draw" for them in every case but byempty. 3. byempty counts rows where either the panel-base column or its total twin is 1. 4. Task 01 runs P1A-80/83/84 and test_option_validation.cscript and records which nodes read the second line. 5. The sites this section edits, all of them (REVIEW R3-35): `_dash_process_segment`'s per-type check block (:6826-6930, the R12 block); `_dash_plot`'s segment call (:8593) and its by() block (the literal gate :8968-8972 and the three refusal exits :9073-9096); `_dash_render_immediate` and `_dash_prepare_spec` (the export call, between the working-column generators and `_dash_write_data`); `_dash_require_mata`'s `_needed` list; the new `_dash_zero_obs_check` and `_dash_zo_line` (dash.ado) and `_dash_zero_obs_rule` and `_dash_zo_records` (dash_parse.mata); `GlyphMapper.map_contour` and the new `_contour_key_empty`. 37-04 edits `_dash_process_segment`'s fit gate (:7210-7245), `_dash_fit_points` and the renderer's by() panel loop, never these lines. 6. The check runs under the frame prefix `_dash_write_data` runs under on each path (D-37-01.c) and reads a framed graph's no-data case from its own frame (TR-37-01.3); Q3701-6 pins both frame paths beside `frame <F>: twoway`. 7. `_dash_plot` drops `dash__zo` directly before each `_dash_process_segment` call (TR-37-01.4), so only the refusal of the segment just run can set it.

- **TR-37-01.2 Rule table** (dash_parse.mata, a new block "Zero observations (WP-37 DG-1)"):
  ```mata
  // _dash_zero_obs_rule(t, c) -- twoway's answer when plot type t has no
  // observation in case c ("nodata", "none", "allmissing", "byempty"):
  // (rc, note line, error line); rc "0" draws.  Measured
  // (test/fixtures/zero_obs_truth.json, scripts/extract_zero_obs_truth.do);
  // "nodata" is the registration-time refusals' answer on no data,
  // compared with twoway live by test_wp37_truth.cscript Q3701-3.
  // mband and mspline refuse only without bands(): the caller asks.
  string rowvector _dash_zero_obs_rule(string scalar t, string scalar c)
  {
      if (c == "byempty") return(("198", "", "nothing to graph"))
      if (anyof(("lpoly", "lpolyci"), t))
          return(("2000", "", "no observations"))
      if (c == "allmissing") return(("0", "", ""))
      if (anyof(("fpfit", "fpfitci"), t))
          return(("198", "(note:  fracpoly could not fit model)",
                  "observation numbers out of range"))
      if (anyof(("mband", "mspline"), t))
          return(("198", "", "bands must be between 1 and 200"))
      if (t == "histogram" & c == "nodata")
          return(("198", "", "observation numbers out of range"))
      return(("0", "", ""))
  }

  // _dash_zo_records(json, pend) -- the records of json's first "plots"
  // array, each its own JSON text, in order: split at depth 1 outside
  // strings.  pend is set to the byte offset of the ] that closes the
  // array (0 when json has none): the graph's own keys -- its qual_col,
  // qual_col_total, if_expr, in_expr and graph_options -- come after it
  // (dash.ado:9357 writes {"plots":[...],"graph_options":...,"if_expr":
  // ...,"in_expr":...}, and _dash_qual_rewrite puts qual_col after
  // in_expr, dash_parse.mata:4684-4686), while every plot record holds
  // keys of the same names.
  string colvector _dash_zo_records(string scalar json, real scalar pend)
  ```
  `_dash_zo_records`: find `"plots":[` (byte scan, `strpos`); from the byte after `[`, walk bytes with `inq` (inside a string: toggled by an unescaped `"`, a `\` skipping the next byte) and `d` (depth: `{`/`[` +1, `}`/`]` -1 outside strings); a record starts at a `{` taking `d` from 0 to 1 and ends at the `}` taking it back to 0; stop at the `]` taking `d` below 0, and set `pend` to its offset (Mata passes arguments by address, so the caller's `pend` holds it). The parameter is named `pend`, never `end`: `end` is a Mata reserved word (help m2_reswords) and a function declaring it does not compile. Both in the header index (one new `*!` entry each at the end of the group) and `_needed`, on one new continuation line `        _dash_zero_obs_rule _dash_zo_records ///` directly before the list's last line (dash.ado:506 at 090d928), touching no existing line.
