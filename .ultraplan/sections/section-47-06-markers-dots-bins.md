# Section 47-06: Marker shapes, empty bins, dot rows, zero weights, dot floor, documented differences

> Part of: WP-47 (Plot-option fidelity, P15) · Items: PIC-2, PIC-9, PIC-10, DG-12, PIC-16, basic:PT-15 · Risk: yellow · Batch: 47.2 · Depends on: 47-03 · Blocks: 47-04 · Tasks: 8, 6 commits · Case-id prefix: Q4706

## Overview

**What is wrong today** (audit package 15; appendix "visual-corpus-schemes" PIC-2/5/6/9/10/16/17, "styles-schemes" ST-9/ST-19, "data-values-edges" DG-12, "type-options-basic" PT-15, "docs-claims" DT-23/DT-24, "silent-divergence" SD-23):

- **PIC-2 (with PIC-5, PIC-6, ST-19, ST-9).** "Marker shapes: diamonds 2/3 as wide; V/v closed triangles (help says open chevron); + filled fat cross; arrow symbols without shaft; msymbol(invisible) draws nothing (twoway notes and draws the default)." Bokeh's `diamond` is "moveTo(0,r) lineTo(r/1.5,0)", so D is 2/3 as wide as twoway's square-on-its-point (symbol_pattern_truth `sym.D` bbox_w == bbox_h); `V`/`v`/`smv` map to `inverted_triangle`, a closed path, where twoway's is "one path, 3 vertices, closed false"; `+`/`plus`/`smplus` map to Bokeh's filled 12-vertex `plus` where twoway strokes two lines; `arrow`/`a`/`arrowf`/`A` are a triangle with no shaft; `invisible` sits in `_INVISIBLE_SYMBOLS` though Stata has no such symbol ("named style invisible not found in class symbol, default attributes used", the SVG equals the default scatter). The help claim dash.sthlp:6069 "V and v an open chevron" is false (Appendix B HR-15).
- **PIC-9.** "Empty histogram bins draw an outline segment along the base": dash emits a Quad for every bin, top == bottom ones included (#60: 8 of 26), stroked along y = 0; twoway draws nothing for a zero-count bin.
- **PIC-10.** "dot draws no row for an observation whose y is missing (dotextend yes); twoway draws the full row": `yxview_dot_draw.ado` `draw_full_dots` loops over every observation using x only; sp500 in 1/45 gives "45 rows x 75 = 3375 dots" where dash draws 3300. Cause: `ok = np.isfinite(vals)` in `_dot_positions` and `keep = np.isfinite(vals) & np.isfinite(pos)` in `_dot_fill`, and the JS twin's `kept` filter.
- **DG-12.** "Markers with missing or zero weight are invisible; twoway still draws a dot": twoway's "size zero" marker is "a filled circle of r=5.20 plus a stroked circle of r=0.34 and stroke-width 9.72". dash.sthlp:4192-4194 says it is "drawn at size zero ... as in twoway" (HR-19).
- **PIC-16 (with PIC-17).** "Dot-plot dots floored to 1 px before the outline (0.46 vs 0.30 rs); dot patterns rounded to whole pixels": `_dot_style` floors the fill to 1 px and adds the 0.768 px outline (1.77 px) where twoway's dot is 0.30 rs (about 1.15 px). Bokeh's `line_dash` takes integers only, so the pattern rounding cannot be closed ([B] §4.8).
- **basic:PT-15 (with DT-23, DT-24, sil:SD-23).** "Other documented drawing and text differences ... Fix: case by case." The case list and each one's fate is D-47-06.f.

**After this section.** Diamonds, V/v/smv, +/plus/smplus and the arrow symbols are drawn in twoway's shapes through Bokeh `Scatter.defs` custom markers (CustomJS function bodies that paint directly: canvas, SVG export and legend keys, under the pages' existing CSP) or the shipped `cross`; `invisible` is noted and drawn as the scheme symbol; zero-count bins draw nothing in both modes and after a move; dot rows are drawn for every observation with a non-missing x under dotextend(yes); zero and missing weights draw twoway's minimal dot; the dot floor applies to fill plus outline; the basic:PT-15 cases this section owns are drawn as twoway draws them and the rest are confirmed closed by their sections.

**Why together.** One batch's JS slot (R12) covers the two saved-page twins (dot rows in `_DASH_AXIS_FINISH_JS`, weighted sizes in `_FILTER_JS`); the marker table, the dot style and the histogram quads are the remaining glyph-level fidelity items of the package.

### Section decisions

- **D-47-06.a — Custom marker defs: CustomJS function bodies; the CSP is unchanged.** New module dict `_DASH_MARKER_DEFS: {"@dash_diamond": <body>, "@dash_chevron": <body>, "@dash_arrow": <body>, "@dash_arrowf": <body>}`, each value the *body of a JavaScript function*, given to `CustomJS(code=<body>, module=False)`. BokehJS compiles that form with `new Function(...names, "cb_obj", "cb_data", "cb_context", code)` (`CustomJS._compile_function`: bokeh.js 3.9.0 about :48453, 3.8.0 about :48331), which the saved page's and the served page's `script-src 'unsafe-eval'` already allow, and `Scatter`'s `_paint` runs it through `execute_sync(fn, this.model, {ctx, i, r, visuals})` (3.9.0 about :54088, 3.8.0 about :53955), so `cb_data` is `{ctx, i, r, visuals}`. Every body has this shape: `const {ctx, i, r, visuals} = cb_data;`, then `ctx.moveTo(...)`/`ctx.lineTo(...)` (and `ctx.closePath();` for a closed shape), then `visuals.fill.apply(ctx, i);` for a filled shape only, then `visuals.line.apply(ctx, i);`; it returns nothing -- never a `Path2D`, which Bokeh's SVG context does not implement ([B] §4.0). **Never the ES-module form** (`export default (args, obj, {ctx, i, r, visuals}) => ...`): BokehJS compiles a module with `import()` of a `blob:` URL (`CustomJS._compile_module`, 3.9.0 about :48435), and neither `_DASH_CSP_STANDALONE` (dash_render.py:5706-5716) nor `_DASH_CSP_SERVED_META` (:5746-5756) lets script-src load `blob:`, so not one custom marker would compile or draw. `module=False` is always passed (BokehJS's default `"auto"` reads any line starting `export default` as a module). Geometry: diamond `(0,-r) (r,0) (0,r) (-r,0)` closed; chevron `(-r*w, -h) (0, h) (r*w, -h)` open (V points down; w and h from `sym.V`'s measured vertices); arrow head plus shaft from `sym.arrow`/`sym.A` vertices. `_MARKER_MAP` maps D, d, Dh, dh, diamond, smdiamond, diamond_hollow, smdiamond_hollow -> `"@dash_diamond"`; v, V, smv -> `"@dash_chevron"`; arrow, a -> `"@dash_arrow"`; arrowf, A -> `"@dash_arrowf"`; +, plus, smplus -> `"cross"` (shipped, two lines, no fill). **Where the defs are attached (one place, no mapper call edited).** New module helper `_dash_marker_defs(marker)` returns `{marker: CustomJS(code=_DASH_MARKER_DEFS[marker], module=False)}` for a `@dash_` string, one such entry per `@dash_` name for a field marker whose column holds them, else `{}` (a fresh CustomJS per call: a model belongs to one document). The last statement of `GlyphMapper._apply_marker_opts` (after 47-03's `_align_marker_size` call) is `renderer.glyph.defs = _dash_marker_defs(renderer.glyph.marker)`; every Stata-symbol marker renderer passes through that method (map_scatter, the dot rows, dropline, rcapsym, scatteri, pcscatter, pccapsym, rscatter -- `grep -n "_apply_marker_opts(" dash_render.py`). `GlyphMapper._sync_brushed_copies` (:16097) stops skipping `defs` (`skip = set(Model.properties()) | {"decorations", "defs"}` loses `"defs"`), so the nonselection and muted copies, which already copy the glyph's `marker`, share its defs: without them a brushed-away custom marker draws nothing. No `fig.scatter(...)` call in any mapper changes (47-02 edits those mappers in this batch; Dependencies). The size factors in `_SMALL_SYMBOL_FACTOR` are re-derived so each draws twoway's measured height AND width (diamond: `r` = half of twoway's height; the factor table is rewritten from `sym.*` bbox rows, and `test_every_symbol_is_twoways_height` gains a width check).
- **D-47-06.b — invisible.** Removed from `_INVISIBLE_SYMBOLS` and `_MARKER_MAP`; it then takes the unknown-symbol path that already notes in twoway's words and draws the scheme symbol (the BUGS E1 rule for star/asterisk/hexagon).
