## Overview

**What is wrong today.** The audit's package 3 (audit :119-161; appendix :1715-1720, :1894-1899, :2143-2184, :2227-2232, :2596-2601) finds that a do-file which names, exports, combines or reuses its graphs does not work unchanged under dash, and that the help says so only in pieces. syn:SD-17/ECO-3: `name()` registers instead of drawing, and `saving()` beside `name()` writes nothing ("ignoring unsupported option(s): saving()"), so a do-file that names every graph produces no output. GW-12/ECO-2/plat:PT-13/TR-16: a dashboard is not a Stata graph: `graph export`, `graph save`, `graph display`, `graph combine`, `putdocx`, `putpdf`, `putexcel`, `dyndoc` and markdown cannot use it; after dash, `graph export` writes an earlier Stata graph or fails r(601) ("no Graph window open"). ECO-1: a registered graph draws the data in memory at `dash build`, not the data it was registered on -- `preserve` / `collapse` / `name()` / `restore` draws the restored 74 rows with no note; a tempvar graph fails at build with "variable __000000 not found", r(111); `frame f2: dash scatter ..., name(gf)` then a build from the default frame fails r(111) (at 090d928; WP-33's 33-07 has since made that graph draw frame f2 -- Stata's own `frame` prefix, which twoway takes, not a `frame()` option, A-17). ECO-4: `graph combine` has no counterpart; `dash build` refuses `xcommon`, `ycommon`, `cols()`, `holes()`, `colfirst`, `iscale()`, `imargin()`, `note()`, `caption()` and `xsize()` ("option X not allowed", r(198)), and the help never maps combine to `layout()`. ECO-15: each one-line command opens its own browser page; only the newest five previews are kept; `saving()` opens none. ECO-7: dash leaves `s(_recast_type)`, `s(g_saving)` and `s(g_name)` behind where twoway clears `s()`.

## User stories

- US-38-01.1 As a Stata user with a do-file of named graphs and `graph export` lines, I want the help to say in one place what dash does instead of each step, so that I can convert the do-file.

## Business requirements

- BR-38-01.1 (syn:SD-17) The help says beside the drop-in claim and in the topic section that `name()` registers without drawing and that `saving()` beside `name()` writes nothing; `dash build` writes named graphs.
- BR-38-01.2 (GW-12) The topic section lists `graph export`, `graph save`, `graph use`, `graph display`, `graph combine`, `graph dir`, `putdocx`, `putpdf`, `putexcel`, `dyndoc` and markdown as unable to use a dashboard, and says `graph export` after dash writes the last graph Stata drew, or fails r(601) when none was drawn (a `nodraw` graph in memory is not enough), and that `r(filename)` and the toolbar's PNG/SVG are dash's routes.
- BR-38-01.3 (ECO-1) The topic section says a registered graph keeps no data, only its command and the frame it was registered in: `dash build` draws it from that frame's data as they are when the build runs (a collapse undone by `restore` before the build is not drawn, with no note), a tempvar is gone by then (r(111)), a graph registered under Stata's `frame` prefix (`frame f: dash ..., name()`) is drawn from frame f, and KPI cards read the frame current at `dash build`; the advice says what matters is that the data are in memory, or in the graph's frame, when `dash build` runs; the section names no `frame()` option, which dash does not take.
- BR-38-01.4 (ECO-4) The topic section maps `graph combine` to `dash build, layout()` / `tabs()` and lists combine's options `dash build` does not take.
- BR-38-01.5 (ECO-15) The topic section says each one-line command without `saving()` writes and opens its own preview page, the newest five previews are kept, and `saving()` opens none.
- BR-38-01.6 (ECO-7) The topic section says dash leaves `s()` as its parsers set it, where twoway leaves it empty.
