## Overview

**What is wrong today.** Five defects of the legend's box and of text boxes' margins (audit :364-381, :388-390, :403-405; appendix LT-2, LT-3, LT-6, LT-7, LT-10):
- **LT-2**: "legend(nobox) removes the region box; in twoway nobox is the key-text textbox option and changes nothing" -- under s2color twoway's `legend(nobox)` SVG equals the default (legend_geometry_truth.json `nobox` == `default_geometry`); `_dash_legend_box` clears border and fill (dash_render.py:39305-39307), the help says "nobox removes it" (dash.sthlp:4472) and test_legend_geometry.py:386-389 pins it.
- **LT-3**: "Key-text textbox options are not drawn: box (silent), bcolor(), fcolor(), justification(), alignment(), margin(), linegap(), tstyle()" -- twoway frames each key's text for `box`, fills the frames for `bcolor()`/`fcolor()`, right-aligns for `justification(right)`, raises the texts 17 units for `alignment(top)`, widens the legend for `margin(large)`, spreads lines for `linegap(5)` and enlarges the text for `tstyle(heading)`; dash takes `box` silently and names the rest.
- **LT-6**: "Legend layout sub-options named: style(), width(), height(), xoffset(), yoffset(), showindex, region(style()/lstyle()/lalign())" -- each changes twoway's SVG (probes L_sty .. L_rla); `_DASH_LEGEND_REGION_NAMES` (:39145-39147) has only fcolor, lcolor, lwidth, lpattern, color, margin.
- **LT-7**: "bexpand on legend() and on title/subtitle/note/caption is taken silently where twoway widens the box" -- `title("T", box bexpand)` spans the box over 522..5286 against 2833..2976, and `legend(bexpand)` shrinks the plot from 3641 to 2438; dash's models are unchanged.
- **LT-10**: "Numeric marginstyle forms (# # # #, l=#, l+#) are refused for textbox margins; legend region margin collapses four sides to the largest" -- `SchemeParser.margin_sides` (:10274-10292) knows names only, so `title("T", box margin(l=20))` is noted `is not a recognised margin`; `_dash_legend_margin_px` (:39150-39174) returns `max(vals)`, so `region(margin(1 20 1 1))` pads all four sides by 77 px; `bmargin()` likewise keeps only the largest side (`legend.margin`, :39244-39249; a Title's `standoff = max(bottom, top)`, :54256-54259).

**After this section** `nobox`/`box` act on the key texts, as twoway's; every key-text textbox option is drawn (natively on the Legend, the frames as overlays of 43-01's dispatcher); `style()`, `width()`, `height()`, `xoffset()`, `yoffset()`, `showindex` and `region(style() lstyle() lalign())` are drawn; `bexpand` widens the legend and the four title boxes as twoway does; every marginstyle form is read for title-family boxes, text() and the legend, with four sides kept -- `region(margin())` as a 4-tuple padding and `bmargin()` reserving exactly each side (R4-6e) -- under `scale()` too (R4-4) and in by()'s legend (R4-8). 43-06's text() box hook is folded into the dispatcher as kind `text_box` (R4-7).

**Why together.** All five are the legend box and text-box margins this section owns (`_dash_legend_box`, `_DASH_LEGEND_SUBOPTS`, `_dash_legend_margin_px`), in the order the manifest gives.

**Test order and commit rule (BRIEF).** 43-03-01 writes LT-2's red tests (and the fixture) without committing; 43-03-02 fixes and commits LT-2; 43-03-03 is the frame-route checkpoint; 43-03-04..07 each write their item's red tests, save the failure, fix and commit `(WP-43 <id>)`.

### Section decisions (binding on the executor)

- **D-43-03.a nobox and box (LT-2, LT-3).** `nobox` and `box` leave the region box alone; `box` (with no `nobox` after it in the same copy, legend_options.sthlp:77) frames each key's text, `nobox` none (the default). The region box is drawn only by the scheme and `region()`.
- **D-43-03.b Key-text options on the Legend (LT-3).** `justification(left|center|right)` -> `label_text_align`; `alignment(top|middle|bottom|baseline)` -> `label_text_baseline` (`top`, `middle`, `bottom`, `alphabetic`); `linegap(#)` -> `label_text_line_height = 1.0 + gap_pt / size_pt` (the title rule); `tstyle(name)` -> `label_text_font_size`/`label_text_color` from `scheme.textbox_style(name)` before `size()`/`color()`; `margin(m)` -> sides `[l, r, b, t]` px from `_dash_margin_sides` (D-43-03.e): `label_standoff += l`, the frame overlay's `grow` = the sides, and the reservation `label_width = max text width + l + r`, `label_height = max line block + t + b`, set by the dispatcher (D-43-03.c) because only the browser knows text widths. `bcolor()` fills and lines the frames, `fcolor()`/`bfcolor()` fills, `lcolor()`/`lwidth()`/`lpattern()` line them, as on title(); without `box` they draw nothing (twoway).
- **D-43-03.c Frames are dispatcher overlays.** Each framed key text is a `BoxAnnotation` (screen units, `level="annotation"`) registered with 43-01's `_dash_overlay` as role `legend_key_box`, target the Legend, part `label` with `spec["item"]` = its LegendItem (the handler finds the item's label element by `target.items.indexOf(item)` in the Legend's DOM, so a by() cell copy, remapped by 43-01's `_dash_overlay_move`, still finds it), grown by the margin sides (`px.grow`), with `watch=[[item, "label"]]` so a stale suffix written into the item's label re-places its frame on the DOM-text route too (R4-9). In a 43-02 hole composite (`legend._dash_hole_at` set) the spacer holds renderer-less stand-ins and the original items sit in the run Legends, so each frame's target is the run Legend that holds its item (the models of the legend's `legend_runs` dispatcher item; `_dash_legend_hole_runs` now returns that list of runs, the one line `return runs` this section adds), and the key-text props of D-43-03.b are set on every run Legend as well as on the spacer (`_dash_legend_key_text` applies them to each run after it applies them to the legend; the stand-ins keep `label_text_alpha = 0`), because `_dash_legend_hole_runs` copied the spacer's props before `_dash_legend_box` runs. The dispatcher runs kind `overlay` before `legend_runs` (D-43-01.c), so a frame on a run Legend first reads the run as the previous run left it (hidden, so the frame is hidden by step 3); this section therefore makes a dispatcher run that wrote anything schedule one more run on the next animation frame, bounded by D-43-01.c's cap of 6 consecutive writing runs per canvas size, so such a frame is placed one frame after its run (43-04's frames on key-cell Labels follow the same way); the budget test's bound of 3 runs per resize holds (place, follow, one run that writes nothing). One more `overlay` item per legend, with no models and the Legend as target, part `labels`, `spec["reserve"] = true` and `px.margin = [l, r, t, b]`, sets the Legend's `label_width`/`label_height` from the widest and tallest label element, compared before setting so it never loops. This section adds the parts `label`, `labels` and `frame` (the figure's frame box, for bexpand) and the `move` field (D-43-03.d) to the `overlay` handler of `_DASH_OVERLAY_JS`; no new layout CustomJS. If 43-01-05 found the legend is not DOM-rendered, checkpoint 43-03-03 escalates (the frames would then need 43-04's key cell).

## Risk: [yellow] -- the legend box of every graph that sets a box or text option; overlay geometry

**Why.** The region box and padding code runs for every legend; frames depend on the legend view's DOM geometry; bmargin's reservation touches the panels of every boxed title.

**Risk factors.** 1. test_legend_geometry.py::TestBoxAndText pins (`test_nobox`, `test_bmargin_and_region_margin`). 2. Padding as a tuple under bokeh 3.8. 3. Overlay frames must follow moves that change key texts (stale-cue suffixes) -- they are re-placed by the dispatcher on the label change. 4. `_dash_margin_sides` returns relative units: conversion at the figure's reference (`OptionTranslator.size_ref_of`). 5. The far-side carry of a title's bmargin must not double-count a span item's own offset.

**Mitigation.** 1. Flip with reason. 2. Measured in 43-03-07 under both versions. 3. A MOVE_CORPUS case and a Chrome stale-suffix check on a framed legend. 4. One conversion helper used by all three callers. 5. The bmargin Chrome test includes a spanned title.
