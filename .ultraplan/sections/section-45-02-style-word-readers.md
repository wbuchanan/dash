# Section 45-02: Style-word readers per class

> Part of: WP-45 (Schemes, styles and figure geometry, audit package 10) · Items: ST-1 (ST-2, ST-3, ST-4, ST-5, ST-6, ST-11) · Risk: yellow · Batch: 45.1 · Depends on: none · Blocks: 45-03 · Tasks: 3, 1 commit · Case-id prefix: Q4502

## Overview

**What is wrong today.** twoway reads each style word through its class's `_unabbrev` program; dash reads fixed tables and digit regexes, so spellings twoway takes are noted (in twoway's own words, though twoway prints nothing) and drawn wrong. The audit (anchors at `090d928`; WP-43 and WP-44 changed some of these sites, see Dependencies):

- **ST-1 compass2dir** (compass2dir.class `_unabbrev`: `syntax [, North South East West NWest NEast SWest SEast Center Top Bottom Left Right *]`, plus the capital forms N S E W NE NW SE SW T B R L): `text(..., placement(nor|N|NE|rig|cen|...))` and `aspectratio(1, placement(rig|R|E|top|nor|N|bot))` draw as the canonical name in twoway; dash's `_dash_at_place` (dash_parse.mata:11555-11573) matches a fixed table exactly, prints "named style nor not found in class compass2dir, default attributes used" and draws east (text) or centred (aspectratio, dash.ado:1172-1190).
- **ST-2 tb_orientstyle** (`syntax [, HORizontal VERTical RHORizontal RVERTical *]`): `orientation(hor|hori|horizo)` is horizontal, `(verti|vertic)` vertical, `(rhor|rhori)` rhorizontal, `(rverti)` rvertical; dash's `_dash_at_orient` (:11579-11592) takes only horizontal/horiz, vertical/vert, rvertical/rvert, rhorizontal/rhoriz, so `orientation(vertic)` is noted and drawn horizontal.
- **ST-3 clockdir names** (`syntax [, Center Top Bottom Left Right *]` -> 0 12 6 9 3): `title("TT", position(bottom|bot|b))` equals position(6), and likewise for legend() and mlabposition(); dash reads digits only -- `_dash_textbox_position` (dash_render.py:54056-54058), edge titles (:54601-54604), the legend's `m_pos` (:39597), `_MLABEL_CLOCK_NAMES` (:14505, used :17647-17655) -- so `title(..., position(bottom))` is drawn above, `legend(position(top))` gets the invented note (dash_parse.mata:10426-10430), `mlabposition(left)` is drawn at 12.
- **ST-4 gridringstyle** (`syntax [, Inside Outside *]` -> 0/1): `legend(ring(inside|in|i))` equals ring(0); dash's legend reads `\d+` (:39598) and prints both gridringstyle notes (dash_parse.mata:10431-10435). `title("TT", ring(in|i|ins|out|o))` is refused by twoway ("option ring() incorrectly specified", r(198); `ring(inside)`/`ring(outside)` taken) -- that title half is already done when WP-45 starts: WP-43's 43-05 (LT-14) refuses a non-numeric title ring after twoway's two notes (`_dash_ring_ok`, D-43-05.c) and reads rings as real numbers 0-100 (`_dash_ring_value`, LT-9, D-43-05.b).
- **ST-5 anglestyle** (`syntax [, Horizontal Vertical RHorizontal RVertical *]`): `mlabangle(v|ve|vert)` = 90, `(rv|rver)` = 270, `(rh|rhor)` = 180, `(h|hor)` = 0, and msangle() alike; dash's `_dash_anglestyle_degrees` (dash_render.py:7538-7573) reads full names and numbers only (the h/v/rh/rv rule exists only in `_parse_axis_angle`, :7576-7607); the sites msangle :15926, mlabangle :17591, mangle :25268.
- **ST-6 connectstyle** (`syntax [, Connected Direct Line Stairstep Upstairstep STEPstair Ascending None I *]`, `L` ascending, `J` stairstep): `connect(di|co|li|as)` direct, `(st|sta|stai)` stairstep, `(up|ups)` stepstair, `(no|non)` none; `_dash_connect_canon` (dash_parse.mata:6844-6869) needs 3+ letters for direct, 5+ for stairstep, 4+ for stepstair, so dash.ado:3417-3421 notes them and draws a direct line.
- **ST-11**: the invented twoway-worded notes above, and the missing one: `title("T", justification(l))` -- twoway notes "named style l not found in class horizontal" (same picture); dash is silent (dash_render.py:54184 ignores non-full words).

**After this section.** One reader per class, in Mata and in Python, follows its class's `_unabbrev` rule; every spelling twoway takes draws its canonical style with no note; a word twoway does not know keeps twoway's note (its real words); `legend(ring(in))` is drawn inside the plot region as twoway draws it; the earlier readers of WP-43 and WP-44 (43-02's compass reader, 44-01's and 43-05's orientation readers) read through the same tables; justification() gets twoway's note. Title rings keep 43-05's grammar and refusal unchanged.

**Why one section.** One item (ST-1 with its siblings), one shared reader design.

**Test order and commit rule.** 45-02-01 writes the extract script and every regression test and saves the failure text (no commit); 45-02-02 changes the Mata/ado readers; 45-02-03 changes the Python readers, runs everything, closes ST-1 and commits `(WP-45 ST-1)`.

### Section decisions

- **D-45-02.a One table per class, two twins.** Mata `string scalar _dash_style_word(string scalar cls, string scalar w)` and Python `_dash_style_word(cls, w)` (module level) return the canonical name for classes `compass2dir`, `tb_orientstyle`, `clockdir`, `gridringstyle`, `anglestyle`, `connectstyle`, or "" for a word the class does not take. The rule: the word is matched against each `syntax` option name in the class's order -- the capital letters are the minimum, the typed word must be lower case and a prefix of the lower-cased name at least as long as the minimum (Stata's `syntax` option abbreviation) -- then the class's special cases (compass2dir's capital exact forms N S E W NE NW SE SW T B R L and its clock numbers 0-12, each only when no lower-case name matched and the word has at most 2 characters, exactly as 43-02's `_dash_compass_dir` ports them; connectstyle's `L` and `J`, `I`; anglestyle's `45`/`270`; clock numbers 0-12 and `default` where the class has them). The canonical results: compass2dir -> n ne e se s sw w nw c; tb_orientstyle -> horizontal vertical rhorizontal rvertical; clockdir -> 0-12; gridringstyle -> the ring number; anglestyle -> degrees; connectstyle -> direct ascending stairstep stepstair none.
- **D-45-02.b The fixture decides every spelling.** The extract script generates every prefix from the minimum to the full name for each option name of each class, plus the capital forms and three unknown words, and records whether twoway's picture equals the canonical one and whether a note is printed. The tables are pinned to it in both twins.
- **D-45-02.c Rings build on 43-05 (REVIEW R4-1).** Titles, subtitles, notes and captions keep 43-05's `_dash_ring_value` (real numbers 0-100, `inside`, `outside`) and `_dash_ring_ok` refusal unchanged: they already refuse `in`, `i`, `ins`, `o` and `out`, since only the full words pass, as twoway refuses them; this section adds no refusal and does not touch `_dash_textbox_position`'s ring reader. Only legend() reads gridringstyle abbreviations: `_dash_ring_value(text, legend=False)` gains the keyword; with `legend=True` the text is first mapped through `_dash_style_word("gridringstyle", text)` (so `in`, `i` and `ins` read 0, `o` and `out` read 1) and then read by 43-05's real-number grammar, so `legend(ring(7.5))` stays 7.5. The legend's step-4 read (`_dash_apply_legend`, :39598 at `090d928`, rerouted through `_dash_ring_value` by 43-05) passes `legend=True`; the Mata legend note block notes only a word that neither `_dash_style_word("gridringstyle", w)` nor `_dash_ring_ok(w)` reads.
- **D-45-02.d One table for each earlier reader (REVIEW R4-2).** 43-02's `_dash_compass_dir(t)` keeps its name, signature and full-name results but becomes `_DASH_COMPASS_FULL.get(_dash_style_word("compass2dir", t))` with `_DASH_COMPASS_FULL = {"n": "north", "ne": "neast", "e": "east", "se": "seast", "s": "south", "sw": "swest", "w": "west", "nw": "nwest", "c": "center"}`; its rules move into the compass2dir branch unchanged, so 43-02's and 43-05's callers (bplacement(), title placement() at ring(0)) see the same answers. 44-01's `_dash_tb_orient(w)` and 43-05's title orientation reader look up `_DASH_ADDED_TEXT_ORIENT.get(_dash_style_word("tb_orientstyle", w))` (a word the class does not take reads "", so the lookup gives None, which 44-01's `_dash_tb_orient` returns for an unknown word and which then gets twoway's note; never a KeyError) (dash_render.py:54394, already on the constants copy list :67054; the same radians 44-01 uses: vertical pi/2, rvertical -pi/2, rhorizontal pi), so `orientation(vertic)` on `title()` and `ytitle()` is read.
- **D-45-02.e Notes.** The note "named style <w> not found in class <cls>, default attributes used" is printed only when the class reader returns "" -- i.e. where twoway prints it (fixture). `justification()` on a title-type textbox with a word that is not `left`, `center` or `right` prints twoway's "named style <w> not found in class horizontal, default attributes used" once (fixture `J_*`).
