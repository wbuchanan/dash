## Risk: [yellow] -- every note path, the generated silent table every command reads, and the library load at every dash.ado load

**Why.** Silencing hides notes users read today; a wrong row hides a real difference. The load change runs on every `dash` command.

**Risk factors.**
1. A silent row derived from too few values could hide a value that twoway draws differently.
2. Many pins assert notes (test_twoway_option_parity.cscript's TP rows, test_option_surface.cscript, test_help_claims_*, test_unsupported_report_is_true.py, test_noted_drawn.py, test_unknown_options.py).
3. Changing `_dash_style_note`'s prefix touches every colour/size note pin.
4. `mata which` must not print when the function exists (`quietly`), and must not be confused by a user's own function of that name.
5. Batch partner 49-01 edits refusal first lines, `_dash_taxis_unit`, `_dash_validate_value`'s `var` kind (:4325) and `_dash_process_segment` lines :5868, :6030, :6276; this section edits no refusal line of `_dash_validate_value` (45-04's graphsize kind is not edited, its Q4504-2 pins it; xsize(abc)'s note is `_stat_option_float`'s, or one note line of the kind, D-49-02.e) and edits `_dash_process_segment`'s :6982 -- different hunks, outside the R12 per-type block (REVIEW-5 R5-8, R5-37).

**Mitigation.**
1. Each option is measured at two non-default values where the option takes a value (the extract records both); a row is silent only when both are `same_picture`.
2. 49-02-01 records every pin that asserts a note this section removes or rewords; each is flipped with a `Flipped:` line naming the fixture key that shows twoway silent or worded.
3. One commit (LT-25) changes the prefix for class-worded notes only; notes in dash's own words (values dash draws differently) keep `dash:` (dash.sthlp's How a note is printed paragraph).
4. The check names a `_dash_` function (dash's prefix is reserved by test_session_hygiene.py); Q4902-7 runs with and without the library loaded.
5. Each hunk is named in both hand-backs as "lines a merger may conflict on"; merge order 49-01 then 49-02.
