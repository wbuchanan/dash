## Overview

**What is wrong today.** GAPS3 C1 (GAPS3.md:120) reads: "pcarrow/pcbarrow/pcarrowi: head `msize() mcolor() mfcolor() mlcolor() mlwidth()` are declared, written to the spec and **silently** not read; heads are fixed `OpenHead(size=10)`; pcbarrow's `NormalHead` has no `fill_color` so its heads fill black; `mangle()`, `barbsize()`, `headlabel` undeclared (generic note); a row missing only its second point is dropped whole. test_phase4_plots.py P4-18/P4-20 pin the black heads." Evidence dash_render.py:19683-19861 (`map_pcarrow`, `map_pcbarrow`), :19660-19662 (`_add_arrow_heads`). B27 (GAPS3 §4.B) carries the arrow part of the same gap under the drop-in register.

**What twoway draws** (research/stata-ground-truth.md §6, from `B/y/yxview_pcarrow_draw.ado` and `B/_/_gr_arrowhead.ado`): the shaft in the series' arrow line style; the head by `_gr_arrowhead ang msz barbsz x0 y0 x1 y1` with `ang` = `marker.angle` (default `anglestyle stdarrow` 28.64 degrees), `msz` = `marker.size` (`symbolsize parrow medium`, dash-s2color.scheme:528), `bsz` = `marker.backsize` (`symbolsize parrowbarb zero`). With `bsz == 0` the head is two open strokes of length `msz` from the tip at angles `pi + phi +/- ang` (back along the shaft). With `bsz > 0` it is a filled polygon: tip, A = tip + msz*(cos(pi+phi+ang), sin(pi+phi+ang)), B = tip + bsz*cos(ang)*(cos(pi+phi), sin(pi+phi)), C = tip + msz*(cos(pi+phi-ang), sin(pi+phi-ang)), back to the tip (`arrowhead_barb`, `_gr_arrowhead.ado:46-73`, read 10oct2026). `barbsize() = msize()` puts B at the foot of the perpendicular from A: a right angle at A (`twoway_pcarrow.sthlp:158-162`). pcbarrow draws the same head at the start point too. Head colour is `markerstyle p#arrow`: fill `p#arrowfill` -> `color p#`, line `linestyle p#arrow` -> the shaft's colour and `linewidth p medium`. The head's line pattern cannot be changed (`sthlp:181-183`). Labels go at the tail unless `headlabel` (`yxview_pcarrow_draw.ado:48-60`). `_gr_arrowhead` exits when a transformed endpoint is missing (`:15-23`): no head for a one-point row; whether the shaft's `gdi line` draws anything, or the point a marker, is measured by this section's extractor.

**After this section** both renderers draw every head as twoway's `_gr_arrowhead` geometry (a custom rotated head: two open strokes or a filled polygon at the tip, D-02.a), size it from `msize()` (default the scheme's `symbolsize parrow`), stroke it in `mcolor()`/`mlcolor()` at `mlwidth()` (default the shaft's colour and the scheme's arrow line width), fill it (any `barbsize() > 0`) in `mfcolor()` defaulting to the series colour `color p#`, never black; `barbsize()` is declared and sets the barb depth (0, the default, = two open strokes; > 0 = a filled head whose back point sits `bsz*cos(ang)` behind the tip); `mangle()` is declared, read and drawn (D-02.b, DECISIONS D1); `headlabel` is declared and moves the labels to the second point on the three arrow types; a row whose second point is missing is drawn as twoway's extractor shows (D-02.d). P4-18 and P4-20 are flipped. The spec, the saved page and the served app share one mapper path.

### Section decisions (binding on the executor)

- **D-02.a A custom rotated head (DECISIONS D1): `patches` + `multi_line` glyphs over a per-layer head source whose vertices are computed in screen space by JS.** Bokeh's `ArrowHead` models (`OpenHead`/`NormalHead`, fixed half-angle atan(0.5) = 26.57 degrees, fixed depth) are NOT used for pcarrow/pcbarrow/pcarrowi; `_add_arrow_heads` and its `Arrow` stay only for the callers that still use them (test_saved_filter_layers.py:315-335 calls it directly; grep every caller before 02-03 and leave them). Each arrow layer gets ONE `ColumnDataSource` `head_source` with columns `xs`, `ys` (lists of lists, data units) and `row` (the pc_source row index), created empty in Python, and one glyph decided per layer by `barbsize()` (one value per layer): `bsz == 0` adds `fig.multi_line(xs="xs", ys="ys", source=head_source, line_color=<stroke>, line_width=<lw>, line_alpha=<shaft alpha>)` (one open polyline A-T-C per head: twoway's two strokes from the tip), `bsz > 0` adds `fig.patches(xs="xs", ys="ys", source=head_source, fill_color=<fill>, line_color=<stroke>, line_width=<lw>, line_alpha=<shaft alpha>)` (closed polygon T-A-B-C). **Vertex arithmetic** (`_gr_arrowhead.ado:46-73`, `arrowhead_barb`; screen space, pixels, `y` down -- the head is mirror-symmetric about the shaft so the axis direction does not matter): for row i with scales `xs = view.frame.x_scales.get(xr) ?? view.frame.x_scale` and `ys` likewise (`xr`/`yr` the shaft renderer's range names, so a `yaxis(2)` layer uses its own scale), `X1 = xs.compute(x1[i])`, `Y1 = ys.compute(y1[i])`, `X2 = xs.compute(x2[i])`, `Y2 = ys.compute(y2[i])` (the metric ratio of the two axes is inside the scales, so a shaft at 45 degrees in data units is drawn at its screen angle, as twoway computes `phi` after `_gr_arrowhead`'s transform); any non-finite value skips the row (no head: `_gr_arrowhead.ado:15-23`); `phi = Math.atan2(Y2 - Y1, X2 - X1)`; `T = (X2, Y2)`; `A = T + msz*(cos(phi+pi+ang), sin(phi+pi+ang))`; `C = T + msz*(cos(phi+pi-ang), sin(phi+pi-ang))`; `B = T + bsz*cos(ang)*(cos(phi+pi), sin(phi+pi))`; `msz` = the row's `__dash_head_px` (pixels), `ang` = `mangle()` in radians (default 28.64 degrees, `anglestyle stdarrow`), `bsz` = the layer's barb pixels; back to data by `xs.invert(X)`, `ys.invert(Y)`. pcbarrow repeats the construction at the start point with `T = (X1, Y1)` and `phi = atan2(Y1 - Y2, X1 - X2)`. `barbsize() = msize()` gives the right angle at A (`twoway_pcarrow.sthlp:158-162`), which U02-03 checks numerically. **Recomputation (both modes, one JS, `_DASH_ARROW_HEAD_JS`):** the CustomJS runs (1) from a `document_ready` hook through the existing `_dash_by_stack_hooks` channel (dash_render.py:44455-44464 saved, :46115-46123 and the served template line :50766), on first render, when `Bokeh.index.find_one(fig)` (already on `_DASH_BOKEH_INTERNALS`, :283, used by `_DASH_SVG_SAVE_JS` :35287) returns the figure view; ## User stories

- **US-02.1** As a twoway user, I want `dash pcarrow y1 x1 y2 x2, msize(large) mcolor(red)` to draw larger red heads, so the picture matches my Stata graph.
- **US-02.2** As a twoway user, I want pcbarrow's heads in the series colour, not black.
- **US-02.3** As a twoway user, I want `barbsize(medium)` to fill the heads and `headlabel` to put the labels at the head, as twoway does.
- **US-02.4** As a dashboard reader, I want heads that keep their size and colour after a filter move in both modes.

## Business requirements

- **BR-02.1** The head's stroke length equals the marker size a `scatter ..., msize(same)` draws on the same figure (pixels), the scheme's `symbolsize parrow` by default; its half-angle is `mangle()`; it is the same picture at every zoom, aspect ratio and after a filter move or resize, in both modes.
- **BR-02.2** The head's stroke colour is `mcolor()`/`mlcolor()` (mlcolor wins), else the shaft's colour; its fill (when filled) is `mfcolor()`, else `mcolor()`, else the series colour `color p#`; its line width is `mlwidth()`, else the scheme's arrow line width. Nothing is black by default.
- **BR-02.3** `barbsize(0)` or none draws two open strokes; `barbsize(#>0)` draws a closed, filled head whose back point is `#*cos(mangle)` behind the tip; a bad value is refused as a size is refused.
- **BR-02.4** `headlabel` puts the layer's labels at (x2, y2) on pcarrow, pcbarrow and pcarrowi; without it they stay at (x1, y1).
- **BR-02.5** `mangle(#)` draws the head at half-angle # (an anglestyle name or degrees), default 28.64; `barbsize(#)` sets the barb depth.
- **BR-02.6** A row whose second point is missing is drawn as twoway draws it (the fixture decides); a row whose first point is missing draws nothing.
- **BR-02.7** Saved page and served app draw identical heads before and after a move.
