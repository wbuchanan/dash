## Overview

**What is wrong today.** The corpus pieces (33-02 extractor, 33-03 twoway runner, 33-04 dash exporter, 33-05 verdict engine) and the two dash features a dash-built gallery needs (33-06's image panel, 33-07's frames) have no entry point and no output a reader sees. M5 and PD-13 ask for `make corpus` and `make gallery`; about 12 README pairs, twoway's SVG left and dash's right with the command and verdict beneath (Q54, Q55); and gallery pages built by dash itself -- one page per plot type plus a dash-built index page (maintainer decision P4-1, superseding Q58's single page), each example's twoway SVG in an image panel beside its live dash graph drawn from its own dataset (C4). Today `.gitignore` ignores `*.html` (line 7) and `.git/info/exclude` ignores `*.json` (:58) and `*.txt` (:52), so neither a page, nor `corpus.json`, nor a committed id list would reach a commit; and nothing scans published output for a path, a user name or a machine name (Q36: `test/test_no_secrets.py` "scans tracked files for key shapes and the e-mail only").

**After this section.** `make corpus` runs the five stages of 33-02..33-05 into a run folder outside the repository and prints a one-line summary (`scripts/corpus/summary.py`, which 33-14 also uses to record its baseline). `make gallery` turns a run folder into `docs/gallery/svg/<id>-twoway.svg` and `<id>-dash.svg`, `docs/gallery/corpus.json` (every example with both answers, refused ones included, P4-10), one page per plot type `docs/gallery/<plottype>.html` holding only the examples twoway draws (P4-10), and `docs/gallery/index.html` (whose panels link to the pages), each page one `dash build` in its own Stata session (a plot type with more rows or datasets than one build holds is built as consecutive parts, `<plottype>.html`, `<plottype>-2.html`, ..., D-33-08.f), every example drawn live except one whose dataset is missing from the offline cache (DECISIONS A-23), all built in a staging folder and moved into `docs/gallery/` only when every page has built; it measures each page's load time in headless Chrome, records it in corpus.json and prints it, splitting nothing on time or size (P5-3); captions and README lines name differences in Stata terms, with GAPS4 ids and check names kept to corpus.json (A-24); the README pairs are only fully vector dash SVGs (A-26); and it writes the README block between `<!-- dash-gallery:start -->` and `<!-- dash-gallery:end -->`, inserting the `## Gallery` heading and the markers the first time. By maintainer decision P4-8 **`make gallery` is not run in WP-33**: the first and only gallery is built at WP-50's closeout (WE.7), after 34-04/45-04 make sizes exact (PD-17), and committed after the maintainer's sign-off. This section writes and tests the tooling; its smoke build (task 04) runs `gallery.py` on a six-example run with scratch paths for the pages and a scratch copy of README.md, and writes nothing under `docs/` or into README.md. The ignore rules let the pages and corpus.json be committed at WE.7; two tests hold any committed gallery and README block to corpus.json (on today's tree they assert that neither exists, and they bind at WE.7); a privacy scan reads every gallery file, base64 payloads decoded, and the README block.

**Why one section.** Every piece is the corpus's publication layer and is tested together on one small run.

**Test order and commit rule.** Task 01 writes the unit, Makefile, ignore, committed-gallery and privacy tests red and saves `<scratch>/33-08-01-failure.txt`; task 02 measures whether one Stata session's frames are limited and writes gallery.py and the id list; task 03 writes summary.py, the Makefile targets and the ignore rules; task 04 runs the smoke build in scratch; task 05 runs the covering tests and commits once: `Add make corpus and make gallery, the gallery pages' builder and the gallery privacy scan (WP-33 33-08)`.
