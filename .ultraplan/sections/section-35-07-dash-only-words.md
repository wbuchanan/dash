> Part of: WP-35 (Accepted syntax and refusals) · Items: DT-15 (DT-16, syn:SD-18) · Risk: yellow · Batch: 35.4 · Depends on: 35-04, 35-05 · Blocks: -- · Tasks: 3, 1 commit · Case-id prefix: Q3507

## Overview

**What is wrong today.** Audit DT-15/DT-16/syn:SD-18: "Accepted where twoway refuses: kernel(GAUSSIAN), xsize(()), an empty-colorvar if, and about 35 dash-only words (ytitle2(), xlabel2(), mlg(), marker(), malpha(), jseed(), plotbgcolor(), hover(), table ...)". Research counted **42 words** on the graph and plot commands ([C] §6: 25 second-axis spellings, 13 other synonyms, 3 extensions, bw() noted off the bandwidth types) and **5 non-word forms**, and measured twoway's answer for each ([S] §5: every word r(198) `option <word>() not allowed`; the forms r(198), r(7), r(3001), r(100)). dash accepts all of them; the help documents them piecemeal (dash.sthlp:4948-4953 "twoway refuses all twenty", :3436, :4252-4254, :5806, :5818-5821 ...), with no single list.

**The ruling.** The maintainer ruled in Phase 4 (DECISIONS.md P4-7, 20oct2026): "Unless the options are specific to functionality that only dash provides, the syntax should mirror twoway syntax as close as possible." Applied to every row of the table below:
- **Refused with twoway's words:** the 25 second-axis forms (ytitle2() ... ttitle2()), malpha(), lalpha(), falpha(), marker(), jseed(), mlg(), cv(), colv(), colornlevels(), colormissing(), plotbgcolor(), pbgc(), colpalette() (twoway's colorlist()/colorrule() cover it), and bw() read as barwidth() (35-04, stat:PT-14).
- **Kept as dash-only options, listed in one help paragraph:** hover() and table -- they control what only a dashboard does (tooltips, the folded data table); the options of dash's own subcommands are dash's too.
- **Non-word forms refused as twoway refuses them:** kernel() is case-sensitive, xsize(()) is refused, a string colorvar() is r(7), and a colorvar() layer whose if keeps no observation is answered as twoway answers when it draws (42-05, CV-14); title("'90s") is refused as twoway refuses it under P4-5 (43-05, LT-24).
- **P4-9:** when dash refuses a synonym it used to accept, the first line is twoway's refusal and a second line names the twoway spelling (e.g. `use ytitle(..., axis(2))`); nothing else is printed.
- **Known differences of the kept words.** hover() and table stay different from twoway on purpose, so their rows in the known-differences tables are not deleted when DT-15 closes: each moves into its table's deliberate dict -- `ABBREV_DELIBERATE` (test/test_abbreviations.py), `DELIBERATE` (test/value_truth_known.py, 33-10's name for VALUE_KNOWN's dict) or the `<NAME>_DELIBERATE` beside a 33-11..33-13 table -- under the ruling id P4-7 (D-33-10.a, BRIEF "The corpus ledger and the known-differences tables").

Every row now has a ruling (the Ruling column), so this section asks nothing of the maintainer. DT-16 and syn:SD-18 are other ids of DT-15; one commit.

**Test order and commit rule.** 35-07-01 runs GitNexus impact, measures twoway (extract script), writes the rulings module from the Ruling column and the table-driven failing tests, saves the failure text and does not commit. 35-07-02 applies the rulings. 35-07-03 documents, closes DT-15 and commits `(WP-35 DT-15)`.

### Section decisions

- **D-35-07.a Refusal by the typed word, in twoway's order.** A REFUSE word is refused when the user TYPED it: one Mata function `_dash_dashonly_typed(string scalar text, real scalar inp)` (TR-35-07.2) scans the option text by value with `_dash_rep_toks(text, 0)` (the tokenizer `_dash_rep_prefix` uses, so both count option words alike), counting only tokens whose `_dash_rep_optname` is non-empty and that are not a `p<k>()` token (`^p[1-9][0-9]?\(`, the tokens 35-02's `_dash_p_take` takes out, so the count is the same on the text before and after `_dash_p_take`), for the first token whose name reaches a REFUSE word (from the word's dash minimum, the capitals of its declaration, to its full name), and returns its row number, its option-word index and the token as typed. The hit is computed on the text as typed: on each segment's text before `_dash_route_axis2` (dash.ado:6612-6613, `_opts_pre`), on the after-comma text before its `_dash_route_axis2` (:8451, `_gopts_axraw`), and on each `p<k>()` text 35-02 takes out (twoway hands a p# text to the plot's own parser, which refuses the word). No hit is refused there at once: twoway, and dash since WP-32, refuses the first word it does not take in list order (`_dash_refuse_unknown`, :11186), and refuses the options after the comma only after every plot group's refusal (`_dash_gopts_checks` deferred, :8453-8456, given at :8898). So a segment's hit is refused only when no word typed before it is refused first, and an after-comma hit after the segment loop (TR-35-07.3; probes `order.unknown_first`, `order.word_first`, `order.group_then_comma`). A hit inside a `p<k>()` text comes later than the plot groups' own words and earlier than the options after the comma, whatever the typed order: twoway parses every p# text after every plot group's own options, in plot order (measured 20oct2026 with this plan's probe: `scatter mpg weight, p1(malpha(50)) bogus` names `bogus`; `scatter mpg weight, p1(malpha(50)) ytitle2(T)` names `ytitle2()`; `(scatter mpg weight) (scatter price weight, bogus), p1(malpha(50))` names `bogus`; `(scatter mpg weight), bogus p1(malpha(50))` and `(scatter mpg weight), p1(malpha(50)) bogus ytitle2(T)` name the p1() text; `(scatter mpg weight) (scatter price weight), p2(jseed(3)) p1(malpha(50))` names the p1() text only). So a p# hit is recorded during the segment loop and refused after it, above 35-02's deferred `p21()` refusal and the after-comma hit (TR-35-07.3; probes `order.p_*`). Inside a p# text twoway takes `marker()`, its markerstyle option there (measured: `scatter mpg weight, p1(marker(O))` rc 0 with `(note:  named style O not found in class markerstyle, default attributes used)`), so the p# scan refuses only the words whose `p.<word>` probe twoway refuses (`_dash_dashonly_list()`'s fifth column, TR-35-07.2). Declarations, folds and internal keys stay: `_dash_route_axis2` itself writes ytitle2() etc. for `ytitle(..., axis(2))`, so the declarations cannot be removed for the second-axis rows.
- **D-35-07.b twoway's words, then P4-9's hint.** A refused word prints the fixture's first line (`option <typed>() not allowed`, or `option <typed> not allowed` for a flag) and then, as dash's second line (PD-11 keeps dash's later lines; REVIEW R2-26), `      use <twoway spelling>` from the Ruling column (P4-9); it exits with the fixture's rc (198). So `dash scatter mpg weight, ytitle2(T)` prints exactly `option ytitle2() not allowed` and then `      use ytitle(..., axis(2))`, r(198): twoway's line, then the hint line naming twoway's spelling, and no third line. The second line of `_dash_refuse_unknown` ("twoway does not take this option here." / the after-comma line, dash.ado:11236-11241) is not printed for these: P4-9's line names what to write instead. kernel(GAUSSIAN) gets the hint `use kernel(<value in lower case>)`; xsize(()) and a string colorvar() are not synonyms and print twoway's line alone. A p# hit prints twoway's p# line instead, `option(s) <tokens> not allowed`, `<tokens>` being the refused tokens of that plot's p# texts as typed -- its own `p<j>()` text's first, then the graph-level `p<k>()` text's -- joined by one blank (measured 20oct2026: `p1(malpha(50))` gives `option(s) malpha(50) not allowed`, `p1(mal(50))` `option(s) mal(50) not allowed`, `p1(malpha(50) mcolor(red) jseed(3))` `option(s) malpha(50) jseed(3) not allowed`, and `(scatter mpg weight, p1(jseed(3))) (scatter price weight), p1(malpha(50))` `option(s) jseed(3) malpha(50) not allowed`), then the first token's hint line (P4-9), r(198).
- **D-35-07.c Non-word forms.** V1-V3 have their own checks (TR-35-07.4). V4 is implemented by 42-05 (CV-14), which needs 37-01's zero-observation check (WP-37, after WP-35); V5 by 43-05 (LT-24), under P4-5. This section records both rulings.

- **D-35-07.e Every use of a refused word is found and classed.** Once a word is refused, every place that types it as a dash option breaks or turns false: the examples (test/test_examples_run.cscript runs every examples/*.do and fails on any non-zero rc), the cscripts that use a word as working syntax while testing something else, and the help lines that present it as a dash option. The search is one extended regular expression, `R` below (each word's full name, the seven words that take an abbreviation written from their dash minimum with each further letter optional, an optional SMCL `:` split, then `(`), run with `grep -n -E`:

  `\b(ytitle2|ylabel2|yscale2|xtitle2|xlabel2|xscale2|yti2|yla2|ysc2|xti2|xla2|xsc2|ytick2|xtick2|yline2|xline2|ymtick2|ymlabel2|xmtick2|xmlabel2|tlabel2|ttick2|tline2|tscale2|ttitle2|marker|mal(p(h(a)?)?)?|lalp(h(a)?)?|fa(l(p(h(a)?)?)?)?|jse(e(d)?)?|mlg|cv|colv|colorn(l(e(v(e(l(s)?)?)?)?)?)?|colorm(i(s(s(i(n(g)?)?)?)?)?)?|plotbgcolor|pbgc|colpal(e(t(t(e)?)?)?)?)(:[a-z]*)?\(`

  Every task and verify that writes `$R` first sets `R` to this expression in its shell (single-quoted). Each hit is classed `pin` (asserts that dash takes the word, or today's answer for it: flipped in place, R9), `incidental` (types the word as working syntax to test or show something else: rewritten to the twoway spelling the row's hint names) or `other` (not the option: a `dash kpi` statistic such as `cv(price)`, a fixture's probe text read as data; unchanged). A help line is rewritten to the twoway spelling or deleted unless it names a word only to say it is refused, or is `other`.

- **D-35-07.f The kept words' differences are deliberate, not deleted (P4-7, D-33-10.a).** DT-15 closes `Closed`, so its plain rows leave every `*_KNOWN` table; a row whose key is hover() (any spelling from its minimum `hov`) or table records a difference P4-7 keeps, so 35-07-03 moves it, in the same file, into that table's companion dict with the ruling id -- `"<key>": "P4-7: hover() kept"` or `"<key>": "P4-7: table kept"` -- in `ABBREV_DELIBERATE` (test/test_abbreviations.py, TR-33-10.6), `DELIBERATE` (test/value_truth_known.py, TR-33-10.2) or the `<NAME>_DELIBERATE` beside any other table `python3 test/known_differences.py DT-15` names (33-11..33-13: `SCALE_FRAME_DELIBERATE`, `BY_POSITION_DELIBERATE`, `BY_TYPES_DELIBERATE`, `STAT_COMBOS_DELIBERATE`, `COLORVAR_DELIBERATE`). `known_problems(..., deliberate=...)` then drops those keys before its rules, so the hygiene tests stay green with DT-15 closed.
