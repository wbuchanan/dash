## Risk: [red] -- a coordinate transform on every glyph of an axis, the log tick input, and the axis finisher's JS

**Why.** CustomJSTransforms change how every renderer's coordinates are read in BokehJS; the finisher runs on every move of every saved page; the log tick input change touches every log axis.

**Risk factors.**
1. A transform missed on one coordinate property (e.g. `x0`/`x1` of a Segment, `left`/`right` of a Quad, a `HArea`'s `x2`) draws that glyph untransformed.
2. Hover tooltips read the source columns (original values): correct, but a test that compares hover x with glyph x may break.
3. The log input change moves ticks on every log axis with non-positive data; other log axes must not move.
4. `_dash_rep_reduce` is on every command's path; a wrong key test refuses a valid copy.
5. The span refusal adds `summarize` calls per plot at export (time).
6. 34-03/34-09 rewrote parts of `_dash_finish_count_ticks` and `dash_axis_finish`; anchors moved.

**Mitigation.**
1. `TestTransforms::test_every_coordinate_is_transformed` walks every glyph class in the dispatch tables (as test_mode_parity's `TestTheCorpusIsComplete` derives types) and every annotation of the five layout lists (44-02's custom-tick LabelSet and Whisker included) and derives each class's coordinate properties from its `dataspecs()` (the D-44-03.b rule), asserting each field spec carries the transform and each data-unit distance on the dimension is rewritten to the two columns; one parity entry per glyph family.
2. Hover is unchanged by design; the help says hover shows the data's values.
3. `TestLogTicks::test_positive_data_unchanged` runs every axis_truth.json log probe.
4. `TestExclusive::test_valid_copies` runs C16 and every axis_look_truth scale probe through the cscript case Q4403-6.
5. The span step runs only on `summarize`-able numeric variables already counted by 37-01's walk; 44-03-12 records the cert block's time.
6. Re-read both finishers at the 44.3 base; the node tests are written against that base.
