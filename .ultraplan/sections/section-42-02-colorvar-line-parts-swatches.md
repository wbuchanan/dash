# Section 42-02: colorfillonly line parts, two colorvar layers, pstyle swatch

> Part of: WP-42 (Colour variables, audit package 7) · Items: CV-1, CV-6, CV-7 · Risk: yellow · Batch: 42.2 · Depends on: 42-01 · Blocks: 42-03 · Tasks: 6, 3 commits · Case-id prefix: Q4202

## Overview

**What is wrong today.** Three colorvar drawing rules differ from twoway's.

- **CV-1.** `colorfillonly` strips the level colour from every line part. `_colorvar_paint` sets only `fill_color` when `fill_only` (dash_render.py:16983-16984), so a Segment, MultiLine or Line keeps the series colour, and `_colorvar_line_parts` returns None under colorfillonly (:17145-17147), so line/connected fall back to one plain line. The audit (CV-1): "colorfillonly only keeps marker and bar OUTLINES in the series colour. Every line is still coloured by level: line (5 level paths plus a grey missing path), connected's line, spike, dropline stems, rcapsym spines, pcarrow shafts and heads ... dash: The lines are drawn in the series colour #1a476f, with no note." Stata's colorvar_options.sthlp:178-185 limits colorfillonly to the outlines of "dots, bars, and markers".
- **CV-6.** Two colorvar layers (colorallowmultiple): "twoway draws one colour key, the last layer's ('Car origin', 0 .2 .. 1), plus a plot legend keying 'Mileage (mpg)' and 'Price' in p1/p2 (M1, K11/R03b). dash draws two ColorBars, one per layer, and no plot legend at all." Each layer adds its key (`_colorvar_key_place` calls :16723, :16860), and the strip loop (:16875-16886) removes each colorvar renderer's item from the plot Legend and the Legend once empty, so `_dash_apply_legend` returns early at `if not fig.legend:` (:39352-39355).
- **CV-7.** In a mixed graph the colorvar layer's plot-legend key "takes the first row's level colour, not twoway's colour": the LegendItem's renderer is the field-mapped glyph, and BokehJS draws a value-label item from row 0 (bokeh.js `get_reference_point` falls back to index 0). twoway draws it in the pstyle colour (p1 #1a476f under s2color, #1a85ff under stcolor) and, under coloruseplegend, in level 1's colour (#0000ff).

**After this section.** colorfillonly colours every line part by level and keeps the series colour only on marker and bar outlines; a graph with several colorvar layers draws one colour key, the last layer's, and the plot legend by twoway's two-key rule; a colorvar layer's plot-legend key is drawn through a legend-only proxy in its pstyle colour (level 1's under coloruseplegend). Both modes.

**Why one section.** All three are how a colorvar layer's glyphs and keys are painted after the stepped default (42-01), in `_colorvar_paint`, `_colorvar_line_parts`, `_colorvar_key_place` and the strip loop, owned here.

### Section decisions

- **D-42-02.a fill_only by glyph kind.** Under colorfillonly a glyph that has a `fill_color` property takes the colour spec on `fill_color` only; a glyph with no `fill_color` (Segment, MultiLine, Line, the arrow heads' MultiLine/Patches) takes it on `line_color`. That is twoway's "dots, bars and markers" rule expressed on Bokeh's glyph classes.
- **D-42-02.b The last layer's key.** When a colorvar layer adds its key (`add_key` true), `_colorvar_key_place` first removes from the figure every colour key an earlier layer placed (a ColorBar or a Legend named `_COLORVAR_LEGEND_NAME`), unless the earlier key belongs to the same renderer group (rconnected's two ends call with `add_key=False` for the second, so they are unaffected). The removed key's relevel plan keeps its reference and updates a model no longer drawn (harmless).
- **D-42-02.c No strip loop.** The strip loop (:16862-16886) is deleted; the plot legend follows `_dash_apply_legend`'s twoway rule (two or more keys draw one), so one colorvar layer alone still draws no plot legend and the mixed case still keys both series (test/test_colorvar_legend.py::TestTheMixedCase stays green).
- **D-42-02.d The proxy swatch.** Every colorvar layer's renderer gets `renderer._dash_key_proxy`: a glyph of the same class on the renderer's own `data_source`, with a `CDSView` of the renderer's `filter`, whose coordinate specs are the constant NaN (`value(float("nan"))`) and whose colours are constants -- the renderer's colours before colorvar painted it (its `fill_color`/`line_color` read at the top of `_apply_colorvar`), or level 1's colour under coloruseplegend -- named `__dash_keyproxy`; added to `fig.renderers`, excluded from every `HoverTool.renderers` and every `DataRange1d.renderers` dash sets. Because it has the layer's rows, it draws nothing (NaN at every row) and its legend key follows the layer's rows: once a filter move leaves the layer no row, the key is not drawn, as an item whose renderers have no rows draws none today (REVIEW-4 R4-26); and there is no extra source for the served redraw to pair. `_dash_legend_keys` (:58213) keys the proxy in place of the renderer. Click-to-hide keeps working: `proxy.js_link("visible", renderer, "visible")`, so hiding the item hides the series; the proxy carries `tags=["dash_key_proxy", <renderer name>]` and the Python attribute `proxy._dash_key_for = renderer`, and `_dash_by_panel_matches` (dash_render.py:55484), which by()'s legend cell uses to give a cloned item every panel's renderers (`_dash_by_legend_cell`, :55644-55680), resolves a proxy to its real renderer's place in panel 1 and returns each panel's own proxy there (`getattr(<panel renderer>, "_dash_key_proxy", None) or <panel renderer>`), so one click hides the series in every panel.

## Risk: [yellow] -- three changes to how every colorvar layer is painted and keyed

**Why.** `_colorvar_paint` is called by every coloured mapper; the strip loop has been in place since the first colorvar key; a proxy renderer adds a model to every colorvar figure.

**Risk factors.** 1. A glyph class with both properties where twoway draws only its outline coloured (none known: twoway's rule is per element kind). 2. Removing the strip loop could draw a plot legend where none was drawn: a single colorvar layer has one key, so `_dash_apply_legend` hides it -- pinned by a new test. 3. Proxy renderers counted by tests that count renderers (test_mode_parity `_glyph_profile`, test_colorvar_coverage). 4. A legend item holding only the proxy would match no by() panel renderer and break click-to-hide under by() (REVIEW R3-13); a proxy with rows of its own would keep its key after a filter move empties the layer (REVIEW-4 R4-26's rule).

**Mitigation.** 1. The fixture measures eight types under colorfillonly. 2. A regression test for the lone layer. 3. The proxy is tagged `dash_key_proxy`; parity and coverage counters skip renderers whose name is `__dash_keyproxy` (add the skip where they already skip `_DASH_SWATCH_PREFIX` swatches; grep `_dash_is_swatch` and `_DASH_SWATCH_PREFIX` in test/). 4. D-42-02.d's `js_link` and the proxy branch of `_dash_by_panel_matches`, pinned by a Chrome click test under by(); the proxy shares the layer's source and filter, pinned by `TestTheProxySwatch::test_emptied_layer_has_no_key` and a MOVE_CORPUS case that empties the layer (TDD stubs).
