# Section 33-06: dash image panel (registered SVG item)

> Part of: WP-33 (Verification corpus and README gallery) · Items: none (new feature for the gallery, PD-12/C4) · Risk: red · Batch: 33.2 · Depends on: 33-01, 33-15 · Blocks: 33-07, 33-08 · Tasks: 5, 1 commit · Case-id prefix: Q3306

## Overview

The gallery must be "built with dash itself": "each example shows its command, twoway's SVG, the live dash graph and the verdict" (Q16, Q58), now as one dash-built page per plot type plus a dash-built index page that links them, so each page loads quickly (maintainer decision P4-1, superseding Q16/Q58's single page), built only at the final closeout (P4-8, WP-50 WE.7) and showing only examples twoway draws (P4-10). Today dash cannot show an image: "Every user string reaches the page as a model property or escaped text, 'never as markup of its own' (dash.sthlp:2725-2728)" [C §4.2]. C4 resolves it with "a new registered image/SVG item placed by tabs()/layout() like a KPI".

After this section: `dash image using <file.svg>, name(<n>) [caption(<text>) alt(<text>) link(<page>.html)]` registers an image panel. The SVG is checked when registered and read again at build: well-formed SVG, refused if it holds a script, an event handler, a foreignObject, a DOCTYPE or entity declaration, or any external reference. The page draws it as `<img src="data:image/svg+xml;base64,...">` inside a Bokeh `Div` (an SVG inside `<img>` runs no script; the saved CSP already allows `img-src data:`), with the caption beneath and the alt text escaped. With `link(<page>.html)` -- a page in the same folder, matching `^[A-Za-z0-9_-]+\.html$`, else r(198) -- the `<img>` is wrapped in `<a href="<page>.html">`, so the picture opens that page; the gallery's index page links its per-type pages this way (P4-1, DECISIONS A-17). `layout()`, `tabs()` and `dash clear` treat the panel like a KPI card, in the saved page and the served app alike. A new count limit, `$dash_max_images` (default 100, at most 1,000), bounds how many a registry holds and is documented in Resource limits; it joins the nine count limits 33-15 leaves. Nothing bounds an image's bytes: there is no size cap on a dashboard (P4-3), so no file is refused for its size and no limit bounds the images' total (A-18); only their number is bounded, by this limit.

**Test order and commit rule.** 33-06-01 writes every regression test (Python and the cscript cases) and runs them red; 33-06-02 adds the Stata registrar and build export; 33-06-03 the renderer (both modes); 33-06-04 help, CHANGELOG and the parity entry; 33-06-05 runs the covering tests and the five cscripts and commits once: `Add dash image: a registered SVG panel placed by layout() and tabs() (WP-33 33-06)`.

### Section decisions

- **D-33-06.a (syntax).** `dash image using <file>, NAMe(string) [CAPtion(string) ALT(string) LINK(string)]` (`LINK` in full, as dash's graph option `link()` is spelled, dash.ado:975). `name()` follows `dash kpi`'s name rules (a letter or `_` first, then letters, digits and `_`; no `__`; not `_all`; `, replace` to reuse a name) with the same bound, **at most 18 characters**: an image's longest globals, `dash_img_<n>__pth`, `__cap`, `__alt` and `__lnk`, put 14 characters around the name (`dash_img_` 9, `__lnk` 5), as `dash_kpi_<n>__<field>` does, whose limit is 18 for that reason (dash.ado:12175-12181), so every image global stays within Stata's 32-character global names. A longer or ill-formed name is refused r(198) in `dash kpi`'s words with the subcommand's own prefix, `dash image: invalid name '<n>'. Names must start with a letter or underscore, contain only letters, digits, and underscores, and be at most 18 characters.` (the name echoed through the character filter `dash kpi` uses, dash.ado:12184-12185; its message :12186-12188). Without `replace` a taken name is refused as `dash kpi` refuses it. `alt()` defaults to the caption, else the name. `link(<page>.html)` (PD-12, A-17; dash-only, an option of dash's own subcommand, P4-7) names a page in the same folder: the text must match `^[A-Za-z0-9_-]+\.html$` in full (no scheme, no slash, no `..`, no blank), checked at registration by `_dash_image_link_ok` (TR-33-06.4), else r(198) `dash image: link() takes the file name of a page in the same folder: letters, digits, _ or -, then .html.` (the typed text is not echoed). Without `link()` the panel links nowhere. No other option.
- **D-33-06.b (what is stored).** Globals `dash_img_<n>` = `"1"` (the marker), `dash_img_<n>__pth` (the absolute path, from `c(pwd)` when relative, stored by value with Mata `st_global`), `dash_img_<n>__cap`, `dash_img_<n>__alt`, `dash_img_<n>__lnk` (the `link()` text as typed, `""` when none; each by value). The name joins `dash_graph_registry` (layout order is the registry's, `_dash_layout_order`). The file's bytes are not stored in a global (c(macrolen) would bound them).
- **D-33-06.c (checks).** One Python function `_dash_image_check(path)` (via sfi, as `_dash_write_data` calls Python) returns `""` or the refusal text prefixed by its return code (`"601 <text>"` or `"198 <text>"`); it runs at registration and again in `_dash_prepare_spec` for every image (the file may change between). Refusals: file missing r(601) `file <name> not found` (Stata's words for a missing file; at build this catches a file deleted since registration); not UTF-8, not XML, root not `{http://www.w3.org/2000/svg}svg`, or holding `<!DOCTYPE`/`<!ENTITY`, a `script` or `foreignObject` element (any namespace), an attribute named `on*` (any case), an `href`/`xlink:href` other than `#id` or `data:image/(png|jpeg|gif|svg+xml);base64,...`, or a `url(` not followed by `#` in any attribute or style text, or `javascript:`/`@import` anywhere: r(198) `dash image: <file> holds <what>; an image panel takes an SVG with no script, event handler, foreignObject or external reference.` The file name is echoed through `_dash_say` (user text), reduced to its base name. No file is refused for its size (A-18: no per-image byte bound; the whole file is read).
- **D-33-06.d (limit).** `images=100,1000` joins `_dash_limit_table` (dash.ado:5008-5021 after 33-15 removed its `cells` and `bytes` rows; re-read) and `"images": (100, 1_000, "dash_max_images")` joins `_DASH_LIMITS` (dash_render.py:2360-2376 after 33-15), which then holds ten keys. `_dash_image_cap <already>` refuses a new image when the registry holds the limit's number of images, r(134), in `_dash_graph_cap`'s words with "images" for "graphs and KPI cards". `_dash_graph_cap` stops counting images (it counts registry names whose `dash_img_<n>` is not `"1"`).
- **D-33-06.e (both modes from one URI).** `_dash_resolve_images(images)` (Python) reads and sanitises each file once at build and replaces `path` with `uri` (`data:image/svg+xml;base64,<b64>`), keeping `name`, `caption`, `alt` and `link`; the saved renderer and `ServerAppBuilder` both call it on the spec they load, so the served app's embedded spec carries the URI and no path. Both modes build the Div with one copied function `_dash_image_div(image)`.
- **D-33-06.f (markup).** `_dash_image_html(uri, caption, alt, link="")` = `<figure class="dash-image" role="group" aria-label="<alt>"><img src="<uri>" alt="<alt>" width="100%"><figcaption><caption></figcaption></figure>` with `alt` and `caption` passed through `html.escape(..., quote=True)` and the figcaption left out when the caption is empty; `uri` is asserted to match `^data:image/svg\+xml;base64,[A-Za-z0-9+/=]+$` before use. When `link` is not empty it must pass `_dash_image_link_ok` (else `ValueError`), and the `<img ...>` element alone is wrapped as `<a href="<html.escape(link, quote=True)>"><img ...></a>` (the caption stays outside the link); with `link` empty the markup is exactly as without the option. Both modes build this markup through `_dash_image_div`, so the saved page and the served app carry the same `<a href>`. The Div: `Div(text=html, sizing_mode="stretch_width", disable_math=True)` with `_dash_aria(div, alt, role="group")` as the KPI card (dash_render.py:70954-70959).
- **D-33-06.g (help promise).** dash.sthlp:2725-2728's "never as markup of its own" gains one sentence: an image panel shows an SVG file that dash has checked, inside an image element, which runs no script; its only link is the `link()` page in the same folder.

## Risk: [red] -- new user-facing markup path, registry and both renderers

**Why.** It is the first user-supplied markup on the page, it shares the registry with graphs and KPIs, and it touches `_dash_layout_cell` and the served app source (R12 hot functions). **Risk factors.** SVG sanitising; a `link()` that leaves the folder or breaks out of its attribute; the registry counters; name collisions between kinds; served/saved drift; the CSP. **Mitigation.** Refuse rather than strip (D-33-06.c); one link rule, `_dash_image_link_ok`, at registration and in the markup, and the link escaped (D-33-06.a, f); `<img>` isolation; a CSP browser test; one Div builder copied by name into the served app; a parity entry; collision cases in test_registry_collision.cscript.

## User stories

- US-33-06.1 As the dashboard author, I want to place an SVG picture beside my graphs, in a tab or a layout cell, with a caption, so that a dashboard can show a reference image.
- US-33-06.2 As the README reader, I want each plot type's gallery page to show twoway's picture beside dash's live graph so that I can compare them on one page.
- US-33-06.3 As the README reader, I want each picture on the gallery's index page to open its plot type's page so that I reach any page in one click.

## Business requirements

- BR-33-06.1 `dash image using f.svg, name(n) caption(c)` places the picture where `layout()`/`tabs()` put `n`, with `c` beneath it, in a saved page and a served app alike.
- BR-33-06.2 A file holding a script, an event handler, a foreignObject or an external reference is refused with r(198); a missing file with r(601); more images than `$dash_max_images` with r(134). No file is refused for its size.
- BR-33-06.3 Caption and alt text are shown as typed, never interpreted as markup or macros.
- BR-33-06.4 Images do not count against `$dash_max_graphs`; `dash clear` removes them.
- BR-33-06.5 A dashboard with no image is unchanged byte for byte in its spec and page (no `images` key, no new script).
- BR-33-06.6 `link(p.html)` wraps the picture in the same relative link, `<a href="p.html">`, in a saved page and a served app alike: in a saved page it opens `p.html`, the page beside it in the same folder; in a served app the relative address resolves against the app's own address (dash serve serves no folder of pages). Any other `link()` text (a scheme, a slash, `..`, another extension) is refused with r(198).
