## Overview

**What is wrong today.** basic:PT-11 (with TR-18, DT-20, sil:SD-17, ST-20): "Noted options twoway draws: back markers (bm*), alalign/blalign, mlabalignment, mlabjustification, bartype(spanning), dropto(), numkeys(), omitanymiss on multi-y, dlpattern(), xtransform, onepanel etc." The audit's verifier measured that twoway draws something different for "P7/P8 (blalign/alalign outside, 36 lines), P17/P18 (mlabalignment(top)/mlabjustification(right), 20 each), P19 (bartype(spanning), 338), P34 (bmsymbol, 149), P38 (numkeys(3), 372), Q22 (149), plaintypes3 R2 (dropto(y), 626), R3 (omitanymiss on a multi-y line with missing values, 4) and R4 (bmlcolor/bmlwidth, 298)"; dash accepts each, names it in "(note: dash: ignoring unsupported option(s): ...)" and draws the default. They are listed in dash.sthlp's Unsupported section (:6455-6612). The audit's fix: "Draw them ... or keep them documented as gaps", and the maintainer ruled package 15 "Resolve. Fix all."

**After this section.** Every option on dash's catch-all and pending lists that twoway draws differently on some plot type is drawn there, in both modes, after a move, silently -- or, where a part cannot be drawn with Bokeh's shipped models and CustomJS, documented under Differences with a measured example (M11's rule, applied to this package). Options twoway draws the *same* picture with are not this section's: they are basic:PT-12's (49-02, silence); options another section owns are listed with that section and only checked here.

**Why one item, one section.** The audit gives basic:PT-11 one id and one fix; the section is red because it touches many mappers. It runs alone in batch 47.4, in four tasks, within BRIEF's one to four per item and index M13's sections of 1-4 tasks (REVIEW-5 R5-10): measure and classify, write the failing tests, draw every Draw row (one group per paragraph, each group's tests green before the next), then regenerate, document and make the item's one commit (the index's commit unit).

**Test order and commit rule.** 47-05-01 measures every candidate on every type and classifies each row from the measurement (no commit; a maintainer question only for a part that would be documented instead of drawn); 47-05-02 writes all failing tests and saves the failure text (no commit); 47-05-03 draws the Draw rows group by group, each group's tests green before the next (no commit); 47-05-04 regenerates the tables, corrects the help and makes the one commit `(WP-47 basic:PT-11)`. No full suite inside the section.

## Risk: [red] -- many mappers, a new renderer on every marker layer, data rules for multi-y layers

**Why.** Back markers add a renderer to every marker layer that names one; omit rules change which rows multi-y layers draw; bartype/dropto change bar geometry; numkeys changes legend numbering.

**Risk factors.** 1. Legend numbering: `numkeys()` shifts every later key's number, which `order()`/`label()` read. 2. The brush and hover must ignore back markers. 3. omit rules across separate dash plot records (each y is its own record). 4. Unknown scope until 47-05-01 measures. 5. Commit size (one item). 6. Per-type refusals: a declared word no longer reaches the catch-all.

**Mitigation.** 1. Measure `numkeys(3)` with `legend(order(...))` and `label()` and copy twoway's numbering. 2. Back markers carry null row ids and no hover (the dots renderer convention, `dash_dots`). 3. dash.ado writes the siblings list; the renderer masks on all siblings' columns. 4. 47-05-01 classifies every row from the measurement before any code (a maintainer ruling only for a part that cannot be drawn). 5. The section's tests run per group (47-05-03); the commit is made after all groups pass. 6. A newly declared word bypasses the catch-all's per-type acceptance (`_dash_tw_takes_tab`), so TR-47-05.1 writes its refusal row from the measurement.
