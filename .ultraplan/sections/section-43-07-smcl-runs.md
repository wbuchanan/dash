## Overview

**What is wrong today.** ST-14 with TR-14, DG-17 and PIC-18 (audit :437-439; appendix ST-14, TR-14, DG-17, PIC-18): "Partial SMCL markup ({bf:}, {it:}, {sup:} on letters, fonts) in titles, labels and keys is drawn in one plain style". twoway draws `title("a {bf:b} c")` with only the b bold, raises the q of `a{sup:q}`, italicises only the p of `{it:p}-value`, and in `xlabel(3000 "{it:italic} text" 4000 "{bf:bold}" 5000 "a{sup:2}")` styles each run; dash gives a drawn text one style, font and baseline (dash.sthlp:5171-5183), draws partial markup in the text's own style with one note per graph and kind (`_dash_graph_text_note`, dash_render.py:49186-49205), and raises only characters with a Unicode superscript form (`_DASH_GT_SUP`, :48418). graph_text.sthlp's examples 13-16 print the note (probe6). The BUGS entry "Inline SMCL style runs and raised text with no Unicode form are drawn in the text's own style ..." (BUGS.md:3689) was closed as a documented limit (M17, D-42a).

**After this section** a text with markup on part of it is drawn as positioned runs -- one canvas `Label` per run, each in its own weight, slant, size, font and baseline, placed side by side from the browser's own text measure -- for titles, subtitles, notes, captions, edge titles, axis titles, explicitly placed tick labels, added text, the legend's title and key texts, and by() panel titles, in both modes, in the SVG export and under `scale()`. The runs are one more kind (`text_runs`) of 43-01's one layout dispatcher per figure, run after every other kind (R4-7). The note is printed only for the texts still drawn in one style: marker labels and tooltips, the composite's residual, documented under Differences with one measured example command (A-26), so ST-14 closes `Documented` (M11, A-5: no open entry).

**Why one section.** One item; it touches the drawing of every text kind, so the manifest runs it alone in the last batch (it owns "text drawing of titles, labels and keys").

**Test order and commit rule (BRIEF).** 43-07-01 writes every regression test and the fixture and saves the failure without committing; 43-07-02 is the spike and checkpoint; 43-07-03..05 build the runs per text kind (no commit; the tree stays green at each step for the tests touched); 43-07-06 certifies and makes the one commit `(WP-43 ST-14)`.

### Section decisions (binding on the executor)

- **D-43-07.a Runs.** `_dash_text_runs_of(text) -> list[dict] | None`: None when a line of *text* needs one style (today's route stays); else, per line, the runs `{"t": text, "b": bold, "i": italic, "f": family or None, "s": size factor, "v": baseline shift in em}` read by the existing parser (`_dash_graph_text_runs`, :48700, which already splits markup into runs to decide the uniform style), `{sup:}` as `s = 0.70`, `v = +0.35` and `{sub:}` as `s = 0.70`, `v = -0.20` unless the fixture (`sup_scale`, `sup_shift`, `sub_scale`, `sub_shift`, measured from twoway's SVG) gives other values -- the fixture's values are used. A run whose characters all have a Unicode super/subscript form keeps today's Unicode drawing (one run, no shift), as now.
- **D-43-07.b Drawing.** A model whose text has runs keeps its place: a `Title` keeps its text with `text_alpha = 0` (a spacer: Bokeh lays it out at its real size); a `Label` (text(), a ring(0) box, a 43-01/43-04/43-05 overlay Label) keeps its point with `text_alpha = 0`; an axis keeps `axis_label` with `axis_label_text_alpha = 0`; a fixed tick label is overridden to `" "` in `major_label_overrides` at that tick; a Legend title or key text (spacer or key cell, 43-01/43-04) keeps its alpha-0 text. ## Risk: [red] -- every text kind's drawing, JS-placed runs, stale cues and export

**Why.** Every graph with markup on part of a text changes from one model to several, placed by layout-time JS that must stay right after resizes, moves, font loading and in the SVG export.

**Risk factors.** 1. `_dash_finish_graph_text` is the last pass in both modes; new models must be in the document before serialisation and after the pass (marked done). 2. The stale cue rewrites Title/LegendItem texts. 3. Tick labels move with moves only when automatic -- explicit ones never; an explicit tick list with markup on a moving axis is handled by the overrides only (the run Labels sit at data x). 4. CSP (CustomJS models only). 5. Accessibility: alpha-0 spacer text stays in the canvas, not the DOM (screen readers read Legend DOM labels: the alpha-0 Legend label keeps the full text there, so a screen reader reads it once; the runs are canvas). 6.
