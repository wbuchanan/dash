## Overview

**Why one section.** Both items close "a committed oracle nobody compares", both are syntax-level (values and spellings), and both introduce the known-differences mechanism the other WP-33 truth sections reuse.

**Test order and commit rule.** Two cycles, two commits in manifest order: TR-11 (tasks 01-03), then syn:SD-20 (tasks 04-06). Task 01 writes TR-11's failing tests on the unmodified tree; task 04 writes SD-20's on the tree TR-11's commit leaves. No full suite inside the section.

### Section decisions (binding on the executor)

- **D-33-10.a Known-differences rule (all of WP-33's truth sections; A-10).** A known-differences table is a module-level Python dict named `<NAME>_KNOWN`, `{key: "<GAPS4 lead id>"}`, whose value has one of three forms, as 33-05's ledger rows do (D-33-05.e): `"<id>"` (an item to be fixed), `"<id> (documented)"` (a Kind Document item; A-10) and `"<id> (residual)"` (the residual of a Partly item). `test/known_differences.py` (new, this section) provides `gaps4_open_ids()`, `gaps4_documented_ids()`, `gaps4_partly_ids()` and `known_problems(results, known, label, deliberate=None)`; a check built on it fails on (1) a key that differs from twoway and is not listed, (2) a listed key that now agrees with twoway ("delete its row: <id> fixed it"), (3) a listed key whose row is not live -- `"<id>"` needs the item open, `"<id> (documented)"` open or Documented, `"<id> (residual)"` open or Partly closed ("the row should have gone with <id>'s fix") -- and (4) a listed key the comparison no longer produces. So a Fix item's closing commit deletes its plain rows (rule 3 tells it to), and the rows of documented or residual differences stay after their item closes, as known differences (A-10; REVIEW-1 R1-16). **Deliberate differences.** A difference a ruling keeps on purpose -- a dash-only word P4-7 keeps (hover(), table), a word CV-14 keeps (A-12) -- has no item left once its item closes `Closed`, so it is not a `_KNOWN` row: each table has a companion deliberate dict `{key: "<ruling id>: <what is kept>"}`, the ruling id a DECISIONS or index id (P4-n, A-n, Q-n, M-n) -- named `<NAME>_DELIBERATE` beside `<NAME>_KNOWN` (e.g. `"hover": "P4-7: hover() kept"` in `ABBREV_DELIBERATE`), except `VALUE_KNOWN`'s, which is `DELIBERATE` in test/value_truth_known.py -- and `known_problems(..., deliberate=<that dict>)` removes its keys from `results` before rules 1-4 (a key in both dicts then fails rule 4, so no key is in both). A Fix item whose ruling keeps a difference (DT-15, P4-7; CV-14, A-12) therefore closes `Closed`: its closing commit deletes the item's plain rows and moves each kept difference's key into the table's deliberate dict with the ruling id. The dicts are `DELIBERATE` in test/value_truth_known.py (TR-33-10.2, for `VALUE_KNOWN`), `ABBREV_DELIBERATE` in test/test_abbreviations.py (TR-33-10.6, for `ABBREV_KNOWN`) and 33-11..33-13's `<NAME>_DELIBERATE` beside their `<NAME>_KNOWN` tables (`SCALE_FRAME_DELIBERATE`, `BY_TYPES_DELIBERATE`, `BY_POSITION_DELIBERATE`, `STAT_COMBOS_DELIBERATE`, `COLORVAR_DELIBERATE`), all empty when written. `dead_rows(known, label)` applies rule 3 alone, without running the comparison; every table's hygiene test calls it, is named `test_every_known_difference_is_open`, and runs in the default tier, so one `-k` selects them all and every gate runs them.

## User stories

- **US-33-10.1** As the Stata user with an existing twoway command, I want dash to refuse a bad option value with twoway's return code and words, so that my error handling (`capture`, `_rc`) behaves the same.
- **US-33-10.2** As the Stata user, I want every abbreviation twoway accepts to mean in dash what it means in twoway, so that `bgc(red)` or a shared prefix does what I typed.
- **US-33-10.3** As the maintainer, I want every known difference listed under the item that fixes it, so that a fix that lands is seen and an unplanned regression fails.

## Business requirements

- **BR-33-10.1** For each of value_truth.json's 311 probes, dash's registration return code (and, where twoway refuses, its first line) equals twoway's, and where twoway refuses and registration passes, so does dash's rendered return code -- or the probe is listed under a live GAPS4 row. The 230 probes twoway draws are compared at registration only (A-10).
- **BR-33-10.2** Every option dash declares has twoway's minimum abbreviation and binding measured, or a measured reason it cannot be (twoway refuses the full name, or the context does not reproduce).
- **BR-33-10.3** No fixture says twoway lacks an option twoway takes.
- **BR-33-10.4** A known-differences list cannot hold a row for a fixed item, nor miss a new difference.
