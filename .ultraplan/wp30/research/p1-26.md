Visibility of a twoway note vs output channels (m5/m6, inside a program, SMCL log):

| channel | plain | quietly | capture | capture noisily | set output error | SMCL class |
|---|---|---|---|---|---|---|
| twoway's note | shown | **shown** | hidden | shown | **shown** | `{txt}` in `{p 0 4 2}` |
| Python stderr (today's notes) | shown | shown | hidden | shown | shown | `{err}` (red) |
| `print()` | shown | hidden | hidden | shown | hidden | `{res}` |
| `SFIToolkit.displayln("{txt}..")`, `noisily display`, Mata `printf` (`_dash_say`) | shown | hidden | hidden | shown | hidden | `{txt}` |
| `SFIToolkit.errprintln("{txt}..")`, `display as error "{txt}.."`, Mata `errprintf("{txt}..")` | shown | **shown** | hidden | shown | **shown** | `{err}{txt}` (text colour) |

So twoway's notes behave like error-class output drawn in text colour.
`errprintln("{txt}" + text)` reproduces that matrix exactly; `displayln` does
not (hidden by `quietly`). `errprintln` interprets SMCL (m6:
`errprintln("... {bf:B} {stata display 7:L}")` logs the raw directives), while
Python stderr does not (m4: `msymbol({stata display 999:x})` is echoed
literally). A long `errprintln` line wraps with "> " in a text log (m8), as
today's stderr lines do, so `cert_helpers.do`'s rejoin keeps working; a
`{p 0 4 2}` paragraph would word-wrap without "> " and break it.

## 3. Approach (both modes)

Rule: keep `warnings.warn` as dash's internal note mechanism (about 16.7k tests
capture notes as warnings; `_dash_warn_once`, `_dash_style_note` and
`_dash_reset_notes` are CRITICAL and are not edited). Change only the
boundaries where notes leave Python.

### Section A: one note channel in Stata's process (X4-a..d, plus m7)

1. New `_dash_smcl_escape(text)` in dash_render.py: printable characters only
   (as `_dash_display`), `{` -> `{c -(}`, `}` -> `{c )-}` (the Python twin of
   Mata `_dash_smcl_text`, dash_parse.mata:640-670). Security: a note echoes
   user text (option values, titles, variable labels) and `errprintln`
   interprets SMCL, so without it `msymbol({stata ...})` would print a
   clickable command in the Results window.
2. New `_dash_emit_note(text)`: inside Stata, `sfi.SFIToolkit.errprintln("{txt}"
   + _dash_smcl_escape(text))`, main thread only; outside Stata, one plain line
   to `sys.stderr` (flushed). No path, no source line.
3. New context manager `_dash_note_scope()`: `warnings.catch_warnings()`, then
   `warnings.filterwarnings("always", message=r"dash(_render| kpi| build| serve)?[: ]",
   category=UserWarning)` inserted first, and `warnings.showwarning` replaced by
   a function that sends dash messages to `_dash_emit_note` (de-duplicated by
   text within the scope, since "always" disables Python's per-location
   de-duplication) and passes every other warning to the saved original
   `showwarning` unchanged. Notes print as they are raised (twoway prints while
   drawing), so a render that later fails still shows its earlier notes. The
   user's filters are restored on exit; they no longer hide or escalate dash's
   notes, and still govern other libraries' warnings.
4. Wrap the `main()` call in the `__main__` block (dash_render.py:37627) in
   `_dash_note_scope()`; the scope ends before `_dash_launch_app` blocks, and
   returns the set of note texts printed (for B4). `main()` itself is not
   wrapped, so tests calling `main()`/`render()` still see warnings.
5. dash.ado: new Mata `_dash_note(before, value, after)` in dash_parse.mata
   (`errprintf("{txt}%s\n", _dash_smcl_text(...))`), used by the `_dash_say("txt",
   "dash: ...")` call sites that are notes (11 `txt` sites; at least
   dash.ado:4995). `_dash_say` itself is not changed (68 call sites).
6. Help (dash.sthlp, near 594-604 "named once per command, in a single note"):
   notes are printed as twoway prints its notes -- shown under `quietly`, hidden
   by `capture`, unaffected by Python's warnings filters or PYTHONWARNINGS.

### Section B: served notes (F5a, F5b, S12)

1. Build-time trial (F5a). `ServerAppBuilder.build(..., trial=False)` gains a
   keyword; `main()`'s server route passes `trial=True`. After the source is
   generated and written, compile that same in-memory source and exec it in a
   fresh namespace with `_DASH_TRIAL = True`, call its `make_document(Document())`
   under `catch_warnings(record=True)`, and re-issue each recorded dash note in
   the building process with `warnings.warn` (once per text). In
   `_generate_app_source`: read `_DASH_TRIAL = globals().get('_DASH_TRIAL',
   False)` at the top, and skip `make_document(curdoc())` (generated 36412-36413)
   and `_dash_install_access_log_redaction()` (36410) when it is set, so the trial
   touches no global curdoc, no logger and starts nothing (the generated module
   has only these top-level side effects plus the `__main__` block and the
   scheme-fallback warning: AST of b2.py, measured). A trial exception becomes
   one note ("the served app could not draw this dashboard: <type>: <msg>; the
   app was written") rather than a failed build. Cost: one render; 0.5 s on
   auto (measured: compile 0.16 s, exec 0.37 s, make_document 0.05 s), up to a
   saved build's own render time at large N (GAPS2: lowess 27.7 s at N=100k).
2. Child notes (F5b, PYTHONWARNINGS). In the generated app (module level, so it
   also holds under `bokeh serve`): install a process-wide `showwarning` that
   prints each distinct dash note once per process to stdout as a plain
   "dash: ..." line (flushed), plus the same "always" filter for dash
   messages. Non-dash warnings keep the default `showwarning`. The child owns
   its process, so a global hook is acceptable there (never in Stata's process).
3. Launcher (F5b). `_dash_launch_app`: relay stderr lines as well as stdout,
   through the same `_clean` + `_dash_redact_query(..., token)` path, keeping
   the 20-line failure tail. Lines starting "dash: " go to `_dash_emit_note`
   (de-duplicated, and skipped when already printed at build: new
   `said=` keyword fed from A4's set); other lines keep `print`. Two budgets:
   notes up to 100 distinct lines, other output the existing 200 (so a
   refused-request WARNING flood, P2.38, cannot crowd out notes). All printing
   stays on the main thread (the drain loop); the pump threads only queue.
4. Empty-layer note parity (S12). Pending decision D1:
   - D1(a) match twoway: a layer whose own if/in keeps no row is silent in both
     modes. `_dash_note_empty_layer` (LOW) gains `layer_rows=None`; silent when
     `layer_rows == 0`. Served call (generated 35405) passes `len(g_df)` as
     `layer_rows` and `len(_g_df_graph)` as `rows`; saved call
     (`_make_figure_body`, dash_render.py:30643, **CRITICAL**) passes the layer's
     qualified row count.
   - D1(b) keep the report, uniformly: served passes `len(_g_df_graph)`;
     `_dash_layer_drew_anything` (LOW) reads the renderer's view filter
     (`GlyphMapper._view_mask` semantics) so scatter, connected and rconnected
     are noted too. No CRITICAL edit.
5. Help: `dash build, server` names the same notes as the saved build; `dash
   serve` prints them before it starts and relays the app's later notes and
   output (bounded); `python app.py` prints them on its own output.

## 7. Decisions for the maintainer

- **D1. A layer whose own if/in keeps no row.** twoway is silent on all 18
  types measured. Today saved notes 11 types, served none. (a) Match twoway:
  silent in both modes (also what `_dash_note_empty_layer`'s own docstring
  rule says); touches CRITICAL `_make_figure_body` by one argument. (b) Keep
  dash's report and make it uniform in both modes (scatter, connected and
  rconnected gain the note). Recommend (a); answer it together with the §4
  A11/C8 decision.
- **D2. How a note looks.** (a) Match twoway: text colour, shown under
  `quietly` and `set output error`, hidden by `capture` (`errprintln("{txt}")`).
  (b) Ordinary text (`displayln`): hidden by `quietly`, unlike twoway. (c) Keep
  Python stderr: red, with path. Recommend (a); consistent with WP-30 M1
  ("Match Stata").
- **D3. Build-time cost for served builds.** The trial adds one render to
  `dash build, server` and `dash serve` (the saved build already pays it).
  (a) Always trial. (b) Skip above a size and say notes appear when a session
  opens. Recommend (a).
