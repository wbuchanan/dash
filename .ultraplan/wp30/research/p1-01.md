## 4. Approach

Fix it in Stata. No renderer edit is needed. GitNexus rates `_apply_marker_opts` and `_dash_style_note` CRITICAL, and both stay untouched.

1. **Keep the quotes.** In `_dash_parse_plot_opts`'s `syntax` (`dash.ado:922-960`), declare the list options `string asis`: mcolor msymbol msize msangle mfcolor mlcolor mlwidth mlabel mlabcolor mlabsize mlabposition mlabgap mlabangle mlabformat lcolor lwidth lpattern color fcolor fintensity clcolor clpattern clwidth pstyle mstyle lstyle mlstyle connect cmissing jitter base barwidth. acolor, alcolor, alwidth and alpattern also go in the set if a truth case confirms they are lists. Values are still read by value (`st_global`), so JSE-69's no-expansion rule holds.
2. **Mata splitter** (new, `dash_parse.mata`, next to `_dash_rep_toks` at :4376, which it reuses unchanged together with `_dash_quote_step` :1762):
   - `string scalar _dash_stylelist_pick(string scalar raw, real scalar i)` returns element *i* after twoway's rules: `.` gives "" (omit the key); `=` repeats the previous element (as the first element it means `.`); `..`/`...` repeat to the end, also when glued (`red..`); a short list pads with ""; extras are ignored. It strips one level of quotes from the element, plain or compound. A quoted `"."` is a literal element.
   - `real scalar _dash_stylelist_bad(string scalar raw)` returns 1 when `..`/`...` is not last.
3. **Validation** (`_dash_validate_opts`, `dash.ado:2577`; `_dash_validate_value`, :2125; rules at :2025):
   - For list keys, refuse a `..` that is not last with twoway's words and r(198): `<opt>(<value>):  invalid syntax`.
   - Validate each element with the existing kind. jitter stays 0-100 per element (dash's stricter rule, already documented). base and barwidth are checked per element on bar, dropline, spike and area. rbar's barwidth stays a scalar, refused r(198) as twoway refuses it. `msangle` is per element. `mlabel=var` becomes a per-element variable check: r(111) "variable X not found", and a list is allowed.
   - `_dash_fold_mlab` (:1691) reads the raw list.
4. **One JSON per series.** Give `_dash_plot_opts_to_json` (:3131) a series index (default 1). For list keys it writes `_dash_stylelist_pick(s(key), i)` and omits the key when the result is empty. Other keys are unchanged. In `_dash_process_segment` (:4330-4370), call it inside the `_yi` loop with `_yi`, and with 1 in the single-plot branch. Calling it with 1 is what makes every single-y type take the first element. `_dash_extract_vars` (dash_parse.mata:2227) already gathers each series' `"mlabel"`, so `mlabel(make rep78)` exports both variables with no change.
5. **Scalars stay scalars**: sort, recast, horizontal, vertical, yaxis/xaxis, colorvar and its family, every estimation option, jitterseed/jseed, and dash's own malpha/lalpha/falpha (see Decision D3).
6. **Docs.**
   - `dash.sthlp`: add a "Stylelists" paragraph under Plot types (near :243) giving the rules above and saying that RGB must be quoted (already :2717).
   - `dash.sthlp`: remove the "dash also refuses ... mlabel() with more than one variable" clause (:740-742), and make jitter() (:3233) "# or a list, one per y".
   - BUGS.md: a new entry (rule 7). CHANGELOG.md: before and after. REMAINING.md row 06 and ROADMAP: close "positional plot-options".
   - Record that TR-28.1's "recycles the last value" claim is refuted (T02, T42, T43, U21, W28).

Effort: L overall (DROPIN said M; the measured scope adds f-i). Risk: yellow. Every multi-y dashboard with a single style value changes: twoway styles only the first y. No repository example or cscript uses that form except SV-04 (`test_string_values.cscript:369`, `mlabel(s)` on 5 y). SV-04 asserts the data round-trip only, and s is still exported through series 1.

Split into two plan sections:
- **P1.1a stylelists of style options**: steps 1, 2, 4, 5, the shorthands, quotes, padding, first-element-on-single-y, the `..` refusal, decisions D1/D2, and the help paragraph. M.

## 7. Decisions for the maintainer

- **D1. A single value or short list on several y.**
  - Options: (a) MATCH twoway: pad with `.`, so `line a b x, lwidth(thick)` thickens a only. (b) Keep dash applying a lone value to every series (an undocumented extension, silent). (c) Recycle the last value (TR-28.1). Measured wrong, so not an option.
  - Implication of (a): existing multi-y dashboards with one style value change look, with no note (twoway gives none).
  - Recommend (a), as WP-29's M1 did for join order. Record it in CHANGELOG with before and after.
- **D2. Unquoted RGB `mcolor(255 0 0)`.**
  - Options: (a) match twoway: three elements; element "255" is noted and the series drawn with dash's unknown-colour fallback. (b) Keep reading exactly three unquoted integers as RGB on a single-y plot only. (c) Keep it everywhere (ambiguous on several y).
  - Recommend (a): the help already documents quoted RGB (:2717). The comma form `255,0,0` stays dash's extension (HC2-16p).
- **D3. dash-only options (malpha, lalpha, falpha, jseed).** twoway refuses them (U32 falpha r(198)). Options: list or scalar. Recommend scalar (today's behaviour), and document it.
- **D4. Unknown element default.** twoway draws "default attributes" (a black colour, a circle, medium size); dash draws the series' scheme default. This divergence predates the fix and also applies to single values. Recommend leaving it to P1.13 or the refuse-vs-note decision.
- **D5. `..` not last.** twoway gives r(198) `mcolor(red .. blue):  invalid syntax`. Recommend refusing with twoway's words and rc.
- **D6. Element checks stricter than twoway** (jitter 0-100, barwidth > 0, where twoway lets `2 abc` and `1 -2` through). Recommend keeping dash's per-element refusals, which are already documented.
