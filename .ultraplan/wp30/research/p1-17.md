## 3. twoway's truth (StataNow 19.5, scheme s2color, console binary via the slot)

### Widths

The SVGs were read with `scripts/svg_truth.py` (read.py: rect width ÷ px-per-x-unit from the fitted tick axis).

```
t1.do: twoway bar y x1 / xp1 / x5 / xu ; rbar lo hi x1|x5 [barwidth(.3)]
bar_s1   w_x=0.9999..1.0001 (all 5)   bar_s01 w_x=1.0000   bar_s5 w_x=1.0000   bar_su (uneven) w_x=0.9999
bar_s01: x axis [-0.4266, 1.0266] although xscale(range(0 .6))  -> the scale includes each bar's full width
rbar_s1 w_x=0.9999   rbar_s5 w_x=1.0000   rbar_bw03 w_x=0.3000
dates (readdate.py): bar_daily 0.9999 days; bar_weekly 0.9999 days; bar_weekly_bw3 2.9999 days
t4.do %tm: m_bar width 1.0 month (centres at whole months); barwidth(.5) 0.5; rbar 1.0
t5.do class values: bar .bar_size=1 by default, .3 with barwidth(.3)
```

Rule: the width is `barwidth()` in the x variable's own units, default 1. Spacing has no effect. On bar and rbar, `%td` gives days and `%tm` gives months (the axis is linear in periods).

### Caps

These are cap `<line>` lengths in SVG units. The canvas is 3960×2880 for 5.5×4 in.

```
rcap default 44.06 | msize(medium) 44.06 | tiny 10.02 | small 29.95 | large 70.04 | vlarge 89.97 | msize(2) 57.55
rcap at x spacing 5: 44.06 (unchanged)  | xsize(11) ysize(4), canvas 7920x2880: 44.06 (unchanged)
scheme(stcolor), canvas 5400x3240: 33.75 (= small 1.04166 x 32.40)
style files: tiny .34722, small 1.04166, medium 1.52778, large 2.4306, vlarge 3.125 (ado/base/style/symbolsize-*.style)
t5.do: .plot1.style.marker.size.val = 1.52778 for a default rcap under s2color (scheme `symbolsize p medium`)
rcapsym: 0 cap lines, 5 spines, markers only (20 circles = 10 markers drawn as fill+outline)
```

Rule: the cap length equals the msize value in Stata relative units, as a percentage of min(graph W, H). Measured: 44.06/1.52778 = 28.84; tiny gives 28.86, large 28.82, vlarge 28.79; min(W,H)/100 = 28.8. The cap is drawn in screen units, independent of the x data. The default is the scheme's `symbolsize p#`, the same size a marker of that plot gets. Caps carry `stroke-linecap="round"`. rcapsym draws no cap lines.

The help's sentence "the value of yvar closest to 0" (twoway_bar.sthlp:125-127) is wrong for y12: twoway draws from 10, not 12. Its other sentence, "bars extend ... to the x axis" (:111-114), is right.

## 4. Proposed approach

The item splits cleanly in two. **17a** (widths and caps) needs no axis knowledge and is invariant under filter moves. **17b** (default base) needs the finished axis scale, in both modes and after every move. That is the machinery P1.3 builds.

### 17a. Widths and caps (dash_render.py, both modes through the shared mappers)

1. **`map_bar` and `map_rbar`.**
   - Width = `barwidth()`/`width()` (rbar now reads them, through `_stat_option_float(..., lo=_MIN_BAR_WIDTH)` as `map_bar` does), default 1, in the x variable's Stata units.
   - On a date axis (`self.date_vars[xvar]` plus `_dash_axis_date_kind(fig, "x")`):
     - `td`: w × 86,400,000 ms;
     - `tc`/`tC`: w ms;
     - period kinds (`tw tm tq th ty`): exact per-row edges `L = _dash_units_to_axis(u - w/2)` and `R = _dash_units_to_axis(u + w/2)`, drawn as VBar with internal columns `__dash_bar_xc = (L+R)/2` and `__dash_bar_w = R-L`. Here u is the row's Stata value, from `_dash_date_units`. Months differ in length, so one constant ms width would be wrong.
   - Remove the spacing-derived width. The string-x branch (`_bar_numeric = False`, :10194-10197) is unreachable since GAPS2 G2 (a string x is refused r(109)); it may keep 0.8.
   - The empty-layer path uses the same width (1 or `barwidth()`).
2. **`map_rcap`.**
   - The spine stays a Segment.
   - The two caps become `fig.scatter(marker="dash", angle=0, size=cap_px, line_cap="round")` at (x, y1) and (x, y2), over the same `cap_source`.
   - `cap_px = self.tr.translate_msize(options["msize"])` when given (a bad value goes through the existing `_dash_style_note`); otherwise `self.scheme.default_marker_size(color_idx)`, which is `symbolsize p#` as twoway's default is. When P1.12 lands, it reroutes this through `resolve_size(..., "marker", default)`.
   - `_apply_line_opts` stays on all three renderers.
   - Drop the `_x0_cap`/`_x1_cap` columns and `_tag_spacing`.
   - Return value: `[spine, bot_cap, top_cap]`, with the caps now Scatter.
3. **`map_rcapsym`.** Draw no cap segments. Return `[spine, bot_dot, top_dot]`, and drop the x0/x1 columns and `_tag_spacing`.
4. **Retire the spacing machinery.** Nothing calls `_tag_spacing` after steps 1-3. Remove:
   - `GlyphMapper._tag_spacing` (:10292-10309);
   - the `dash_spacing` block of `_FILTER_JS` (:18737-18778);
   - the `derived_spacing_json`/`derived_spacing_glyphs` args (:19522-19523, :19584-19585, :19647-19648, :32264-32265);
   - `_dash_copy_redraw_geometry` (:24941-24957), its app-name entry (:33332) and its emitted call (:36042).

   A width is now a constant or a per-row column, so a saved filter move (rows kept by id) and a served redraw (data copied) keep it with no recompute. Alternative: leave the machinery inert; not recommended (dead code with tests pinning it).
5. **Optional, not required.** rbar and rcap could now draw from the shared source with a view, so linked brushing reaches them (dash.sthlp:1162 explains why rbar shows no selection today). Leave this to a later item.

### 17b. Default base (after P1.3)

1. **Mark the base column.** `map_bar` (bottom becomes a column `__dash_base`), `map_spike` (`y0`), `map_dropline` (`y0`) and `map_area` (`<y>_base`) write a provisional 0 when `base()` is absent. Each tags its source with `source._dash_auto_base = {"axis": "y"|"y2", "col": <name>}`. An explicit `base(#)` stays a plain value and stays in the scale.
2. **Keep it out of the hull.** P1.3's hull reader (`_dash_axis_hull` and its port `_dash_secondary_values`) skips every auto-base column, so the scale is twoway's `[curmin, curmax]`.
3. **Fill it once the scale is known.** New `_dash_finish_auto_bases(fig)` runs after the axis scale is final. It sets each tagged column to `min(max(0, lo), hi)` for its axis, in axis units: on a date y axis, 0 is `_dash_units_to_axis(0, kind)` (01jan1960), shared with P1.23. Call sites:
   - at build time: at the end of `_dash_finish_count_ticks` (LOW risk; already emitted into the app at :35430), so the CRITICAL `_make_figure_body` is not edited;
   - in the served app: inside P1.3's new `_dash_refinish_axes`, after the live sources are written;
   - on the saved page: in P1.3's `_DASH_AXIS_FINISH_JS`, after the scale is computed and before the ranges are written. It needs a JS list of (source, column, axis).

   A new module function must be added to the app's name list (:33300ff).
4. **by().** Each panel's base follows its panel's scale. A common scale gives a common base.
5. **Fallback if P1.3 is not in WP-30.** Clamp 0 into the hull of the axis's layer data plus the explicit scale values (`_dash_axis_hull`'s explicit list). The JS twin goes in the saved filter callback. This matches twoway whenever the natscale ticks do not reach beyond the data (ypos case), and misses the y12 case (12 vs 10). Document that residual.

## 8. Decisions for the maintainer

- **D1. Bar width default.** Options: adopt twoway's 1 x unit, or keep 0.8 × the smallest gap as a documented divergence.
  - With twoway's rule, yearly or categorical bars touch instead of leaving gaps. Fractional-x data gets overlapping bars, exactly as twoway draws them. Every existing bar/rbar dashboard changes.
  - Recommendation: match twoway, as decision M1 "Match Stata" implies for look. Confirm, since M1 named only the title, ticks, padding, alpha and size units.
- **D2. Default base.** Options: twoway's rule (the axis stops at the data; the bar nearest 0 can have zero height), or keep 0.
  - Recommendation: match twoway, landing after or with P1.3.
  - If P1.3 is not in WP-30, choose between the data-hull fallback (one documented residual) and deferring 17b.
- **D3** (no new decision; note only). twoway accepts `barwidth(0)` and `barwidth(-1)` (rc 0), where dash refuses r(198). This belongs to DROPIN §4 "Refuse vs note". Keep the refusal unless that decision changes.
