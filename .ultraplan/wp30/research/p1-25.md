### 25B: Stata's lookup rule for scheme(), c(scheme) and #include

1. **dash.ado: a new `_dash_scheme_dirs`** returns the ordered, absolute ado-path directories.
   - It reads `c(adopath)`, maps BASE/SITE/PERSONAL/PLUS/OLDPLACE through `c(sysdir_*)`, maps "." to `c(pwd)` and expands `~`.
   - It filters by D1: all directories for (a), or no PLUS/SITE/BASE for (b).
   - `_dash_render_immediate` (:6765-6769) and `_dash_prepare_spec` (:8002-8049) write the list as `build_options.scheme_dirs`, a JSON array escaped through `_dash_json_str`.
2. **dash.ado: the gate** (`_dash_validate_value`, kind `scheme`, :2423-2478).
   - Keep the shipped/theme test. For any other name, first require the name to be a scheme token: `^[A-Za-z0-9_][A-Za-z0-9_-]{0,79}$`, optionally followed by `.scheme`. This keeps refusing separators, `..` and quotes, a deliberate difference from twoway's accepted relative path.
   - Then `capture findfile scheme-NAME.scheme`, and if that fails `capture findfile NAME.scheme` (or `NAME` as written when it ends `.scheme`). That is Stata's own rule.
   - Under D1(b), a hit whose `r(fn)` lies under `c(sysdir_plus)` or `c(sysdir_site)` is refused with its own sentence.
   - The refusal lists the 26 names and the six themes: "scheme() must be one of economist, meta, ... stsj, sttrans, a theme (clean, dark, default, economist, mono, sj), or a scheme file Stata finds on the ado-path (scheme-NAME.scheme or NAME.scheme) (got: X)".
3. **dash_render.py: one resolver.** `SchemeParser._resolve_path(name)` gains the directory list: `SchemeParser(name, ado_dirs=...)`, `resolve_or_fallback(name, context, ado_dirs=...)`, `can_resolve(name, ado_dirs=...)`. A class-wide setter is not used, because P1.4 shares this parser.
   - **Order:** a shipped name (26) or a `.scheme` spelling of one comes first and gives dash's translation (`dash-NAME.scheme` beside the renderer, then the PLUS/d fallback that exists now). BASE is first on twoway's path, so this is twoway's order (flips f, see D3).
   - **The walk:** for each dir in `ado_dirs`, try `dir/scheme-NAME.scheme` and then `dir/s/scheme-NAME.scheme`. Then, for each dir, try `dir/NAME.scheme` and `dir/<first char>/NAME.scheme`, using `_` for a non-letter first character as findfile does.
   - **Guards:** the name token (as in the gate); every dir absolute, an existing directory and realpath-resolved; the candidate's realpath inside that dir's realpath (BUG-51's symlink rule, now per directory); a regular file; and a new size cap, `_MAX_SCHEME_BYTES`, for example 1 MB, checked in `_parse_lines` before `readlines` (there is no cap today).
   - **Without `ado_dirs`** (a hand-built spec or a test), the walk uses only the working directory, plus the `scheme-` form, so the old behaviour is a subset.
   - `_include` / `_resolve_cached` use the same `ado_dirs`, so `#include` resolves exactly as `scheme()` does.
4. **`_resolve_scheme_name`** (:19678) reads `build_options.scheme_dirs` and passes it to `can_resolve`. A session scheme Stata found then resolves, and the warning remains only for a name the walk cannot reach (under D1(b), a PLUS scheme). Its text names the reason: "found by Stata in PLUS, which dash does not read".
   - `DashRenderer.__init__` / `_scheme_for` (:29162, :30140-30156) and `ServerAppBuilder.__init__` (:32829-32832) pass the list through.
   - The served app keeps receiving properties, not paths, so nothing changes at app run time or after a filter move.
5. **Help** (dash.sthlp:705, 3290-3300, 3445-3513, 3570-3597): state the rule as twoway's (`scheme-NAME.scheme`, then `NAME.scheme`, along the ado-path). State D1's PLUS answer, the shipped-name precedence (D3), the 26 names, the token rule (no paths, unlike twoway) and the new refusal text. Remove the "copy it into the working directory" remedy, or correct it to keep the `scheme-` file name.
6. **Records:** a BUGS.md entry per rule 7, written before the fix. CHANGELOG "Results that change": an inherited `c(scheme)` such as stcolor_meta now draws, the six names now draw, and a working-directory `s2color.scheme` no longer overrides (D3).

## 7. Decisions for the maintainer

- **D1: third-party and PLUS schemes** (DROPIN §4; DISCOVERY Q30; GAPS2-X5-b, AUDIT-74).
  - Options:
    - (a) Read along the whole ado-path as twoway does (BASE, SITE, cwd, PERSONAL, PLUS, OLDPLACE and added dirs), with the token, per-dir realpath and size guards.
    - (b) Read cwd, PERSONAL, OLDPLACE and added dirs, but not PLUS or SITE. This keeps WP-05; PLUS schemes are refused when named and warned when inherited.
    - (c) cwd only, adding the `scheme-` form.
  - Implications:
    - (a) matches twoway for every `set scheme` a user can make, including the 129 PLUS schemes on this machine. Fidelity is limited: 88 of the 129 name colour styles dash cannot read, and get 18 warnings each; that is P1.13's area.
    - (a) only reads `.scheme` files Stata itself reads for `set scheme`. WP-05's worry about shared letter directories exposing other packages' files does not arise, because only `scheme-<token>.scheme` and `<token>.scheme` names are reachable.
    - Under (a), Q30's release-gate exclusion can stand: no sweep of PLUS; tests write their own files into a scratch PLUS.
    - (b) leaves sub-claim c open for PLUS-installed schemes such as blindschemes and cleanplots.
    - (c) closes only the copy remedy.
  - **Recommendation: (a).**
- **D2: how to support the six internal StataCorp schemes.**
  - Options: (a) ship translations (26 files) from the extractor; (b) read BASE's raw `scheme-*.scheme` at render time, mapping `#include` to dash's translations.
  - Implications: (a) needs no Stata install path, keeps every colour in hex, and is verified in scratch. It reverses the extractor's "deliberately not translated" note and moves the "twenty" in tests and help to 26. (b) parses StataCorp text and style names (`stc1`, `anglestyle`) and would set off P1.4's unread-directive warnings.
  - **Recommendation: (a).**
- **D3: a working-directory file named like a StataCorp scheme.**
  - Options: (a) match twoway, so the shipped translation always wins; (b) keep dash's documented override.
  - Implications: (a) flips test_scheme_resolution.py:827 and dash.sthlp:3458 and 3582, and changes any dashboard that relies on a local `s2color.scheme`, so it needs a CHANGELOG line. twoway never honours such a file (t1, t3).
  - **Recommendation: (a)**, in line with M1 "Match Stata".
- **D4 (minor): paths in `scheme()`.** twoway accepts `scheme(adod/w30r)` (t3). dash refuses separators. **Recommendation:** keep refusing, as a documented security difference.
