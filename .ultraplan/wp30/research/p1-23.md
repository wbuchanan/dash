## 3. Approach (both modes)

Every helper below is shared: the served app calls the same `_dash_*` functions (emitted calls at dash_render.py:35070-35088, 35171-35206, 35268, 35417, 35476) and the same GlyphMapper methods through `_dash_glyph_dispatch` (:28501). The rule throughout is WP-29's: an axis is a date axis when every layer on it has a date variable of one kind; positions on a date axis are epoch ms of the Stata value (`_dash_units_to_axis`); on a mixed axis they are the Stata values.

### 23a. Date positions on every axis

1. **Axis decision.** `_dash_figure_date_kind(plots, key, fallback, date_vars, axis_no=1)`: count a layer only on its own axis (`options.yaxis`/`xaxis` "2" goes to axis 2); read range keys (yvar1, yvar2 on y; xvar on x) and pc keys (y1var, y2var on y; x1var, x2var on x); skip `_DASH_LITERAL_TYPES`. `_dash_axis_vars` returns yvar1 / y1var / x1var so the tick formatter uses that variable's own format. Callers: `DashRenderer._figure_date_kind` (:30282) and the emitted `_x_date/_y_date` (:35171) and `_rkinds` (:35070).
2. **Second axes.** `_dash_mark_date_axes(fig, x, y, x2=None, y2=None)` also stores `fig._dash_date_kinds2`; `_dash_axis_date_kind(fig, axis)` accepts "x2"/"y2". `_dash_add_secondary_axes` gets the axis-2 kind (axis_no=2) and builds `DatetimeAxis` with `_dash_date_axis_formatter(...)`; `_dash_finish_secondary_axes` passes that kind as `date_kind` (:23313) and converts `range()` values through `_dash_axis_positions`; `_dash_refline_draw` uses the y2/x2 kind for `axis(2)` lines. The served throwaway figure marks all four kinds (`_rkinds`, :35069-35088).
3. **Computed layers on axis 2.** `GlyphMapper._on_axis(fig, values, var, axis, options=None)` uses "y2"/"x2" when the layer's options name axis 2; its 13 callers pass `options`.
4. **Literal layers.** New `GlyphMapper._literal_on_axis(fig, values, axis, options)`: `_dash_units_to_axis(values, kind)` on a date axis, values outside 0100-9999 dropped with one note (`_drop_off_dates`). Used for x and y in map_scatteri, map_pci_literal, map_pcarrowi and map_function (stored points and the fallback grid).
5. **Raw date layers on a mixed axis.** New shared post-draw pass `_dash_dates_in_axis_units(fig, date_vars)`, called in both renderers after the layers are drawn: each coordinate field of a GlyphRenderer that names a date variable on a numeric axis becomes `transform(field, CustomJSTransform(v_func=_DASH_FMT_JS + "...dash_stata_value_of(v, kind)..."))` (fixed code, no user text). The source keeps ms, so filters, brush, embed plan and the served refresh are untouched; Python twin `_dash_date_units` for tests and any Python-side hull. Feasibility measured (tf.py, headless Chrome, Bokeh INLINE): `JS x_range=-764.3..16072.3` (DataRange1d spans the transformed positions); `LinearInterpolator(clip=False)` does not extrapolate (`0.45..12.55`), so it is not usable. Labels: Decision 1.
6. **minmax on a mixed axis.** `_dash_apply_axis_options` reads a date column on a numeric axis as Stata values (`_dash_date_units`); the all-layer hull is P2.20.
7. **base().** map_bar/map_area/map_spike/map_dropline read an explicit `base(#)` on a date value axis as `_dash_units_to_axis(base, kind)`; the default 0 is 01jan1960 (`_dash_units_to_axis(0, kind)` = -315619200000). P1.17's auto-base column then clamps it into the scale (twoway excludes a far base, measured).
8. **Help.** dash.sthlp:2895-2912: literal layers, range/pc layers and second axes on dates; correct the mixed-axis sentence. CHANGELOG "Results that change"; BUGS.md entries.

### 23b. Date and format text in keys and tooltips

1. **Colour key of a date** (`GlyphMapper._apply_colorvar`, :8887; key code :9243, :7859). The mapper stays in ms. Continuous: `ColorBar.ticker = FixedTicker(ms of natscale ticks computed in Stata units)` with `major_label_overrides` in twoway's text (Stata value, comma general format: "15,000"). Binned: `number_text` writes Stata values; `colorcuts()` and `colorlevels` boundaries are taken in Stata units and converted to ms before binning; `zlabel()` ticks likewise (`_dash_apply_z_options`). Decision 2.
2. **Fallback tooltips** (`_dash_build_hover._cell`, :27341): a column that holds a variable's values gets that variable's Stata format through `_dash_fmt_hover(fmt, kind, storage, cache)` (`@{left}{custom}`; on a date axis the column is ms, as the data tooltip already handles). Histogram bins use the histogram variable; fit x/y use xvar/yvar; kdensity's rows are named by its variable and "Density".
3. **Histogram height label** (:27373): `_DASH_HIST_YTITLES[measure]`, read from a private tag `map_histogram` sets on its source; an untagged quad uses "Density" (twoway's default).
