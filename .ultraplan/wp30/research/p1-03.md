## 2. Sub-claims at HEAD

### (a) Every default axis keeps Bokeh's ticker: TRUE, in both modes

Evidence:
- `_dash_apply_axis_options` (dash_render.py:22997) changes the ticker only when `xlabel()`/`ylabel()` gives a rule. Its mode "default" (no rule, or sub-options only such as `ylabel(, grid)`) leaves Bokeh's ticker in place.
- `_dash_count_ticker` (22176) is reached only from `#N` (22793), `xtick(#N)` (22924) and the colour key (26172).
- `_dash_finish_secondary_axes` skips a second axis that has no `ylabel2()`.

### (b) Range padding is Bokeh's 10% (5% a side): TRUE, and wider than stated

Evidence:
- No `range_padding` is set anywhere (grep), so DataRange1d keeps `range_padding=0.1`. BokehJS `_compute_range` spans `(max-min)*(1+0.1)` (bokeh.js:20300-20400), which is 5% a side.
- Axes with an explicit value use `_dash_padded_range` (23489), also 5% of the span.
- An extra divergence: a `#N` axis is pinned at its outermost tick with no margin. `_dash_place_count_ticks` (23419) sets `rng.start = t_lo`. Measured in D01b: y.start = 10.0 exactly and x.end = 5000. twoway places the tick 71 SVG units inside the plot-region edge, at y edge 9.12 and x edge 5050.

Rules these establish:
1. The default axis is `#N` with N = the scheme's `numticks_g horizontal_major`/`vertical_major`, which is 5 in all 20 shipped schemes (resolved through the include chains; `schemekeys.py`).
2. The tick input is the minimum and maximum over every layer's coordinates (fits, CI bands, scatteri, function and bar bases included), not including the bar half-widths.
3. The scale (curmin/curmax) is the hull of those values, every drawn tick and every bar's full width.

dash's `_dash_natscale_ticks` model, on those tick inputs, reproduces 22 of 23 measured default axes exactly. The 23rd, P06 log, is right through `_dash_axis_count_ticks(..., "log")`, which drops the 0. The `%td` model gives P07's quarterly ticks.

The margin was measured from SVG exports with svg_truth (gap between a plot-region edge and the hull, in SVG units):
```
P01 stcolor 5400x3240: 71.4/71.2 px each side (y and x) = 0.0220 of min(W,H)
P02 s2color 3960x2880: 63.3 px = 0.0220     P13 xsize(4) ysize(4): 63.4 = 0.0220
B02 title+legend+note: 71.2 = 0.0220        B03 s2color xsize(10) ysize(3) 7200x2160: 47.5 = 0.0220
P11 plotregion(margin(zero)): 0             P21 plotregion(margin(large)): 259.2 = 0.0800
B01 by(foreign), panel 1: 60.5 = 0.0187 of min(W,H)  (by() scales it; one case only)
```
The rule is: margin = r × min(canvas W, H), on all four sides, regardless of titles, legend or aspect. Here r is the scheme's `margin plotregion` gsize: medsmall = relative2p2 in 19 schemes, and vsmall = relative0p6 in economist. The economist value comes from its scheme file only. Its SVG has no tick marks to fit, so it is UNMEASURED. Expressed as a share of the inner span, the margin is per-axis and per-aspect: P01 y 2.84% and x 1.54%, P02 y 2.80% and x 1.90%. dash uses 5% of the span on both axes.

UNCLEAR or unmeasured:
- The by() margin rule beyond one 2-panel case.
- Stata 14-18 (only `/usr/local/bin/stata-mp`, 19.5, may be run). Measuring them would mean rerunning the new extractor under each `/Applications/Stata */.../stata-mp` binary, once the maintainer allows it.
- Windows and Linux. natscale is compiled and probably platform-independent, but this is unmeasurable here.

## 4. Proposed approach (both modes, before and after a filter move)

Reuse the tested `#N` machinery. Every continuous axis without a rule becomes an implicit `#N` with the scheme's N. Then give every axis twoway's extent and margin, and re-finish after each move in both modes.

A1. Default ticks.
- In `_dash_apply_axis_options` (mode "default" on a continuous, non-categorical axis), set a placeholder from a new `_dash_default_ticker(n)`. It carries the same count tag plus a "default" marker. Do not change `_dash_count_ticker`'s signature: the colour key uses it (CRITICAL).
- Do the same in `_dash_finish_secondary_axes` for y2/x2 with no `label2`.
- `_dash_finish_count_ticks` and `_dash_common_count_ticks` then place natscale, the log rule or tsnatscale exactly as for `#N`, by() common ticks included.
- Read N from new scheme keys: `numticks_g horizontal_major` and `vertical_major`, and `margin plotregion` as a relative number. Add them through `scripts/extract_scheme_truth.py` to the 20 `dash-*.scheme` files and `SchemeParser` (defaults 5 and 0.022).

A2. Every layer counts.
- `_dash_limit_ranges_to_primary` and `_dash_keep_primary_ranges` stop dropping computed layers from the scale (c15, P03, P14, P20, P05, Q04). Swatches and colour keys stay out.
- `_dash_count_axes` already pools every renderer on y. On x it must stop using the primary-limited `rng.renderers` pool (its comment about the 10% fit grid is stale since `_FIT_GRID`).
- Date axes: a scatteri, pci or function layer on a date axis is still drawn at raw SIF values (P1.23). Until P1.23 lands, exclude such layers from a date-axis hull, or the axis spans back to 1970.

A3. Extent and margin.
- `_dash_axis_hull` always returns a hull: drop `if not explicit: return None`. `_dash_hull_ranges` gives every continuous axis a Range1d.
- `_dash_padded_range(lo, hi, kind, reverse, margin=None)` pads by twoway's margin, not 5%. A new `_dash_plot_margin(scheme, graph_opts, aspect)` returns per-side fractions of the frame from r × min(W,H). W and H come from xsize()/ysize() or the scheme's graphsize (decision D1). `plotregion(margin(zero|tiny|...|vlarge|# # # #))` overrides r. A by() panel uses the measured by() factor.
- In data units the pad is f/(1-2f) × span (log10 units on a log axis).
- `_dash_place_count_ticks` stops pinning start and end at the outermost tick.
- `_dash_range_hull` (the inverse used by 10 test and cscript files) follows the new padding.

A4. by().
- `_dash_share_by_scales` (CRITICAL) shares one Range1d per axis over the union hull, as `_dash_common_count_ticks` already does for hull axes. This replaces the BokehJS-shared DataRange1d of WP-29 P0.2.
- yrescale and the other rescale options keep per-panel scales.

A5. After a filter move, served app.
- Add a new `_dash_refinish_axes(figs, rescale)` beside `_dash_finish_count_ticks`, copied into the app.
- `_on_filter_change` calls it after it has written the sources. It re-reads each source, re-ticks, re-hulls, re-shares by() panels, and sets `start/end` and `reset_start/reset_end`.

A6. After a filter move, saved page.
- Add a new `_DASH_AXIS_FINISH_JS`, run at the end of `_FILTER_JS` (UNKNOWN impact; 27 test files reference it). It contains:
  - a port of `_dash_natscale_ticks`: about 60 lines of pure arithmetic, with `"%.15g"` written as `Number(v.toPrecision(15))`;
  - the log rule;
  - a coordinate reader over each renderer's current source columns (a port of `_dash_secondary_values`);
  - bar half-widths;
  - the margin rule;
  - the by() union.
- It writes `FixedTicker.ticks`, `Range1d.start/end` and `reset_start/reset_end`. Its args are per-figure axis plans as JSON strings (the `_FILTER_JS` Map rule).
- Computed layers that the saved page leaves frozen (M3 stale cue) are hulled as drawn.

A7. Zoom and pan (decision D3). A CustomJSTicker returns the fixed twoway ticks at the home extent, and natscale over the visible range when zoomed (the same JS port).

B (date axes, `%td` to `%ty`). Default ticks come from the existing `_dash_tsnatscale_ticks` model in both modes at build and in the served re-finish. The saved re-finish needs a JS port of the tsnatscale model: about 350 lines of calendar arithmetic, with parity over the fixture's 12,000 answers.

Docs:
- dash.sthlp "Axis labels": the default is twoway's `#5`; the margin is twoway's; every layer counts; behaviour after a move and on zoom; replace the "5% of that span" text at 2846-2852.
- CHANGELOG: a behaviour change for every dashboard.
- BUGS.md: entries first (rule 7).

## 8. Decisions for the maintainer

- **D1. Margin rule.**
  - (a) twoway's r × min(W,H) applied to the live browser figure. This is exact, but needs the frame size from BokehJS view internals and a resize hook (`inner_width` is set with `no_change`, so `js_on_change` never fires).
  - (b) the same relative margin, converted at build into a per-axis fraction of the frame from the graph's aspect (xsize/ysize or the scheme's graphsize). It is off by a few px when titles shrink the frame or the 560 px height cap widens the figure. It is the same in both modes and needs no internals.
  - (c) keep 5% of the span.
  - Recommend (b). It interacts with P1.12.
- **D2. After a filter move.**
  - (a) default and `#N` axes re-tick and re-range over the kept rows in both modes. This is twoway's answer for the same `if`; today's default axes already follow the data.
  - (b) hold the build-time ticks and extent, as explicit-value axes are documented to do.
  - Recommend (a). Explicit-value axes stay as documented.
- **D3. Zoom.**
  - (a) natscale over the visible range;
  - (b) only the fixed twoway ticks, as `#N` behaves today (a deep zoom shows no labels);
  - (c) Bokeh's ticker when zoomed.
  - Recommend (a).
- **D4.** Every existing dashboard's default axes change (ticks, extent, fits no longer clipped). Accept this as a CHANGELOG behaviour change with no opt-out. Recommend accept.
- **D5.** Default date axes take a model that agrees on 52-66% of `%td`-`%th` ranges (98% on `%ty`). Bokeh's DatetimeTicker missed the one measured case (P07) and the model hit it. Recommend accepting the model, with the floors pinned.

## 9. Effort, risk, split, feasibility

- **Effort XL overall.** DROPIN's M did not account for re-finishing after a move in both modes.
- **Risk red.** It changes every dashboard and five CRITICAL symbols, and replaces WP-29 P0.2's BokehJS-shared range.
- **Split.**
  - **P1.3-A** (L): numeric, log and `%tc` default axes, the second axes, every-layer hull (c15), twoway margin with `plotregion(margin())`, the `#N` margin, by() common Range1d, re-finish after a move (served in Python, saved through the JS natscale port), zoom ticks, docs and tests.
  - **P1.3-B** (L): `%td`-`%ty` default axes, in both modes, after a move (the JS port of the tsnatscale model plus parity tests). It depends on A and on P1.23.
  - A must not be merged without its own after-move re-finish, or the two modes disagree after a move.
- **Feasibility: high here.** StataNow 19.5 (for the truth), node v24 (for parity), headless Chrome (range_probe), and bokeh 3.9 are all available. Stata's Python bokeh (3.8) should get one Chrome run of a saved page as well. Older Stata versions, Windows and Linux are not measurable.
