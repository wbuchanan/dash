## 3. Approach (both modes, before and after a filter move)

### 3.1 One translator, Python only
New pure functions in dash_render.py (no Stata/Mata change is needed: dash.ado passes the text through intact, measured):
- `_dash_graph_text(text) -> (plain, style, font, flags)`: a single left-to-right, iterative (no recursion, no backtracking) scanner over Stata's graph-text grammar as measured: `{bf}`/`{it}` syntax 1 and 2 with innermost-wins and bold/italic exclusive; `{sup}`/`{superscript}`/`{sub}`/`{subscript}`; `{stSans}`/`{stSerif}`/`{stMono}`/`{stSymbol}`; `{fontface "x"}`/`{fontface x}` syntax 3 and 4; `{c #}`, `{c 0x#}`, `{char ...}`, the 78 `{c name}` forms; the 148 `{&name}` symbols; leading/trailing blanks inside the tag allowed (`{ bf:x}`, `{bf :x}`), tag names case-sensitive; anything else (unknown tag, unbalanced brace, `{&alpha;}`) is emitted literally, as SMCL does. Output of `{c -(}` etc. is never re-scanned. Tables live in module constants built from the truth fixture.
  - Whole-string style: if every visible run shares one weight/style (e.g. `{bf:a}{bf:b}`, `{bf}x`), return `style="bold"|"italic"`; if one font tag wraps everything, return `font` = `serif`/`sans-serif`/`monospace` or the sanitised fontface (`[A-Za-z0-9 _-]`, at most 64 chars).
  - Inline mixed style, inline font, or per-line style differences in a multi-line text: drawn in one style; `flags` records it for one note per graph and sink kind (no user text echoed).
  - `{sup:}`/`{sub:}`: Unicode super/subscript when every character of the run has one (digits, `+ - − = ( )`, and `n i` for sup); otherwise drawn level, flagged. (TeX route: see decision D1.)
  - Control characters from `{c 1..31}`/`{c 127..159}` without a cp1252 glyph are dropped; `{c 0}` empties the text (twoway's measured result) or is dropped (D4).
  - Every result passes through `_dash_inert_tex` LAST, so `{c S|}{c S|}x{c S|}{c S|}` or `{c 92}(` cannot assemble a live TeX pair.
  - Linear time: hostile inputs (100,000 `{`, 10,000-deep nesting, 50,000 `{&`) must finish in well under a second.
- `_dash_graph_text_plain(text)`: the characters only (for DOM sinks if D3 says so).
- `_dash_finish_graph_text(models, seen, key)`: one pass over a document's models that rewrites only these (class, property) pairs, and tags each model it rewrote (`dash_graph_text`) so a second call is a no-op:
  `Title.text` (+ `text_font_style`, `text_font`), `Label.text` (+ style, font), `Axis.axis_label` (+ `axis_label_text_font_style`, `axis_label_text_font`), `Axis.major_label_overrides` values, the tick-label `CustomJSTickFormatter.args["labels"]` map (dash tags that formatter in `_dash_apply_axis_spec`), `LegendItem.label` value, `Legend.title`, `ColorBar.title` and its `major_label_overrides` (zlabel text). Per-item style on legend items and tick labels is set on the Legend/Axis only when every item shares it; otherwise flagged. It never touches `GlyphRenderer.name`, `CategoricalColorMapper.factors`, `Select.options` values, sources, Divs or `HoverTool` fields.
  - TeX: because every rewritten string goes through `_dash_inert_tex`, no canvas sink holds a TeX pair, the saved page stops shipping MathJax (back to ~1.30 MB), and the served page draws `\(y\)` literally as twoway does (it still ships MathJax; that is Bokeh's server bundle).

## 5. Decisions for the maintainer

- D1. Inline mixed styles and sup/sub that Unicode cannot express. (a) Unicode only: draw in the run's style, Unicode super/subscripts where they exist, one note otherwise; no MathJax, saved page ~1.3 MB. (b) Generate TeX for canvas sinks: exact raising and inline bold/italic, but +1.79 MB per saved page (measured), MathJax's TeX font instead of the scheme's font for the whole string, a TeX-escaping layer over user text, and legends/tick formatters/mlabels cannot follow.
