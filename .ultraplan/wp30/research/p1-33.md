## 7. Decisions for the maintainer (M3 already decided the policy)
1. **Downloads.** The matrix needs PyPI wheels (about 150-250 MB per venv) and an arm64 Python 3.11.
   - Options: (a) approve the downloads: conda `create -p <scratch> python=3.11` (or python.org universal2), plus pip wheels into scratch venvs; (b) no downloads, and the floor stays 3.13 (M3 cannot be executed); (c) run pytest on the x86_64 3.11 under Rosetta and skip the Stata leg on 3.11.
   - Recommend (a). Option (c) changes architecture and version together, and a 3.11 floor would then be declared without a Stata measurement.
2. **What "passes" means.**
   - Options: (a) pytest strict, with both pin sets on 3.11 and 3.12 (4 runs), plus the release-gate-style Stata leg on each, plus the full cscript suite on the chosen floor Python; (b) pytest only.
   - Recommend (a): the floor is a promise about `dash` in Stata, not only about pytest.
3. **Patch-level floor.**
   - Options: (a) declare 3.11 (minor); (b) declare 3.11.N+, the patch carrying the Windows 0o700 fix.
   - Recommend (a). Note the Windows caveat under P1.34 (deferred), since nothing on Windows can be measured here.
4. **If 3.11 fails but 3.12 passes:** the floor becomes 3.12 per M3. No further decision is needed unless the failure is a small 3.13/3.12-only API, which gets a guard per M3.
