## 2. Method

Every probe is run four ways in one Stata session (`m1.do`-`m4.do`, 136 probes, sysuse auto / sp500; scheme stcolor, Stata's default):

1. `twoway <body>, <opts>` exported to SVG, and its `legend(off)` twin. Keys = bare texts minus twin texts (multiset), titles = the twin's rotated (y, y2 by x position) and flat (x) non-numeric texts, read with `scripts/svg_truth.py`.
2. `dash <body>, <opts> name(id)`, then `dash build, saving(id.html) replace nobrowser` (saved page) and `dash build, saving(id_app.py) server replace` (served app).
3. The saved page's Bokeh JSON and the served app's `make_document` document are read for each figure's left/right/below/above axis labels and Legend items.

Every probe returned rc 0 in all five steps. `j.do`/`k.do` read twoway's own objects (`.Graph.plotregion1.dynamicmv[i].dimtitle x|y`, `.Graph.xaxis1.title.text[1]`) to pin the title rule. The full per-probe table is in the scratch `table.md`; the quoted rows below are from `python3 read.py` (`OUTD=out|out2|out3|out4`).

### 4.2 The default axis title is the first series' label when the last series' label equals it

This is NOT "all layers agree" (GAPS2 A13's plan). twoway titles each axis with its first series' label when the LAST series on that axis has the same label, whatever lies between. Measured by class reads (`k.do`) and SVG (`m4.do`):

- The rule holds per axis: axis 2's title comes from the series on axis 2 (K11 `price, trunk, price` -> `Price`; M06 `price, trunk` -> none; H05 lfitci on axis 2 -> none), and under `by()` (K10 -> `Mileage (mpg)`; G05 -> none).
- The two-series CI layer counts as two series, band first, so a CI fit LAST on an axis always removes that axis's default title.

- Reading `ado/base/p/plotregion.class:396-448` (`dimtitle, clean`) suggests "all agree"; the drawn result does not follow it, so the rule must be pinned by measurement, never by that source.

### 5.1 dash_render.py

1. **New `_dash_layer_series(plot, var_labels=None, default_level=None)`** after `_DASH_CI_TYPES` (:26706): returns `[(y_label, x_label), ...]` per the table of 4.1, through `_dash_var_label`. The function y name comes from a new spec field `yname`, kept only when it matches `[A-Za-z_][A-Za-z0-9_]{0,31}` (ASCII), else `y` (old specs and hand-edited specs).
2. **New `_dash_axis_default_titles(plots, var_labels=None, yaxis=1, xaxis=1)`**: the series of the layers on that axis (option `yaxis`/`xaxis`, default 1), in order; the default is `series[0]` when `series[-1] == series[0]`, else `""`.

5. **`_dash_legend_key`** (:26925) returns `_dash_layer_series(plot, var_labels)[-1][0]`; **`_dash_legend_keys`** (:26998) keys a CI line with `_dash_layer_series(...)[-1][0]` and the band with the series' band text (its level stays `_resolve_level`).
6. **`GlyphMapper.map_scatteri`** (:13714) adds `legend_label="y"` so a scatteri-only graph has a Legend for `_dash_apply_legend` to rebuild (I01, G12, G24). The default legend-visibility rule then decides whether it shows, as for every other type.
