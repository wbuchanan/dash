## 2. twoway's truth (StataNow 19.5)

Dataset (t1): x = 2 5 3 6 1 . 7 4; y = 10 20 . 40 50 45 60 70; y2 = 12 22 32 42 . 47 62 72. SVG paths were read in data units (an.py, through scripts/svg_truth.py). `M` marks a new subpath.

**connect():**
- `scatter y x, c(l)` → `M(2,10)(5,20)(6,40)(1,50)(7,60)(4,70)` plus 6 markers. The SVG is byte-identical to `connected y x` apart from the graph name (diff: only `<desc>`). yxview.class:2085 `_maybe_override_type` turns any scatter given connect() into type connected.
- `line y x, c(J)` → `M(2,10)(5,10)(5,20)(6,20)(6,40)(1,40)…`: flat, then vertical.
- `c(stepstair) sort` → `M(1,50)(1,10)(2,10)(2,70)…`: vertical, then flat.
- `line y x, c(L)` → `M(2,10)(5,20)(6,40) | M(1,50)(7,60) | M(4,70)`. L compares consecutive *drawn* points: a missing-y row is skipped first, so 5→6 joins across x=3.
- Ties join. On x = 1 3 3 2 4 5 6, `c(L)` gives `(1,10)(3,20)(3,30) | (2,40)…`, so L breaks only where x[j+1] < x[j]. The help says ">", but a tie joins.
- `c(i)` and `c(none)` on line draw no path. With legend on, the key keeps its label and has no line sample (t5 c1).
- Unknown name: `c(bogus)`, `c(j)` and `c(Direct)` each print `(note:  named style bogus not found in class connectstyle, default attributes used)`, rc 0, and draw a direct line, on scatter too (t3 c6, c7).
- Spellings, from connectstyle.class `_unabbrev` and measured in t4: `l`/`line`, `d`/`direct`, `c`/`connected` → direct; `L`, `a`/`asc`/`ascending` → ascending; `J`, `s`/`stair`/`stairstep` → stairstep; `u`/`upstairstep`, `step`/`stepstair` → stepstair; `n`/`none`, `i` → none. Case-sensitive.
- Stylelist per y (twoway_yxview_parse.class:758-759 factors Connect per variable):
  - `scatter y y2 x, c(l)` connects y only; missing elements take the default.
  - `c(. l)` connects y2 only.
  - `c(l ..)` connects all three.
  - `c(J =)` gives y J, y2 J, y3 none.
  - `c(l . J)` gives y l, y2 none, y3 J.
- Repeats are rightmost: `c(l) c(J)` draws J; `recast(scatter) recast(area)` draws area.
- Which types draw connect(J) differently (t2 matrix, SVG compared with the type's base):
  - DIFF: scatter, line, connected, lfit, qfit, lfitci, qfitci, lowess, lpoly, lpolyci, fpfit, fpfitci, mspline, mband, kdensity, tsline, rline, rconnected, tsrline, rarea, scatteri, function.
  - The same picture: area, bar, spike, dropline, dot, histogram, rbar, rspike, rcap, rcapsym, rscatter, the pc family, pci and pcarrowi.
  - lpoly is DIFF on auto (t3 c35/c36); the tiny t2 dataset was degenerate for lpoly.
  - lpolyci with c(J) steps both the line and the CI band (t3 c38).
  - rarea with c(J) gives an odd stepped polygon that mixes rows across missing values (t2 t23_o2).

**cmissing():**
- `scatter y x, c(l) cmissing(n)` and `line y x, cmissing(n)` → `M(2,10)(5,20) | M(6,40)(1,50) | M(7,60)(4,70)`. The line breaks at the missing y (row 3) and at the missing x (row 6).
- Under `sort`, the missing-x row sorts last and makes no break (`c(l) cmissing(n) sort` → `M(1,50)(2,10) | M(4,70)(5,20)(6,40)(7,60)`).
- A row an `if` drops makes no break (`if _n != 5`).
- `line y y2 x, cmissing(n)` breaks y only (stylelist); `cmissing(n ..)` breaks all.
- `rline`/`rconnected y y2 x, cmissing(n)`: each bound breaks at its own missing value and at a missing x.
- `area y x, cmissing(n)`: three separate polygons, each closed to the base.
- `rarea y y2 x, cmissing(n)`: polygons only over runs where both bounds and x are present.
- Combined: `cmissing(n) c(J)` steps within each run; `cmissing(n) c(L)` applies both breaks.
- Derived types:
  - lowess and fpfit break at the x of a row whose y is missing (t2 t13_o5, t16_o5).
  - function bridges by default: `function y=sqrt(x^2-1), range(-2 2)` is one subpath, `(-1.01,0.14)` joined straight to `(1.01,0.14)`. With cmissing(n) it is two subpaths (t3 c33/c34).
- Accepted values (yesno.class `_unabbrev`): y, yes, on, t(rue) and n, no, off, f(alse).
- An unknown value is accepted with nodraw (rc 0, notes) but refused once drawn. `line y x, cmissing(x)` prints `(note:  named style x not found in class yesno…)`, `(note:  yesno not found in scheme…)` and ` not allowed`, then r(101). `cmissing(N)` does the same.
- Spellings: `cmiss(n)` and `cmissings(n)` are accepted; `cm(n)` gives `option cm() not allowed`, r(198).

**recast()** (twoway_yxview_parse.class:143, :153, :246-247: RECASTas sets `type`):
- Within its group, recast swaps the whole look:
  - `scatter y x, recast(line)` ≡ `line y x`;
  - `line y x, recast(scatter)` ≡ `scatter y x`;
  - `scatter y x, recast(connected)` ≡ `connected y x` (full SVG equality).
- Derived types are drawn as the target:
  - `kdensity x, recast(area)` is an area polygon;
  - `function y=x^2, recast(area)` is an area;
  - `lfit y x, recast(scatter)` gives 3 markers;
  - `histogram x, recast(line)` is a line through the bar heights;
  - `histogram x, recast(scatter)` gives markers;
  - `lfit y x, c(J)` steps.
- Range types within their group: `rarea …, recast(rline)` gives two lines; `rspike …, recast(rcap)` gives caps.
- Out-of-group or unknown names print `(note:  named style rline not found in class yxtype, default attributes used)` and `(note:  yxtype not found in scheme…)`, rc 0, and fall back as follows:
  - a yx type falls back to scatter (`line … recast(rline)` ≡ `line … recast(scatter)`);
  - a range type falls back to rspike (`rline … recast(pcspike)` ≡ the rspike base);
  - a pc type falls back to pcspike;
  - function draws its base line;
  - dot ignores recast entirely (all 10 targets give the dot base).
- A range type cast to a yx name draws the first bound against x (`rline y y2 x, recast(line)` is one path of y). `histogram x, recast(rline)` draws two lines, the heights and 0.
- Spellings (class `_unabbrev`):
  - yx: sc…scatter, li…line, co…connected, b…bar; other names exact;
  - range: rsc…, rli…, rco…;
  - pc: pcar, pcbar, pcl, pcsp, pccaps, pcsc.
- `recastas()` and `type()` are synonyms.
- The ci types refuse recast: `recastas() option not allowed`, r(198).
- tsline: `tsline y, recast(connected)` adds markers in time order; `tsrline y y2, recast(rarea)` gives a time-order polygon.

**Style chain.** Under stcolor, line, connected, `scatter c(l)`, `scatter recast(line)` and `line recast(connected)` all draw stroke-width 9.72 #1A85FF (t3 c1-c5). scatter-with-connect is the connected type, so it takes map_connected's chain.

## 3. Approach

Split into two plan sections; both depend on P1.1's per-y stylelist splitter.

### 3A. connect() and cmissing() (P1.8a)

dash.ado:
1. Add a new sclass helper, `_dash_connect_opt <ptype>`. It is called in `_dash_process_segment` after `_dash_fold_typed` and before `_dash_sort_opt` (:4134-4137). It does three things:
   - Canonicalises each token of `s(connect)` and `s(cmissing)` with the class rules in §2, writing direct/ascending/stairstep/stepstair/none and y/n.
   - Expands `.`, `=` and `..` per y through P1.1's splitter.
   - Prints twoway's own note for an unknown connectstyle and uses direct.
2. Per y, when ptype is scatter and that y's connect token is non-empty, write `"type":"connected"` into that y's plot object (yxview `_maybe_override_type`). This happens in the per-y loop :4355-4365, the block P1.1 also edits. `scatteri` keeps its type and its mapper honours connect.
3. Declare `CMISSings` (so `cmissings()` binds) and keep `Connect`/`CMISSing` rightmost; check that `_dash_opts_repeats` treats them as rightmost (its default).
4. Take connect and cmissing off the pending list on the 22 types in §2 that draw them. On types where twoway draws the same picture (bar, spike, …), stay silent, following the bare-`sort` precedent at :1774-1785. On area and rarea, keep cmissing(n) named unless D3 decides otherwise.
5. Handle an unknown cmissing value per decision D2.

dash_render.py (GlyphMapper, copied into the served app by `inspect.getsource`, so both modes follow):
1. Add a new `GlyphMapper._dash_join_glyph(fig, src, x, y, connect, **kw)`. It draws through one helper:
   - Line for direct and ascending;
   - `fig.step(mode="after")` for stairstep and `mode="before"` for stepstair;
   - nothing visible for none, but still a legend item with no sample (line_alpha 0).

   BokehJS 3.8 StepView breaks at non-finite points, as Line does.
2. map_line (:9880) keeps its join order (`_join_order`, unchanged). Under cmissing n it keeps rows whose y or x is missing (in join order) as NaN rows instead of `dropna` (:9937). Under ascending it inserts a NaN break row between j and j+1 where x[j+1] < x[j]. Use one pure helper, `_dash_join_breaks(df, x, y, cmissing, ascending)`, which the served redraw reuses automatically.
3. map_connected, map_rline, map_rconnected, map_tsline, map_tsrline and map_scatteri forward connect/cmissing. The fits (map_lfit, map_qfit, map_lowess, map_lpoly, map_fpfit, map_mspline, map_mband, map_kdensity, map_function and the ci fit lines) draw through `_dash_join_glyph`. The ci band uses `varea_step` under stairstep (lpolyci truth c38).
4. map_function: by default drop NaN points (bridge); keep them under cmissing(n). This is the regression fix for 1d.
5. Saved page (`_FILTER_JS` :18562, derived loop :18755-18782). The snapshot turns NaN into null (`_dash_json_value` :17256-17276), and JS `null*k+b` is finite, so a null y after a filter move would be drawn at 0, not as a break. Add a per-derived-source `derived_breaks_json`, parallel to `derived_spacing_json` and built beside it in `_build_filter_widgets` (:32195-32218), naming the x and y columns and the ascending flag. After a move the JS:
   - writes NaN for null in those columns;
   - drops the synthetic break rows, whose ROW_ID is null, so the keep set never matches them;
   - re-inserts ascending breaks with the same rule as `_dash_join_breaks`.

   The served redraw (`_dash_redraw_for`) reruns the mapper, so it needs nothing extra.
6. Help: rewrite dash.sthlp:3728-3735 and the `{ul:Join order}` paragraph to state the rules in §2. Update GAPS2 A4/B12/G15, TWOWAY_COVERAGE_AUDIT, ROADMAP and CHANGELOG, and add BUGS entries for "scatter c(l) draws no line" and "function draws a gap where twoway bridges".

### 3B. recast() (P1.8b)

dash.ado:
1. Add a new `_dash_recast_opt <ptype>`. It runs after the option parse and repeat reduction, before `_dash_fold_bw`/`_dash_validate_opts`/`_dash_fold_typed`/`_dash_sort_opt` (:4088-4137), and also reads `recastas()` and `type()`. It:
   - Canonicalises the target with the class `_unabbrev` rules.
   - Picks the outcome for each kind of plot type:
     - **Base yx types** (scatter, line, connected, area, bar, spike, dropline) and **range base types**: rewrite `ptype` to the target, so every later step sees it. Varlist families match within a group.
     - **dot**: ignore recast.
     - **Out-of-group or unknown targets**: twoway's note, then the fallback (scatter, rspike or pcspike).
     - **Range type cast to a yx name**: draw the first bound against x.
     - **Derived types** (lfit, qfit, lowess, lpoly, fpfit, mspline, mband, kdensity, function, histogram) and **tsline/tsrline/scatteri/pci/pcarrowi**: keep the type and write `"recast":"<canonical>"` in options.
     - **ci types**: refuse with `recastas() option not allowed`, r(198), per D2.
2. Remove recast from the pending list where it is honoured.

dash_render.py:
1. Add a new `GlyphMapper._dash_draw_xy_as(fig, src, xcol, ycol, target, options, color_idx, legend)`. It draws a derived points source as scatter, line, connected, area, bar, spike, dropline or dot, using that type's scheme chain (default_color/plot_line_width/default_alpha kinds) and the shared `_dash_join_glyph`.
2. Each derived mapper ends in this helper when options.recast is set. The JS recompute of kdensity and histogram writes the same column names (`kd_source` x/y, the histogram's heights), so the agg registry works whatever the glyph. Check that the stale cue (WP-29 M3) still covers a recast fit.
3. `_dash_glyph_dispatch` (:28517) is unchanged for base types, because ptype was rewritten in Stata.
4. Leave histogram → range targets named, as a residual.

## 5. Decisions for the maintainer

- **D1. recast() fallbacks.**
  - Option (a): mimic twoway's measured fallbacks (yx → scatter, range → rspike, pc → pcspike, function and dot ignore) with twoway's note.
  - Option (b): honour within-group recasts only and name the rest.

  Recommend (a). It is cheap, because it is a ptype rewrite at parse.
- **D2. Refuse or note** (ties to DROPIN §4 "Refuse vs note"). Three cases:
  - `recast()` on lfitci/qfitci/lpolyci/fpfitci: twoway gives r(198) `recastas() option not allowed`.
  - An unknown `cmissing()` value: twoway gives r(101) when drawn, rc 0 under nodraw.
  - An unknown `connect()` name: twoway notes it and draws direct, so dash does the same; no decision is needed here.

  Recommend refusing the first two with twoway's rc and message.
- **D3. area/rarea cmissing(n) and rarea connect().** BokehJS 3.8 VArea ignores NaN (it does not break), so separate polygons need a Patches glyph rebuilt in the filter JS.
  - Option (a): implement it.
  - Option (b): keep these named and file a P2 residual.

  Recommend (b). The usage is rare.
- **D4. Function default bridge.** Matching twoway changes existing function dashboards that have interior missing regions: a gap becomes a straight segment. Recommend MATCH twoway, as decision M1 did for join order.
- **D5. Silent vs named** on types where twoway accepts connect()/cmissing() and draws the same picture (bar, spike, histogram, pc, …). Recommend silent, following the bare-`sort` precedent.

## 6. Effort, risk, split, feasibility

- **Effort:** L overall. DROPIN's M is an underestimate.
  - 3A is M-L: ado parse plus 12 mappers through one helper, plus a `_FILTER_JS` change.
  - 3B is L: ado resolution plus about 10 derived mappers through a draw-as helper, plus agg recompute checks.
- **Risk:** yellow.
  - Default output changes only for function (D4).
  - The `_FILTER_JS` change sits under a CRITICAL caller (`_build_filter_widgets`).
  - The null-vs-NaN pitfall can draw a false vertex at 0 on the saved page.
- **Split:** yes.
  - P1.8a "connect() and cmissing() on the line family and the fits" (with the function bridge fix).
  - P1.8b "recast()".
  - Residuals for P2:
    - area/rarea cmissing(n) (D3);
    - rarea c(J);
    - cmissing(n) at missing points generated by lowess/fpfit/lpoly/mband/mspline;
    - histogram → range targets.
- **Feasibility here:** full. twoway truth comes from the slot runner (done); saved pages run under node (test/js_runner.py); served documents through `ServerAppBuilder` + `Document`.
- **UNCLEAR:**

### C1. 3A.1 runs too late: cl options and sort are decided on `scatter` before the override (gap, measured)
`_dash_connect_opt` is placed after `_dash_fold_typed` (dash.ado:4131-4137). By then three type-keyed steps have already treated a connect-bearing scatter as a plain scatter:
- **`_dash_fold_cl` (dash.ado:1653-1660).** `_dash_fold_bw` calls it before validation, and it clears `clcolor`/`clpattern`/`clwidth` on every type outside `cl_types`, scatter included. twoway honours them once connect() is given:
  - k1 c1: `scatter y x, c(l) clcolor(red)` draws its line `stroke:#FF0000`.
  - k1 case 4: `scatter y x, c(l) clwidth(-1)` is r(198) `gm_linewidth must be between 0.000 and 1.0e+04`.
  - At HEAD dash takes both with rc 0 and names only `connect()`. After 3A as written, the line would draw in the default colour and clwidth(-1) would still be accepted.
  - The help paragraph dash.sthlp:3737-3750 also says these options draw nothing on "every other plot type". That becomes false for scatter + connect().
  - Existing twoway truth `HC2-18m` (test_help_claims_2.cscript:584: `scatter …, connect(l) lwidth(-1)` r(198)) has no dash counterpart.
- **`_dash_fold_typed` (dash.ado:1780-1785).** It names a bare `sort` on scatter, and `sort` is serialised for every type (`_dash_plot_opts_to_json` key list :3150). Once the plot object says `"type":"connected"`, the renderer honours it (`_DASH_JOIN_TYPES` :27616, `_join_order` :10817). The note would then name an option that works, which is the defect test_unsupported_report_is_true.py exists to catch. ### C3. Step glyph has no hit test, so hover is lost on stairsteps (decision missing)
- **What the source shows.** In bokeh 3.9.0, `models/glyphs/step.d.ts` declares no `_hit_point`/`_hit_span`; `line.d.ts` declares both (:16-17). Both modes lose tooltips on `c(J)`/`c(stepstair)` lines that have them today. 3.8's StepView is not checked here.
- **Second problem.** For `c(i)`/`c(none)`, 3A's line_alpha-0 Line still hit-tests. Tooltips would then pop over a line twoway does not draw.
- **New D6 for the maintainer.**

  - Option (b): pre-expanded stair vertices on a Line. Hover works, but `_FILTER_JS` must rebuild the stairs after a move, as it re-inserts ascending breaks.
