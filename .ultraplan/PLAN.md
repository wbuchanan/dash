# dash WP-33..WP-50 -- Technical Plan

> Generated by UltraPlan | 2026-10-20 · Phase 3/6 (Step 3b). For the plain-English requirements see `PRD.md`; the binding manifest, rulings and procedures are `sections/index.md`; the writing standard is `sections/BRIEF.md`.

## Architecture overview

dash is a Stata package: `dash.ado` and `dash_parse.mata` parse twoway syntax in Stata, evaluate qualifiers and export the data and a JSON spec; `dash_render.py` (Bokeh) draws the saved page (standalone HTML whose filter moves run JavaScript twins inside `_FILTER_JS` and `_DASH_AXIS_FINISH_JS`) and writes the served app (`bokeh serve`, which copies the glyph layer's functions by name). Truth comes from Stata itself on this machine (StataNow 19.5 console) through committed `scripts/extract_*_truth.do` fixtures and live `twoway` comparisons in certification scripts. The plan adds: a GAPS4 register with one BUGS entry per audit item; a corpus harness (`scripts/corpus/`) that runs about 620 twoway examples under twoway and dash, exports both as SVG, scores them and writes a README block and a gallery page built by dash; a dash image panel and per-graph frames (the gallery's needs); then sixteen WPs of fixes and documentation, each closed by a full gate; then a test-suite speed WP.

## Tech stack (unchanged for users)

- Stata 19+ (measured on StataNow 19.5 console, macOS arm64); Mata.
- Python 3.11+ with bokeh 3.8/3.9, numpy, pandas (no new user dependency).
- Harness only: headless Chrome over the DevTools protocol (`test/range_probe.py`), node for the page JS (`test/js_runner.py`), the stdlib SVG readers in `scripts/svg_*.py`, numpy+scipy SSIM ([B] §2). Dev/test-only additions are allowed (Q19) but none is planned.
