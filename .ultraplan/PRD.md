# PRD — WP-28: close 22 GAPS2 gaps

> Product requirements for one work package of the `dash` Stata package.
> Generated by UltraPlan, 2026-09-25. All ten sections approved by the maintainer.
> Source of record: `GAPS2.md` (audit of 25 September 2026 at `91d97be`).
> Decisions: `.ultraplan/DISCOVERY.md`. Measurements: `.ultraplan/RESEARCH.md` and `.ultraplan/research/`.
> For the technical plan see `PLAN.md` and `sections/`.

## 1. What we're building

We are closing 22 audited defects in dash, the Stata command that accepts twoway's syntax and draws an interactive HTML dashboard instead of a static graph. Fifteen of the 22 are silently wrong output: the page draws different numbers, text, colours or rows from what twoway draws, returns success and says nothing. The other seven are documented capabilities that fail visibly or drift from twoway. Each fix is proven against Stata itself, through a fixture measured from twoway's own drawing or Stata's own display, and asserted in both renderers: the saved offline page and the served app. The work is one package, WP-28, whose exit is the existing release gate with no open S1 or S2 defect.

| Set | Gaps |
|---|---|
| S1, silently wrong output (15) | B1, B2, B3, B5, B6, B7, C2, D1, E1, E2, F1, G1, K2, X1, X2 |
| S2/S3 (7) | E3, E14, G2, G3, G5, G6, G16 |

## 2. The problem

dash promises that a Stata user can paste a working twoway command and get the same picture and the same numbers. The 25 September audit measured 122 places where it does not. The 22 in scope are the ones that hurt most or share one cause. Axis labels are misread: `xlabel(1 "2019" 2 "2020")` draws six ticks and no text. Scales narrow or invert where twoway only ever widens. Textbox abbreviations such as `c(red)` are drawn as title text. Legend `order()` text lands on the wrong keys. A histogram silently drops its largest observation. A copied third-party scheme loses every colour. KPI cards ignore their format and dates ignore the variable's format everywhere. Dropdown filters rewrite string codes, and `exclude()` leaves cards showing rows from a filter state that no longer exists. `dash serve` reports success when no server ran, and the installer accepts Python and Bokeh versions on which every render fails. An internal column name can overwrite a user's variable; string variables are accepted where twoway refuses them; Unicode names are refused; value labels are never drawn; and the saved page and the served app still present the dashboard differently. None of these warn.

## 3. Who it's for

- **The Stata user pasting twoway syntax.** They expect twoway's numbers, text and colours, and twoway's refusals: r(109) for a string y variable, r(198) for a format the page cannot write.
- **The dashboard viewer**, who may not be the author. They move a filter and expect every card and graph to reflect the widgets as they now stand; they read dates and numbers in the format the author set.
- **The maintainer.** They need each defect closed by a regression test that failed before the fix and passes after, recorded in BUGS.md with the test's name and in ROADMAP.md as WP-28, with the release guard green at every commit.
- **The dash serve operator.** They need a non-zero return code and a message when the port is taken, and an installer that refuses a Python or Bokeh below the floor the suites actually run on.
- **The scheme author.** They expect a scheme file written the way Stata's own schemes are written, with quoted RGB and %opacity, to be read.

## 4. What it does

All 22 are must-have. They are grouped by the component that closes them, which is how the technical plan is cut.

- **Display formats (E1, E3, G6).** Every number and date on a KPI card, dropdown, slider, tooltip, date axis, marker label and CSV is written in the variable's Stata display format or the card's `fmt()`: `%f`, `%g` and `%e` with `c` and the European comma, and every `%t` picture. Floats show as Stata shows them. `%x` and `%H` are refused with r(198).
- **Axis labels and scales (B1, B2, G16).** `xlabel`/`ylabel`/`xtick`/`ytick` read numlists and value `"text"` pairs as Stata does, including multi-line and compound-quoted labels and `#N` followed by a list. Label and tick values widen the axis unless `norescale`; `range()` only widens and `r()` is accepted. `valuelabel` puts value labels at the ticks and `hover()` shows them.
- **Textbox grammar (B3, B6, B7).** Every sub-option abbreviation is honoured or named, never drawn as text; `axis(#)` routes an axis title; `xtitle("")` removes the title; `ytitle2()`/`xtitle2()` are read as textboxes.
- **Legend (B5).** `order()` with text and `-` text-only lines, `label()` by key number, `lastlabel()`.
- **Histogram (C2).** Every observation is counted with Stata's floor-and-clamp rule, in Python and in the page's own JavaScript.
- **Schemes (D1).** Quoted values and %opacity are read; an unreadable directive line is warned once and never stored under a malformed key.
- **Colour by variable (X2).** `colordiscrete` with `colorcuts()` makes the cuts the levels and draws other values gray; cuts below the minimum are dropped; `colorlevels()` and `colorvarminmax` work; `zlabel()`, `ztitle()` and `zscale()` draw on the colour key. The continuous default is unchanged.
- **Filters (E2, X1).** Each graph and card is masked by exactly the filters that do not exclude it, on every move, in both modes. Dropdown values are compared as numbers for numeric columns and as exact text for string columns; 'nan', 'None' and 'NaT' are ordinary strings; `""` is listed blank; numeric missing is not listed.
- **Presentation parity (E14).** The served page gets the viewport tag, dash's 0.15 dimming, rspike/rconnected selection and the 992 px reflow with KPI minimum heights; the saved bs page moves its filter bar below the header.
- **Serve and floor (F1, K2).** `dash serve` returns non-zero with a message when no server ran; `--port` outside 1024-65535 is refused, not clamped; the URL is printed once `/health` answers. The declared floor becomes Python 3.13, Bokeh 3.8, pandas 2.3, numpy 2.3 everywhere, and the generated app imports annotations from `__future__`.
- **Data handling (G1, G2, G3, G5).** A `__dash` prefix is reserved and refused with r(110), with every internal column under it; string plot variables are refused with r(109) as twoway refuses them; the data limit counts what the saved page embeds; Unicode names work in `filter()`, `dash kpi`, `by()`, `hover()` and `colorvar()`.

Should-have and nice-to-have: none, by decision. Deferrals are in section 7.

## 5. How it behaves for the user

Silent when right, loud when refusing. An option dash now honours prints nothing, exactly as twoway prints nothing; only an option dash still cannot draw is named in the note. A refusal names the thing refused and uses twoway's return code and, where twoway has one, twoway's wording. Numbers, text and colours change only where they were wrong, and every such change is listed once in CHANGELOG under "Results that change" with the command, the old value and the new one. The one visible layout change is that a saved `layout(bs)` page moves its filter bar below the header, where the served app and every other layout already put it. Whatever the saved page shows, the served app shows, and the parity corpus proves it.

## 6. What it connects to

- **Stata.** The export gains each variable's storage type; dash.ado expands axis numlists with Stata's own `numlist`; the rules come from Stata's own help and ado files (numlist, axis, textbox, legend, colorvar, histogram, format, scheme grammars), cited in the research report.
- **Bokeh 3.8 and 3.9.** Label-only legend items, `major_label_overrides`, `CustomJSTickFormatter` for date axes and sliders, `CustomJSHover` for tooltips, `Select` widgets carrying numeric values, and `Range1d` extents computed in Python.
- **The saved page's own JavaScript.** A format writer twin, one filter-mask rule with per-target exclusion sets, and the histogram recount; each twin is tested under node against its Python original.
- **The test tooling already in the repo.** The node runner (made stateful for chained moves), the headless Chrome layout runner (skipped where Chrome is absent), the Stata truth-extraction scripts, and the release gate that installs the package into a scratch PLUS and runs every example.

## 7. What it does NOT do

- **C4 and its duplicate E4:** the saved page still does not re-estimate fitted or smoothed lines after a filter move. Nothing is ported to the page's JavaScript on that account.
- **G1 residuals:** the qualifier, by()-order and ustrfix columns are still generated in the user's dataset, so a dataset already at `c(maxvar)` may still fail; and a user variable named like a Bokeh glyph field (`x`, `y`, `top`, `count`, `density` and the like) is still shadowed by the derived value in `hover()` and `mlabel()`. Both are recorded, not fixed.
- **G3:** the export stays JSON; row-drawing layers stay bounded by the limit; the served app still embeds every row, so the relaxed count applies to the saved page only.
- **X2:** the continuous colour default, and `colorrule()`, `colorstart()` and `colorend()`, stay as documented.
- **E1/E3:** `%x` and `%H` formats are refused, not written.
- **E14:** the `filterposition(left)` layout difference found in research is recorded, not fixed.
- **D1:** third-party scheme files are out of scope: dash reads the quoted values Stata's own schemes use, proven with a scheme file the test writes; the locally installed third-party schemes are neither swept nor pinned, and the CMYK, hsv and `colour*#` colour forms stay a separate gap (D7).
- No new plot types and none of the other 100 GAPS2 gaps.
- No commit to main: the merge command is reported at the end.

## 8. How we'll know it works

- Every one of the 22 gaps has a regression test that fails at commit `91d97be` and passes after its fix, asserted in both modes wherever the gap has a page.
- Stata-measured fixtures pin the truth: display outputs (about 200 values across the numeric formats, the European comma and every date kind with default and custom pictures), axis label text and drawn extents (about 20 label and range cases), title, axis-title and legend text from twoway's SVG, histogram counts for nlsw88 ttl_exp `bin(27|51|54|83)` and census pop `bin(75)`, colorvar fill groups on auto and nlsw88, twoway's return code and message for a string variable in every position of all 40 plot types, and Stata's own KPI display strings.
- The full pytest suite is green under both interpreters with no skips; the certification suite passes with no skips; the release gate passes from an installed package with every example at rc 0.
- BUGS.md has no open S1 or S2 entry; 22 closed entries each name their test; WP-28 is marked done with its GAPS2 traceability table; every GAPS2 entry in scope carries a Tracked line naming the commit.
- CHANGELOG lists every changed number, text or picture.

## 9. Release and tracking

- **Branch:** `s3-bugs`, the current branch. The merge command into `main` is reported at the end, never run.
- **Commits:** one per gap, the failing regression test then the fix, with the gap's BUGS.md entry landing closed in that same commit and naming the test. Shared components (the format writer, the SVG truth helper, the stateful node runner, the tracking-test change) land in their own commits first. No AI references in messages.
- **Roadmap:** WP-28 is opened in ROADMAP.md at the start with user stories, business and technical requirements, acceptance criteria and a test plan, and its own GAPS2 traceability table; it is marked done at the end.
- **GAPS2.md** is committed (added to the packaging allowlist) and each closed entry's Tracked line names WP-28, the BUGS.md title and the commit; C4 and the residuals are marked deferred with the reason.
- **Documentation:** each gap updates the dash.sthlp paragraph GAPS2 cites and adds a CHANGELOG line; changed numbers or pictures go under "Results that change" with before and after.
- **Execution:** independent sections run in parallel, one agent per section in its own worktree, merged with `patch -p1`; concurrent Stata runs stay at two or three, each with its own `STATATMP`.
- **Exit:** the full pytest suite under both interpreters, the certification suite, and the WP-27 release gate from an installed package, all green; working tree clean.

## 10. Risks and concerns

1. **The `%w.0g` rule is documented only by examples.** A rule derived from examples could be wrong on values nobody looked at. Mitigation: a Stata-measured fixture of about 200 values pins both the Python and JavaScript writers, and any mismatch fails loudly.
2. **The served `layout(bs)` half-row reflow at 768-991 px** needs per-child CSS on a Bokeh GridBox, which Bokeh does not expose directly. Mitigation: a stylesheet on the grid's children; if Bokeh cannot carry it, the item is recorded as a residual rather than faked.
3. **Widening axis extents** to the hull of data, ticks and `range()` must not fight the count-tick placement, log and date axes, or the by() common scale. Mitigation: the SVG fixture covers a case of each, and the hull runs in the one place that already adjusts ranges after the layers.
4. **Routing `axis(2)` on a title** must happen in Mata before dash.ado merges repeated titles. Mitigation: a Python-side rewrite is the fallback if the Mata change proves fragile.
5. **Many existing tests pin today's wrong behaviour.** Mitigation: each is flipped in the same commit as its fix with the reason in the commit message; none is deleted.
6. **Parallel agents all edit dash_render.py.** Mitigation: sections are cut at function boundaries, batch 1 holds only disjoint regions, and the full suite runs once on the merged tree before any commit.
7. **Many concurrent Stata sessions can drop Stata's Python setting**, turning every Python cscript into a skip. Mitigation: at most three Stata runs at once; check `c(python_exec)` before trusting a run of skips.
