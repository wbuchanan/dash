# dash WP-31 -- Product Requirements Document

> Generated by UltraPlan | 2026-10-10

>
> Written in plain English. It describes WHAT we are building and WHY, not HOW.
> The technical plan is PLAN.md and sections/.

---

## 1. What We're Building

We are finishing dash so that a Stata user can put the word `dash` in front of
any working `twoway` command and get the same picture, the same numbers and the
same refusals, as an interactive web page that works offline or as a live
served app. Work package 31 (WP-31) closes every gap the 10 October 2026 audit
(GAPS3.md) recorded that this machine can close: the plot types dash does not
yet draw (contour, contourline, rpcap, rpspike), the twoway options dash
accepts but does not draw, the values dash wrongly refuses, the places where
its picture differs from Stata's, and the saved page's remaining differences
from the served app. It also adds the dashboard features you asked for: a data
table under any graph, richer filters and KPI cards, more than one link group,
complete exports and accessible pages.

## 2. The Problem

Today a pasted twoway command usually works in dash, but not always the way it
works in Stata. Four plot types are refused outright and two more get an
unhelpful "unrecognised" message. About seventy accepted options are quietly
set aside with a note, a handful are dropped with no note at all, and some
values Stata accepts (a variable in range(), degree above 3, a second y axis
pair, a weight expression) are refused. Arrowheads, dot rows, minor ticks, edge
titles, legend spacing and sizing options draw differently from Stata or not at
all. The offline page cannot refit fitted lines after a filter move and shows a
"frozen" cue instead; the second axis and emptied panels never follow a move. A
user who trusts the drop-in promise finds these out one by one, usually in a
dashboard already shared with someone.

## 3. Who It's For

**The Stata user with an existing twoway command** (primary). They know twoway
well and dash hardly at all. They paste a command from a do-file after `dash`
and expect Stata's picture, numbers, legend and axis titles, and Stata's error
when something is wrong. They judge dash by the first difference they notice.

**The dashboard author** (secondary). They start from dash's own options:
filters, KPI cards, links, tabs, layouts. They want a data table under a graph,
a reset button, more than one group of linked graphs, and an export that shows
the whole dashboard, not just the figures.

**The reader of a shared page** (passive). They open a saved HTML file or a
served link in a browser, often with no Stata. They need every filter and tab
to be reachable from the keyboard, labelled for a screen reader, and readable
in print.

**The maintainer and the coding agents who execute this plan.** They need each
task specified so that it is right the first time: exact files, exact lines,
the Stata truth to compare against, and the test that proves it.

## 4. What It Does

### Must Have
- **Nothing dropped in silence**: arrowhead marker options, rbar's marker-size
  width, dot's recast, and any option a type does not take are drawn or refused
  with Stata's words, never ignored quietly.
- **Values Stata accepts are accepted**: a variable in range(), degree up to 7,
  lowess bandwidths above 1, several labels in one mlabel(), scatteri
  fractions, Stata's level bounds, a second y axis pair, axes 3 to 9, weight
  expressions, operators in option variables.
- **Four more plot types drawn**: rpcap, rpspike, contour and contourline
  (exact up to about 1,000 points, bounded beyond), in both the saved page and
  the served app; sunflower and matamatrix refused by name with advice.
- **Named options drawn**: fit options, kdensity area/boundary, histogram gap,
  function droplines/base, dot rows and dot options, arrowheads with angle and
  barb size, colorvar on every type, weighted marker sizes, jitter on the four
  range types, minor ticks and labels, edge titles, title and legend geometry,
  scale/fxsize/fysize/aspect ratio, line-pattern formulas, the symbol
  remainder, named styles from style files.
- **Refused like twoway**: plot-type abbreviations twoway refuses, options on
  types that do not take them, misplaced date literals.
- **The offline page refits** all eleven fitted and smoothed layers after a
  filter move, and the second axis and emptied panels follow a move in both
  modes.
- **Extended missing values** kept apart; set dp comma honoured; leap seconds
  in %tC.

### Should Have
- **Dashboard additions**: a per-graph data table, multi-select and
  missing-value filters, slider direction, a reset button, KPI weights and
  three more statistics, several link groups, brush as a filter, complete
  PNG/SVG export, a print layout.
- **Accessible pages**: keyboard-reachable widgets, labels on every filter,
  card, tab and figure, contrast checked for every shipped scheme.
- **Honest documents**: help, unsupported list, examples, version headers,
  tracking documents reconciled; README and dash.pkg author lines.

### Nice to Have
- JavaScript error banner on the saved page; environment variable checks;
  served-bundle trimming; session hygiene.

## 5. How It Should Feel

A dash page should look like the Stata graph it came from. Same default
colours, line widths, marker sizes, legend layout and title placement for the
chosen scheme; same axis ticks and labels; same legend keys and axis titles.
Where Bokeh cannot draw exactly what Stata draws (text before a legend symbol,
a line into the margin), the help says so with a measured example, and nothing
is quietly different. Messages sound like Stata: twoway's own words and return
codes where twoway has them, otherwise one plain sentence naming the option and
what dash did instead. The offline page keeps every interactive promise the
served app makes, or shows a visible "frozen" cue where it cannot. Dashboard
extras stay out of the way until asked for: a data table is folded under its
graph until opened. Every control is reachable from the keyboard and named for
a screen reader, and the page prints as it looks.

## 6. What It Connects To

Stata itself, on this machine: every number dash draws is checked against what
Stata's own twoway produces, measured by committed scripts that anyone can
rerun, so nothing in dash is hand-typed truth. Stata's installed help, style and
scheme files, which define the exact options, defaults and geometry dash copies.
Bokeh (versions 3.8 and 3.9) in Python, which draws the figures and ships the
contour engine dash will use, and its JavaScript twin inside the saved page,
which dash extends with its own small routines so the offline page can redraw
after a filter move. A headless Chrome on the maintainer's machine, used only by
the tests, to check what the page really does and to run an accessibility
checker. No new Python packages, no internet access from a saved page, and no
change to how dash is installed (`net install` from GitHub).

## 7. What It Does NOT Do

- It does not certify Linux, Windows, Intel Macs, GUI Stata or Stata before 19,
  and adds no scripted image export command; that platform package stays
  deferred as WP-30 left it.
- It does not draw sunflower or matamatrix plots; both are refused by name
  with advice.
- It does not draw a filled contour exactly for more than about 1,000 distinct
  points; above that it draws on a bounded grid and says so.
- It does not put legend text before the symbol (Bokeh cannot); the help
  records the difference.
- It does not add a licence file, change the version number from 0.1.0, or add
  any Python package.
- It does not split the renderer into modules; that is a follow-up.
- It does not read colour spaces other than RGB and Stata's RGBA form from
  scheme files.
- It does not change how dash is installed or served, and never weakens a
  security guard.

## 8. How We'll Know It Works

- Every in-scope GAPS3 row has a BUGS.md entry that is closed in place by a
  commit, a GAPS3 "Tracked" line naming that entry and commit, and a test that
  fails on the old code and passes on the new.
- Every new number dash draws is compared to a value Stata produced, recorded
  by a committed extract script; no test compares to a hand-typed number.
- Every new or changed drawing is identical in the saved page and the served
  app (the parity guard has an entry for it), and every refit after a filter
  move is checked in both.
- Every pasted twoway command in the test corpus either draws what twoway draws
  or stops with twoway's return code and words.
- After the last batch: the full pytest suite, `make cert` and `make gate` are
  green on this machine; no BUGS.md entry is open at severity S1 or S2; the
  help's unsupported list equals the code's; the examples exercise every drawn
  plot type; an accessibility checker reports no violations on the example
  pages.
- Each batch leaves the tree releasable: the full suite and `make cert` pass at
  every batch end.

## 9. Business Model (release and distribution)

dash is free. It is distributed from GitHub now, where any Stata user installs
it with one `net install` line from the README this plan adds, and it will go to
the SSC archive later, so dash.pkg gains the author and keyword lines SSC needs.
No licence file is written in this plan. The version stays 0.1.0; only the date
in every shipped file and the package's distribution date move when the plan's
last batch lands, so `adoupdate` sees the new build. No paid features, no
accounts, no telemetry: a saved page never calls home, and the served app runs
only on the user's own machine.

## 10. Risks & Concerns

1. **Stata's hidden rules.** Contour's polygon cutting, the dot-row base and
   several refusal messages live in compiled code. Every such item is measured
   with a committed script before it is coded; where a rule cannot be
   recovered, the plan matches the measured outputs and says so.
2. **Many hands in one big file.** The renderer is one 52,000-line file. Three
   agents editing it at once will collide; the plan assigns one owner per batch
   to the hot functions and merges with patches, as WP-30 did.
3. **Changing pictures people already have.** Dot rows, arrowheads, legend
   spacing, minor ticks and size defaults will change existing dashboards. Each
   change is listed in the changelog's "may need your do-files changed" section
   and pinned by a flipped test.
4. **The JavaScript twins.** Eleven estimators and a contouring routine must
   give the same numbers in the browser as in Python. Each is pinned to its
   Python twin on shared data before it ships, and the parity guard gains a move
   entry for each.
5. **Contour cost.** Exact contours are capped at about 1,000 points; beyond
   that the page shows a bounded grid with a cue. A user with a large contour
   will see a difference from Stata, by design.
6. **Browser-only checks.** Accessibility, print and error-banner behaviour can
   only be proven in a browser; those tests need the maintainer's Chrome and run
   in the release tier.
