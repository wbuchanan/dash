## 1. What We're Building

We are closing every shortcoming the drop-in audit of 19 October 2026 found
(`review/DROPIN-AUDIT-19oct2026.md`), so that a Stata user can type `dash`
where they would type `twoway` and get twoway's picture, numbers and refusals.
The work is eighteen work packages:

- WP-33 to WP-49: one for each of the audit's seventeen packages, in the
  maintainer's order. WP-39 was removed (A3), so sixteen of these are used.
  WP-33 comes first; it compares about 620 twoway examples with dash and
  publishes the result as a README gallery and a gallery page built by dash.
- WP-50: speeding up the test suite.

The maintainer's rulings (D40, D41, Q1-Q58, A1-A3) decide whether each item is
fixed, documented or withdrawn.

## 2. The Problem

The audit's verdict was that dash is not yet a drop-in replacement. It found six
problems:

1. The first drawing of very common commands differs from twoway: every
   default histogram's axis, every by() graph's ticks and shared y title, the
   default area outline, range() ticks, aspectratio() with xsize(), ci layers
   with nofit, date axes with a missing end row, and a label rule that writes
   5.551e-17 for 0.
2. Some valid twoway is refused, and some invalid twoway is accepted.
3. A dashboard is not a Stata graph.
4. dash refuses a Python that Stata found by itself.
5. About 50 options are accepted with a note but not drawn.
6. Several help and README sentences are false.

Nothing compares dash with twoway over a broad set of examples, which is why
most of these went unnoticed. Only one of them is tracked in BUGS.md.

## 3. Who It's For

- **The Stata user with an existing twoway command (primary).** They paste a
  command or do-file after `dash` and expect twoway's picture, numbers, legend
  and titles, and twoway's error when something is wrong. They judge dash by
  the first difference they notice.
- **The Stata user evaluating dash (README reader).** They decide whether to
  adopt dash from the gallery. They need honest side-by-side pictures with a
  verdict, captioned in Stata terms.
- **The dashboard author (secondary).** They use dash's own options (filters,
  KPIs, tabs, links). Nothing they rely on may break, and the new image panel
  adds to what they can build.
- **The maintainer and the coding agents.** They need each task exact: files,
  lines, the Stata truth to compare against, and the test that proves it.

## 4. What It Does

One line per work package, in run order.

- **WP-33 (audit P13, verification).** Register every item in GAPS4.md and
  BUGS.md. Remove dash's cell and page-size caps (first batch). Compare the
  twoway examples (help files, g.pdf, `examples/`, the audit's probes; about
  425 after removing duplicates) with dash, using geometry verdicts and an
  image score. Add a dash image panel, and let one build draw several
  datasets. Add a ~20-example certification guard. Close P13's coverage items.
  The gallery itself (dash-built pages, one per plot type, and about 12 pairs
  in the README) is built last, at the final closeout (Phase 4: P4-1, P4-8).
- **WP-34 (P1, default drawing).** Resolve all ten items: the histogram bin
  axis, by()'s x ticks and its painted shared y title, range() ticks,
  aspectratio() with xsize()/ysize() (never a 0 px plot), the area outline, ci
  nofit plot numbers, date axes with missing end rows (time-series operators
  are allowed in twoway; the D41 precondition is met), the zero label written
  0, and Stata's ticks at build. The after-move natscale misses stay open.
- **WP-35 (P11, accepted syntax and refusals, plus P4's remaining items).**
  Accept and refuse as twoway does, with its return code and words. The
  dash-only words are decided per word from the measurements. P4's remaining
  items are covered here: refuse capitalised plot-type names; draw the empty
  graph without axes; accept `(scatter ..) line ..` and an option-less `||`
  inside a group.
- **WP-36 (P2, Python and environment).** Use the Python Stata finds or the
  user sets, with no pre-check. Fix the WebGL items. Keep function points off
  the macro. Document: tested in Chrome on macOS arm64; the lock's coverage;
  the dependencies; the large-data timings.
- **WP-37 (P12, statistical layers).** One zero-observation check that copies
  twoway case by case. Fix the rarea gap outlines and the empty-contour key.
  Draw contours from Stata's own grid where the data is gridded or
  interp(none). Fit lfit on xlog/xtransform(). Correct the help on lpolyci and
  the documented numeric limits.
- **WP-38 (P3, Stata graph integration).** Help notes stating that a dashboard
  is not a Stata graph, with every return-code and message difference listed.
- **WP-39.** Removed (A3); the number stays unused.
- **WP-40 (P5, resource limits).** Document every cap. Count only the rows
  if/in selects when nothing needs every row.
- **WP-41 to WP-45 (P6-P10).** Draw every by(), colorvar, legend/title/text,
  axis and scheme/style/geometry item: Bokeh can draw all of them. Document the
  three residuals (mixed SMCL runs, dates past the browser's range, custom key
  cells without click-to-hide).
- **WP-46 to WP-49 (P14-P17).** recast()/horizontal (RH-8 documented); option
  fidelity (jitter unchanged); help, README and tracker accuracy, including
  removing sunflower and matamatrix() from the help; messages (dash's hint
  lines kept).
- **WP-50 (test suite).** Bring `make test` toward 5 minutes.

## 5. How It Should Feel

- **Using dash:** pasting a twoway command should feel like using twoway. The
  same picture appears on first load, the same errors come with the same
  return codes, and no notes appear where twoway is silent. Where dash still
  differs, the help says so in one line under "Differences from twoway", linked
  to the full note.
- **README gallery:** about 12 side-by-side pairs, twoway's SVG on the left and
  dash's SVG on the right. The command sits beneath each pair as a caption,
  with a verdict (Same, Close or Differs) and a one-line list of the
  differences. Each pair is drawn at the size twoway draws that example, and a
  link goes to the full gallery.
- **Gallery page:** one page built by dash, with tabs by plot type. Each
  example shows its command, twoway's SVG, the live interactive dash graph and
  the verdict.

## 6. What It Connects To

- **Stata on this machine** (StataNow 19.5, console): the truth for every
  comparison. It provides twoway's pictures as SVG, its return codes and
  messages, and its grid for contours.
- **Stata's examples:** the help files, g.pdf and the 21 datasets. The three
  fetched from the internet are kept in a local, untracked cache.
- **Python and Bokeh:** dash uses whichever Python Stata finds or the user
  sets. Bokeh 3.8 and 3.9 are both supported.
- **Headless Chrome:** draws the dash pages for the SVGs and the image score.
  Chrome is the only browser dash is tested in.
- **GitHub:** the README and a `docs/gallery/` folder in the repository.
  Publishing that folder as a website (GitHub Pages) is a step the maintainer
  takes later.
- **No new dependency for dash users.** Developer-only tools are allowed but
  are not expected to be needed.

## 7. What It Does NOT Do

- Not a plot type, gap or test: heatmap, sunflower and matamatrix(). Stata's
  internal class names and types defined by files on the ado-path are out too.
- No work on Stata editions, ever. No platform ports: Windows, Linux, Intel
  macOS and GUI Stata are documented as untested. No browsers other than
  Chrome.
- No Stata graph in memory, graph export, .gph, play() or Graph Editor
  support. These are documented only (P3).
- Kept as they are:
  - jitter's noise (not documented);
  - dash's extra refusal lines;
  - JSON data columns (timings documented);
  - every count cap (documented); the cell and page-size caps are removed (P4-3);
  - the Stata 19 floor;
  - the lock's coverage (documented);
  - version 0.1.0 (only the date moves);
  - the README's drop-in claim.
- Not copied or reproduced: RH-8's broken twoway picture, and Stata's compiled
  round-off (lpolyci at zero df). The after-move natscale misses stay open.
- No custom compiled Bokeh extensions. Drawing uses shipped Bokeh models and
  CustomJS only.

## 8. How We'll Know It Works

- Every one of the 221 live items in GAPS4.md ends Closed, Documented or
  Withdrawn. Each has a BUGS.md entry and a pinning test; a documented item has
  a test that reads its help sentence.
- Each WP closes with `make test-all` green and a ROADMAP line.
- At the final closeout, the corpus is re-run and the gallery regenerated. The
  maintainer signs it off before it is committed.
- The ~20-example certification guard passes on every gate.
- Every regression test was red before its fix.
- No test was deleted to make a change pass.
- Saved and served modes agree (parity guard green).
- No gallery file holds a local path or user name.
- WP-50: `make test` runs in at most 5 minutes, or the plan records the
  measured bottleneck and its fix.

## 9. Business Model (release and distribution)

- dash stays free and is installed from GitHub with `net install`, as today.
- The version stays 0.1.0; each WP closeout moves only the dates.
- The README keeps its drop-in claim, with the gallery as evidence. WP-48
  corrects each false sentence as its owning WP lands.
- The gallery is committed under `docs/gallery/` with no size cap. Turning on
  GitHub Pages is the maintainer's separate step.
- No new dependency for users; the help lists the existing ones.

## 10. Risks & Concerns

1. **Gate time.** Each gate already takes about 40 minutes, and each of about
   16 WPs adds a truth script. Mitigation: each WP's script is created in that
   WP's own first section, blocks are kept small, and WP-50 works on speed.
2. **The gallery feature is new dash code.** The image panel and per-graph
   datasets touch registration, tabs and security (dash accepts no raw user
   markup today). Mitigation: the panel takes only SVG files that dash reads
   and sanitises; CSP and escaping tests.
3. **Shared hot functions.** Many WPs edit the same axis, legend and by() code
   in dash_render.py. Mitigation: an owner table per hot function, cherry-pick
   merges, and one section with JavaScript twins per batch.
4. **Flipping many pinned tests.** About 221 fixes reverse today's pins.
   Mitigation: a flipped test states its reason and is never deleted; every
   fix starts with a failing test.
5. **Corpus verdict noise.** Doubled SVG text, random clip ids, dashed grid
   segments and fonts can flag false differences. Mitigation: normalisation, a
   known-differences ledger, and the maintainer's sign-off.
6. **Scattered-data contours** stay subsampled above 1,000 points; this is
   documented.
