## 1. The item

DROPIN P1.18: `nolabels`, `noticks`, `xscale(off)`, `noline`, axis line colour, width and pattern, `alt` and `titlegap` are not honoured. `angle(rvertical)`, `angle(stacked)` and other anglestyle names are dropped silently. `labcolor`, `tlength`, `tposition` and `add` are not honoured; `add` replaces the default ticks. WP-29 note: `add` on an axis(2)-routed label is named, not drawn.

Sources: GAPS2 B21 (c, e, f), B23 (b to f), D9 (a); REMAINING 09-02 items (the scale list at REMAINING.md:2447, the label list at :2459); AUDIT-28 (Axes row: "alternate-axis suboption absent"). BUGS.md (GAPS.md E3, fixed in WP-14) made these sub-options *named* instead of silent. Nothing in WP-29 changed them except P0.5 (commit 3208b2b), which routes `axis(2)` forms to `ylabel2()`/`yscale2()`. None of the residuals P2.30 to P2.41 concerns axis sub-options.

Three more defects found while measuring (rule 7: each needs its own failing test first):

- **D-1. Two `add`s lose `add` in the Mata merge.** `dash scatter mpg weight, ylabel(25, add) ylabel(35, add) name(g3)` -> spec `"ylabel":"25 35"`. twoway draws `10 20 30 40 25 35` (e13). Cause: `_dash_rep_merge` dash_parse.mata:5736-5743 always drops `add` (`drop = ("add")`).
- **D-2. dash.ado expands an a(b)c rule before the renderer, so the renderer cannot apply twoway's rule-vs-list distinction.** `ylabel(15(10)35, add)` reaches the spec as `"15 25 35, add"`, the same as `ylabel(15 25 35, add)`; twoway draws `15 25 35` for the first and `10 20 30 40 15 25 35` for the second (a01, a02). The same expansion defeats WP-28 B2's "lone a(b)c rule drops norescale" through Stata: `ylabel(0(10)100, norescale)` -> spec `"0 10 20 ... 100, norescale"`, and `_dash_parse_axis_spec` then keeps `norescale=True` (it drops it only for the unexpanded `0(10)100, norescale`). Cause: `_dash_axis_expand` dash.ado:2537-2560. The norescale half is outside P1.18 but uses the same fix.
- **D-3. Sub-options are read from the whole option text, label strings included.** `_dash_parse_axis_spec('10 "angle(45)" 20')` gives angle 0.785; `'10 "nogrid" 20'` turns the grid off. This is the same bug as P2.20's "quoted label text triggers sub-options". Any new key must be read from the tail only.

## 4. Approach (both modes; holds before and after a filter move)

Axis look is set at build in shared helpers. A filter move changes only data and views, so the look holds after a move, provided that P1.3's planned re-finish after a move keeps `_dash_extra_ticks`. Both modes already call the same functions: saved `DashRenderer._make_figure_body` (:30255, :30392, :30405) and the served template in `ServerAppBuilder._generate_app_source` (:35166, :35257, :35268). Any new module helper or table must also be added to the served copy lists in `ServerAppBuilder._glyph_layer_lines` (:32934 tables, :33255 functions).

### A. Sub-option tables and tail-only parsing (dash_render.py)

1. Add `_DASH_AXLABEL_SUBOPTS` and `_DASH_AXSCALE_SUBOPTS` as (full, minimum) tables, transcribed from axis_label_options.sthlp:107-150 and axis_scale_options.sthlp:47-77. Match case-sensitively, lower case only. Use `_TEXTBOX_SUBOPTS` as the model. Include the measured spellings (`notick`, `tick`, `nolab` and `tp(o)` accepted; `nola` refused). Add `_dash_axis_subopt_canon(tok, table)` -> (canonical, value).
2. `_dash_parse_axis_spec`: read every sub-option from the tail tokens only (fixes D-3 for the new keys; coordinate with P2.20 for format/labsize/grid). New keys:
   - `show_labels`: the positive word wins.
   - `show_ticks`: the positive word is assumed to win; measure it in the fixture.
   - `labcolor`, `tlength`, `tposition`.
   - `add`.
   - `angle`, with `angle_bad` for an unknown name.
   The `unsupported` list keeps everything else: labgap, labstyle, tstyle, tl*, gl*, gmin/gmax, alternate, custom (P2.20).
3. `_parse_axis_angle`: use `_dash_anglestyle_degrees` (case-sensitive, -360..360) on the tail's `angle()` only.
   - An unknown name, or (in a hand-written spec) a number out of range: `_dash_style_note("ylabel(angle)", v, "angle", "horizontal")`, and draw **0** explicitly, as twoway does (q11).
4. `add`: if the head starts with explicit values, use mode `count` with N from the scheme's `numticks_g` (5). Through P1.3's `_dash_default_ticker(n)` if that has landed, else `_dash_count_ticker(5)`. The listed values go to `_dash_extra_ticks`, which `_dash_place_count_ticks` already unions in. If the head starts with a rule (`#N`, a(b)c via `_DASH_AXIS_INCR_RE`, `minmax`, `none`), `add` is consumed with no effect.
5. `_dash_apply_axis_spec` applies, after `labsize`:
   - `show_labels=False`: `major_label_text_font_size="0px"`, `major_label_standoff=0`. The label space collapses, as twoway widens the region.
   - `show_ticks=False`: `major_tick_in=major_tick_out=0`.
   - `labcolor`: through P1.13's colour reader (`parse_color_alpha`/`translate_mcolor`) into `major_label_text_color`/`_alpha`. An unknown colour gets a note.
   - `tlength` and `tposition`: `outside` gives out=L; `inside` gives in=L; `crossing` and any unknown value give in=out=L/2, with a note for unknown. L is the size in px, **rounded to int** (the Bokeh props are `Int`; a float raises ValueError and aborts the render) and clamped.
6. Other callers of the parser must name the new keys they do not draw:
   - `_dash_apply_tick_option` (xtick/ytick; its extra-name list at :22905-22910).
   - `_dash_apply_z_options` (zlabel, :26149-26160).
   Otherwise `zlabel(, labcolor(red))` would become silent.

### B. Scale look (dash_render.py)

1. Extend `_dash_scale_name`, `_DASH_SCALE_SUBOPTS` and `_DASH_SCALE2_SUBOPTS` with `off`, `on`, `noline`, `line`, `lcolor`, `lwidth`, `lpattern`, `alt` and `titlegap`. `fill`, `outergap`, `lstyle` and `extend`/`fextend`/`noextend` stay named.
2. `_dash_scale_spec` returns a `look` dict. Resolution: `off` wins over `on`. `noline` wins over `line`, unless an `lcolor` is given (measured f10).
3. New `_dash_apply_axis_look(axis_obj, look)` and `_dash_apply_scale_look(fig, xspec, yspec, by_graph, seen, key)`. Call them in both modes right after `_dash_apply_scale_ranges`, which runs after `SchemeParser.apply_to_figure` in both, so the user's values win.
   - `off`: `axis.visible=False` (the title goes too; grids stay).
   - `noline`: `axis_line_color=None`.
   - `lcolor`, `lwidth`, `lpattern`: `axis_line_color`/`_alpha` (P1.13), `axis_line_width` (`translate_lwidth`, P1.12 D3), `axis_line_dash` (`translate_lpattern`). A note for unknown names, as twoway gives.
   - `titlegap`: `axis_label_standoff` (int px).
   - `alt`: move the primary axis. y: `fig.left` -> `fig.right` at index 0, inside any y2. x: `below` -> `above`.
4. Under `by()`, follow the by() measurements in section 3: skip `off`, `titlegap`, `nolabels` and `noticks`, and keep the rest. Whether to note the skipped ones is decision D1.
5. Secondary axes: `_dash_finish_secondary_axes` applies the same `look` to the y2/x2 axis object. `yscale2(alt)` puts y2 on the left, outside y1. The label sub-options reach `ylabel2()` through the shared parser.

## 8. Decisions for the maintainer

- **D1. by() exceptions.** Under by(), twoway draws `off`, `nolabels`, `noticks` and `titlegap` as if they were absent, with no note (measured c01-c08).
  - (a) Match, silently.
  - (b) Match and note once per graph.
  - (c) Honour them per panel as a dash extension.
  - Recommend (b), consistent with dash.sthlp's "nothing dropped without being named". It falls under §4 "Drew nothing notes where twoway is silent".
- **D2. Size units for `tlength()`/`titlegap()`.** Follow P1.12 D1. twoway's unit is 1% of the graph's smaller side (measured: 32.4 SVG units at 4.5in). Until P1.12 lands, read a number as px as today.
- **D3. Wrong-case and unknown anglestyles.** `angle(Vertical)` draws 90 degrees today; twoway notes it and draws 0. Recommend matching twoway, with a CHANGELOG line. This changes existing dashboards that rely on it.
- **D4. Refuse vs note (existing §4).** twoway refuses `NOLABELS`, `OFF` and `Alt` with r(198) and the bound violations (angle, lwidth). Recommend refusing the bound violations now, as dash already does for mlabangle, and leaving capitalised words to the §4 decision.
