### 2.2 An xlabel()/ylabel() rule keeps the fallback

```
twoway scatter price weight, ylabel(#5)          -> y 0 5,000 10,000 15,000
twoway scatter mpg weight, xlabel(2000(1000)5000) -> x 2,000 3,000 4,000 5,000
twoway scatter mpg weight, xlabel(minmax)        -> x 1,760 4,840
twoway scatter price weight, yscale(log) ylabel(#5) -> y 0 5,000 10,000 15,000
twoway scatter price weight, yscale(log)         -> y 5,000 10,000 15,000
```

On a log axis with ylabel(#5), twoway draws a "0" label at y=-1825.59 in the
3240-unit viewBox (off the canvas), and the visible labels are 5,000 10,000
15,000. The help's claim about the visible labels is therefore true of twoway.
The off-canvas zero and the compressed spacing (5,000 at 524 vs 2068 without
#5) belong to P1.3's tick geometry, not to this item.

### 2.3 The format comes from the axis's serset column, so it depends on the layer type

The rule, read from Stata's own classes, is that an axis takes
`plotregion.dimformat` (axis.class:260-273). That is the format of the first
view's serset variable in that dimension (plotregion.class:549-573,
yxview.class:244-258). xygraph_g.class:134/193 call `scale.setfmt` with
`sers[...].format`. A computed layer's serset holds generated variables, each
with its own format. For example, twoway_histogram_parse.class:135 does
`format %6.4g` on the height, and twoway__histogram_gen.ado:220 copies the
variable's format to the bin mid-points.

| First layer | x labels | y labels | Truth (case) |
|---|---|---|---|
| scatter, line, connected, area, bar, spike, dropline | x var's | y var's | u11, u14, u18, u19, u26, v10 |
| rarea, rbar, rspike, rcap, rcapsym, rline, rconnected, rscatter | x var's | **first y** (yvar1) var's | u12 (price/mpg -> 5,000), u13 (mpg/price -> 5000), v04-v09 |
| pcspike, pcarrow, pcscatter, pccapsym | x1 var's | y1 var's | u16, v11, v12, v18 |
| scatteri, pci, pcarrowi, function | %9.0g | %9.0g | u15, v13, v14, t15 (".2 .4") |
| lfit, qfit, lfitci, qfitci | %9.0g | %9.0g | u01, v01, u04, u22 (x "2000", y "4000") |
| lpoly, lpolyci | %9.0g | %9.0g | u05, v02 |
| kdensity | %9.0g | %9.0g | t14b, u10 (x "0 5000", y ".0001") |

### 2.7 New defect: the narrow explicit-digit %g writer

Stata, via `disp.do` and `disp2.do`, against `dr._dash_fmt(v, f)`:

```
display %6.4g .0001  -> " 1.0e-04"   dash ' .0001'
display %6.4g .00012 -> " 1.2e-04"   dash '.00012'
display %6.4g .00001 -> " 1.0e-05"   dash '  1.e-05'
display %6.4g 12345  -> " 1.2e+04"   dash '  1.e+04'
display %9.4g .00001 -> "   .00001"  dash ' 1.00e-05'
display %8.3g .00001 -> "  .00001"   dash ' 1.0e-05'
28 cases, 6 differ
```

`_dash_g_text` (dash_render.py:20510) and its JavaScript twin
`dash_fmt_g_text` (dash_render.py:17728, inside `_DASH_FMT_JS`) use "exponent
under -4" for an explicit d, whatever the width. Stata's switch depends on the
width too. format_truth.json has %9.4g and %9.2g rows but none of these values.
The defect is not in DROPIN, BUGS or GAPS2. P1.5 needs the fix because the
histogram's y axis is %6.4g: twoway writes 1.0e-04, and dash would write .0001.
The same writer also serves mlabformat(), hover and KPI fmt(), so the fix
reaches those sites too.

## 3. Approach (closes the item in both modes, before and after a move)

All changes are in module-level helpers that the served app copies, so one
change covers both modes.

1. **New helper `_dash_axis_tick_formats(plots, numeric_formats)`** in
   dash_render.py, beside `_dash_axis_vars`. It returns `{"x","y","x2","y2"}`,
   the format twoway labels each axis with (sections 2.3 and 2.4):
   - Each y axis takes the first layer on it.
   - x takes the first layer of the y axis whose first layer comes latest; x2
     and y are symmetric.
   - Per type:
     - Observation, range and pc layers take the format of their first variable
       on that axis (`yvar`, then `yvar1`, then `y1var`; `xvar`, then `x1var`).
     - Literal types and lfit/qfit/lfitci/qfitci/lpoly/lpolyci/kdensity take
       `%9.0g`.
     - lowess and fpfit(ci) take the x variable's format for x and `%9.0g`
       for y.
     - mspline and mband take both variables' formats.
     - histogram takes its variable's format for x and `%6.4g` for y.
   - It returns `""` for a date variable (the date path, E3, already formats
     those) and `%9.0g` for a variable with no usable format.
   - It must be added to the served helper list in `_generate_app_source`
     (dash_render.py:33160-33170).
2. **`_dash_apply_axis_options`** gains `plots=None`. With no `raw`, a non-date
   axis gets `_dash_fmt_tick_formatter(fallback, "", "", fmt_cache)`. With
   `raw`, the fallback passed is the helper's rather than
   `numeric_formats.get(var)`. Callers: `_make_figure_body`
   (dash_render.py:30405) and the served template string (35268). Both add
   `plots=plots`.
3. **`_dash_apply_axis_spec`** changes:
   - It gains `date_kind=None`.
   - The format branch becomes: for kind f, g or e, and for kind t whenever
     `spec["format"]` is given, use
     `_dash_fmt_tick_formatter(fmt, date_kind or "", "", fmt_cache)`. On a date
     axis the JavaScript turns the epoch-ms tick back into the variable's Stata
     value (`dash_stata_value_of`), and the format writes it as twoway does
     (section 2.5).
   - The fallback applies to every numeric kind, not only %f.
   - A %s format writes `%9.0g`. twoway accepts %s silently, and its text is
     not exactly %9.0g (1.200e+08 vs 1.20e+08), so the note stays, reworded to
     "written in %9.0g". %x and %H keep their note.
   - When explicit text labels exist, use a labels-plus-format formatter (a new
     `_dash_fmt_label_tick_formatter(labels, fmt, kind, storage)`) instead of
     the bare `String(tick)` one. An unlabelled tick in `xlabel(2000 "two"
     3000)` then reads 3,000. `args["labels"]` is kept, which four existing
     tests and the XSS guard read: test_axis_label_grammar.py:368,
     test_adversarial_matrix.py:1677, test_served_dates.py:574 and
     test_graph_options.py:375. The label text stays in args and out of the
     code.
   - `_dash_apply_axis_options` passes `kind` (it already computes it at
     dash_render.py:23013).
4. **`_dash_finish_secondary_axes`** gains `numeric_formats=None`. The y2/x2
   fallback comes from the helper, and an axis with no ylabel2() also gets it
   (u17, u35). Callers: dash_render.py:30660 and template 35417. A date
   variable on axis 2 is P1.23's and is left alone.
5. **Writer fix (section 2.7):** fix `_dash_g_text` and `dash_fmt_g_text` for
   explicit d at narrow widths. First add Stata truth rows to
   format_truth.json for %6.4g, %8.3g and %9.4g over .00001-.1 and
   1e3-1e6.
6. **Help:**
   - dash.sthlp:2879-2883 becomes: "A numeric axis's ticks are written in the
     display format of the variable twoway takes it from: the first layer on
     that axis (a computed layer's own %9.0g; a histogram's height %6.4g)…;
     format() writes the axis variable's stored value: format(%9.0fc) on a
     %td axis writes 14,976, format(%tdDD/NN/CCYY) writes 01/01/2001,
     format(%td) on a numeric axis writes dates."
   - The log example at 2865-2866 then becomes true.
   - Add a sentence on %s/%x/bogus.
7. **Effect on every dashboard:** every numeric axis changes from Bokeh's
   text to Stata's. For example "0.2" becomes ".2", "2000" becomes "2,000",
   and "1e+7" becomes "1.00e+07". Each distinct (format, kind, storage)
   triple adds one formatter model of 33,408 characters of JavaScript
   (measured `len(dr._DASH_FMT_JS)`) to the page. auto's mpg, weight and price
   need about two or three models, so roughly +70-100 KB on a 1.30 MB page
   (p_default.html 1,301,182 bytes). Hover already carries the same body per
   format. See Decisions.

### Corrections

1. **The writer defect (2.7) is broader than the "exponent under -4" switch.**
   crit5.do compared 32 `display` rows: 30 differ. There are three faults:
   - **Mantissa decimals at narrow widths.** `_dash_sci_decimals`
     (dash_render.py:20380) and its JS twin `dash_fmt_sci_decimals`
     (17669) floor an explicit d at 0 decimals, but Stata keeps one:
     `%6.2e 12345` is 1.2e+04 (dash `1.e+04`), and `%6.4g .00001` is
     1.0e-05 (dash `1.e-05`). This hits **%e too**: all 12 narrow %e rows
     differ (%6.2e, %5.1e, %6.3e).
   - **The fixed/scientific switch for explicit-d %g depends on width.**
     `%6.4g .000123` is 1.2e-04 (dash .000123).
   - **Fixed digits are capped by the width.** `%7.4g .000123` is .00012
     (dash .000123).

   So the fix also edits `_dash_sci_decimals` and `dash_fmt_sci_decimals`.
   Their callers are `_dash_f_sci_fallback` (20472), `_dash_fmt_number` and
   `_dash_g_text`. The fix changes %e and %f-fallback text at every site:
   KPI fmt(), mlabformat(), hover and axis format(). The truth rows must
   cover narrow %e, %g and the %f fallback.
