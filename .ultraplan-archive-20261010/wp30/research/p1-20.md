### 3.4 Bokeh feasibility (bokeh 3.9.0 here; floor 3.8)

- `Plot.border_line_color/width/dash/alpha` exist in 3.8.0 (`/opt/anaconda3` bokeh 3.8.0:
  `'border_line_color' in Plot.properties() -> True`, plots.py:723) and 3.9.0. Rendered in the
  Browser pane: a red 4px line round the whole canvas. GAPS2-B18's "no border line around the whole
  canvas" is out of date: graphregion `lcolor`/`lwidth`/`lpattern` map natively.
- BokehJS `_paint_empty` fills the border with an even-odd clip that excludes the frame, so
  `background_fill_color=None` shows the page, not the graph colour (rendered: white frame on a
  `#eaf2f3` border). `fcolor(none)` must therefore paint the frame with the graph region's colour.
- `BoxAnnotation(left=Node(target="frame", symbol="left", offset=15), ..., level="underlay")`
  renders an inset box under the glyphs, inside the frame: the plot region's inner box is drawable.
  The same box on `Node(target="canvas", ...)` is clipped to the frame (only its right edge showed), so
  the graph region's inner box is not.
- `min_border_left=80` moves the frame to 80px but is a minimum, not added to the axis's own space; CSS
  `styles={"padding-left": ...}` overflows the stretched canvas; a blank spacer `Title` takes no
  space. There is no exact additive outer margin.

## 5. Approach

Split in two plan sections. Both modes run one shared helper, as `_dash_reference_lines` does.

### Section A: region styling, colours and notes (closes B18-b..f, AUDIT-66 styling half)

1. `_DASH_REGION_SUBOPTS` (dash_render.py, new): canonical name -> minimum abbreviation, from
   region_options.sthlp and 3.1: style 3, color 1, fcolor 2, lstyle 2, lcolor 2, lwidth 2, lpattern 2,
   lalign 2, istyle 4, icolor 2, ifcolor 3, ilstyle 3, ilcolor 3, ilwidth 3, ilpattern 3, ilalign 3,
   margin 1. `_dash_region_canon(name)` -> canonical or None (prefix of the full name, at least the
   minimum).
2. `_dash_region_spec(raw, option, seen, key)` (new): split with `_dash_by_tokens`, canonicalise, and
   resolve one copy's effects with twoway's measured precedence: style -> lstyle -> fcolor/lcolor/
   lwidth/lpattern -> color (outline) and fcolor after color (fill). Colours through
   `_dash_unquoted` + `OptionTranslator._means_no_color` + `parse_color_alpha` (fill/line colour,
   alpha; `none` = not drawn). `style(none)`/`istyle(none)` clear fill and line; `lstyle(none)` clears
   the line colour (a later `lcolor()`/`color()` revives it, `lwidth()` alone does not). Widths via
   `translate_lwidth`, patterns via `translate_lpattern`; a bad value keeps today's
   `_dash_style_note`. Unhonoured tokens (`lalign`, `ilalign`, named areastyles/linestyles other than
   `none`, graphregion `i*`, unknown names) go to `_dash_report_suboptions(option, bad, seen, key)`,
   once per graph (by() panels share `seen`).
3. `_dash_apply_regions(fig, graph_opts, seen, key, scheme)` (new), called from `_make_figure_body`
   (replacing :30350-30379) and from the `_generate_app_source` template (replacing :35231-35256), and
   added to the app's copy list (:33385-33392):
   - plot region: `background_fill_color/alpha`; fill `none` -> the effective graph region colour
     (3.4); `outline_line_color/alpha/width/dash`.
   - graph region: `border_fill_color/alpha`; fill `none` -> the scheme's `color background`;
     `border_line_color/alpha/width/dash` (Bokeh >= 3.8).
   - `bgcolor(none)`/`plotbgcolor(none)`: `none` handled in `_dash_graph_color` (keep the scheme's
     colour, as twoway shows no change), never `#000000`.
   - Delete `_extract_region_color/_lcolor/_lwidth` (update test/function_test_map.py,
     test_help_claims_7 `TestTheNewHelpers`).
4. Mata (dash_parse.mata): `_dash_rep_subkey` canonicalises region sub-option names when the option is
   plotregion/graphregion (needs the key: pass it from `_dash_rep_merge` -> `_dash_rep_subs`), so the
   later copy wins per setting; for those keys keep every `margin()` copy in order (twoway
   accumulates); when a later copy sets `lcolor()` (or `fcolor()`), rewrite an earlier copy's
   `color(x)` to `fcolor(x)` (or `lcolor(x)`) so the renderer's within-copy precedence cannot revive it.
   Pin the exact rules with the truth fixture before coding.
5. Refusals: `plotregion(bogus(1))` and a sub-option repeated inside one copy follow the §4
   "Refuse vs note" decision; until it is taken, name them (the renderer) as every other sub-option.
6. Help (dash.sthlp Region Styling Options, Unsupported list, :3608): full sub-option table with
   abbreviations, `none`, `%NN`, `color()` = fill and outline, the graph outline, what is named;
   help-conformance tests updated.

### Section B: margins and the plot region's inner box (closes B18-a, AUDIT-66 "margins")

## 8. Decisions for the maintainer

- D1 Refuse vs note (existing §4): twoway refuses `region(bogus(1))` and a sub-option given twice in

- D2 `graphregion(margin())`: (a) name it, not drawn; (b) approximate with `min_border_<side>`

  `margin` plus a styled container). Recommendation: (a) in WP-30, (c) filed as P2.
- D3 graphregion `i*` (inner graph region): Bokeh boxes clip to the frame. (a) name and re-disposition
  (Stata's own manual calls `ifcolor` "of little use"); (b) CSS overlay. Recommendation: (a).
- D4 `plotregion(margin())` exactness: (a) static per-side padding fraction (exact for `zero`, approx.
  otherwise, responsive-scale invariant); (b) exact pixels via a JS layout callback in both modes
  (interacts with zoom/reset and served range updates). Recommendation: decide with P1.3; (a).
- D5 `lalign()`/`ilalign()`: join the §4 stroke-alignment re-disposition (accept and report).
- D6 by(): match twoway (outer `graphregion()` invisible on a by() graph; honour
  `by(..., graphregion() plotregion())`) here or in P1.15. Recommendation: P1.15.
