### M4. Edge truths (t4-t9)

- **Both flags.** `twoway bar mpg weight, horizontal vertical` (either order): "may not combine options horizontal and vertical", r(198). dash: rc 0, both named (t8: `GLB|dash hv|rc=0`).
- **Abbreviations.** `hor` and `vert` are the minimums (`ho`, `ver`: "option ho not allowed", r(198)). These match dash.ado:953 `HORizontal VERTical`. dash notes `ho()` under its unknown-option policy.
- **Graph-level placement.** `twoway (bar mpg weight), horizontal`: "option horizontal not allowed", r(198). dash refuses it the same way (t8). `twoway bar .. || bar .., horizontal`: rc 0, so it binds to the last plot.
- **`recast(bar)`.** `twoway scatter mpg weight, recast(bar) horizontal`: rc 0, so acceptance follows the recast type (couples to P1.8).
- **`by()`.** `bar ..., horizontal by(foreign)` and `histogram mpg, horizontal by(foreign)`: rc 0.
- **Date variable.** `(bar y d, horizontal)` with d %td: the y axis is labelled 01feb2020..01jun2020 and titled "Day"; the x axis is "Yvar". `(rcap lo hi d, horizontal)`: y is dates, x is "Lo/Hi". So the date axis follows the layer to y.
- **`yaxis(2)` is physical.** `(scatter y x) (bar y x, horizontal yaxis(2))`: the right axis has 1..5 titled "Xvar" (the bar's x), the left 10..50 titled "Yvar". The horizontal layer's x goes on y axis 2, and its y joins the shared x axis.
- **Marker labels keep their physical clock position** (t6, label positions in data units):

  ```
  dropline v:  A at (1.025, 9.752)   [3 o'clock]   dropline h: A at (10.251, 0.975) [3 o'clock]
  bar v:       A at (1.0, 10.371) middle [12]      bar h:      A at (10.0, 1.056) middle [12]
  ```

  The anchor point is transposed; the screen offset is not.
- **t-axis options stay physical** (t9): `twoway tsrline lo hi, horizontal tlabel(2 4)` labels the horizontal axis at 2 and 4 (x: ['2','4'], y: 5..1). twoway folds t* onto x* without regard to orientation (input to P1.6).
- **Default titles with mixed or multiple layers** (t4, t5; P1.16's rule, recorded here as input):
  - `(scatter y x)(bar y x, horizontal)`: no x or y title.
  - `(scatter y x)(bar y x, horizontal)(scatter y x)`: y "Yvar", x "Xvar".
  - `(bar y x, horizontal)(bar y x, horizontal)`: y "Xvar", x "Yvar".
  - `(rcap lo hi x, horizontal)(scatter x y)`: y "Xvar", no x title.
  - `(scatter y x)(scatter lo x)`: no y title.
  - `(scatter y x)(scatter y lo)`: no x title.
  - `(scatter y x)(scatter lo hi, yaxis(2))`: x title "Xvar...".
  - `(scatter y x)(bar y x, horizontal yaxis(2))`: x title "Xvar...".

  A horizontal layer contributes its y variable(s) to the x title and its x variable to the y title. How layers combine is P1.16's rule.

## 4. Approach (both modes, before and after a filter move)

Principle: twoway's horizontal is an exact transpose of the upright drawing (M2). Draw the layer exactly as now, then transpose the layer's glyph bindings and annotation coordinates. Column names and data are unchanged. Everything gated on the flag leaves existing dashboards byte-identical.

### dash_render.py

1. **New constants and helper.**
   - `_DASH_HORIZONTAL_TYPES`: the 24 types of M1.
   - `_DASH_VERTICAL_TYPES`: the 22 types.
   - `_DASH_TRANSPOSE`: glyph class → (new class, property map).
   - `_dash_is_horizontal(plot)`: true when the type is in the set and `options["horizontal"]` is non-blank.
   - `_dash_transpose_layer(fig, renderers, annotations)`:
     - Rebuilds `glyph`, `selection_glyph`, `nonselection_glyph`, `hover_glyph` and `muted_glyph` from `properties_with_values(include_defaults=False)` with the map.
     - Swaps LabelSet/Arrow (and Label/Span if present) data coordinates. It never changes `x_offset`/`y_offset`/`angle`/`text_align`, which stay physical (M4).
     - Re-points each source's `_dash_spacing_glyphs` entries from old glyph objects to new ones.
     - Marks each renderer `_dash_horizontal = True`.
     - Refuses an unmapped glyph class loudly (a warning naming the type), so a future mapper glyph cannot silently stay upright.
   - Add all of these to the served app's copy lists (dash_render.py ~:32937 constants, ~:33227 functions).
2. **Call it in both layer loops**, immediately before `_dash_assign_axis_ranges`:
   - saved: `DashRenderer._make_figure_body` at dash_render.py:30649, with `fig.renderers[_r_before:]` and `fig.center[_c_before:]`;
   - served: template `_dash_draw_layer` at dash_render.py:35009.

   `_dash_assign_axis_ranges` keeps `y_range_name`/`x_range_name` unchanged, which is twoway's physical `yaxis(2)` (M4). The served redraw draws on a throwaway figure through `_dash_draw_layer` and returns only sources (dash_render.py:35083-35092), so it is unaffected.
3. **Axis variables, orientation-aware, one rule for both modes.**
   - `_dash_axis_vars` (dash_render.py:821): swap for a horizontal first layer. A univariate horizontal layer returns `("", var)`.
   - `_dash_figure_date_kind` (dash_render.py:788): a horizontal layer contributes its x variable on `"yvar"` and its y variable(s) on `"xvar"`. A univariate horizontal layer contributes `var` on `"yvar"` only. This closes the S05 hand-off.
   - `_dash_axis_labels` (dash_render.py:21665): swap `(x_default, y_default)` when the first layer is horizontal (histogram: x "Density", y label; kdensity: x "kdensity v", y "x"). The explicit `xtitle()`/`ytitle()` stay physical.
   - `_compute_secondary_range` (dash_render.py:7684): read `xvar` for a horizontal layer on `yaxis(2)` and its `yvar` for `xaxis(2)`. The y2 default title comes from `_dash_axis_labels(own)` with the same swap.
   - `_DASH_X_COORDS` (dash_render.py:23112): add `"x2"` (HArea).
4. **Computed layers on dates.** `map_histogram` (dash_render.py:12514) and `map_kdensity` (dash_render.py:12881) pass `"y" if _dash_is_horizontal(...) else "x"` to `_on_axis`, so a horizontal date histogram converts by the y axis's kind (M4 date truth). function and the pc/literal types on a date axis stay P1.23.
5. **After a filter move.**
   - Saved page: the spacing writer in `_FILTER_JS` (dash_render.py:18777, `_g.width = _w`) writes `height` for an HBar. `_build_filter_widgets` (~:32217) emits the property name per spacing glyph in `derived_spacing_json`; JS reflection is not used.
   - Served: `_dash_copy_redraw_geometry` (dash_render.py:24941) copies `height` for an HBar.
   - The histogram recount, CDSView filtering, the stale cue and the served redraw write data columns only. They need no change, and tests prove that.
6. **Hover.** In `_dash_build_hover` (dash_render.py:27118), `_drawn_field` reads through the inverse map when the renderer is `_dash_horizontal`, so tooltip rows keep the variable roles. `_bins` returns `"hline"` instead of `"vline"`. The `_band` shape accepts HArea.

## 7. Decisions for the maintainer

1. **`horizontal` with `vertical`.**
   - (a) Refuse r(198) with twoway's "may not combine options horizontal and vertical".
   - (b) Keep accepting and naming them.

   This is a §4 "Refuse vs note" case, but a contradiction rather than an unknown option. dash already refuses `horizontal horizontal`. **Recommend (a).**
2. **`horizontal` on the 16 types twoway refuses, and `vertical` on kdensity/function.**
   - (a) Keep naming (current policy).
   - (b) Refuse r(198).

   This follows the open §4 "Refuse vs note" decision. **Recommend (a) until §4 is decided.**
3. **Sequencing of default titles.**
   - (a) P1.9 swaps only the first-layer default, which is exact for single-layer and same-orientation graphs. P1.16 implements twoway's multi-layer rule (M4 cases, including the "Xvar..." form) on top of the orientation helper.
   - (b) Fold the multi-layer rule into P1.9.

   **Recommend (a).**

## 8. Size, risk, split, feasibility

- **Effort L.** About 24 types, but one generic transposition. Most of the work is in axis variables, filter-move geometry, hover and tests.
- **Risk yellow.** It touches CRITICAL/HIGH symbols, but every change is gated on the flag, so unflagged output is byte-identical (pinned by `TestUprightIsUntouched`).
- **Split into two plan sections:**
  - **9a, draw and axes (M):** transposition helper, both loops, axis vars/titles/date kinds/y2, dash.ado note gating and refusal, help, fixture, transpose/axes/date tests, flips.
  - **9b, interaction parity (M):** the saved spacing JS height, served `_dash_copy_redraw_geometry`, hover fields and `hline`, filter-move and parity-corpus tests, by()/yaxis(2) after a move.
