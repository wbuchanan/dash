## 3. Approach (closes the item in both modes)

Both modes are covered without a filter-move dimension:

- The prefix is stripped before registration, so the saved page, `dash build, server` and `dash serve` all see the same spec.
- The browser rule lives in the two deciders shared by the one-line form, `dash build` and `dash serve`.
- The saving() parser is shared by the one-line form and `dash build` (HTML and `server` .py). `dash serve` keeps noting and ignoring saving().

### a. No window under `set graphics off` or in batch

- Add a private program `_dash_display_on, rclass` in dash.ado. It returns r(on)=0 when `c(graphics)=="off"` or `c(mode)=="batch"`.
  - It also needs a test seam, the undocumented global `$dash__display` (values `on` or `off`). It overrides the session reading so that the controls in the certification suite (which always runs in batch) can still reach the opener.
  - The name follows the existing `dash__uv` and `dash__gq_if` convention.
- `_dash_browser_wanted` and `_dash_dashboard_browser` each call it and set open to 0 when r(on)==0. `dash serve` then gets `--no-browser` through r(flag), unchanged.
- The existing "else" branches already print where the page went:
  - one-line: "dash: dashboard saved to <path>" (dash.ado:6830)
  - build: "dash: dashboard saved to ..." (:8243)
  - The preview is named `q` (not opened), as under `$dash_nobrowser`.
- `_dash_open_page` is not changed. HC2-30b/34f drive it with stubs in batch.
- dash.sthlp: update the nobrowser row (:950-956) and the `nobrowser_global` paragraph (:959-977). New text: "In batch (c(mode) batch) or after set graphics off no window opens, as twoway displays no graph; the page is written and its path printed." Interactive console Stata keeps opening.

### b. twoway prefix

- In `dash` (dash.ado:115-136), before the subcommand dispatch, strip a leading prefix in Mata, by value:
  - `twoway`, `tw` or `two`
  - `graph` or `gr`, followed by one of `tw`, `two`, `twow`, `twowa` or `twoway`
- Re-derive `_subcmd`/`_args`, then route only to `_dash_plot`. `dash twoway build` must not become `dash build`.
- Refuse what twoway refuses:
  - `twow`, `twowa`, `gra` and `grap` fall through to the existing "unrecognised plot type", r(198); twoway gives r(199).
  - A doubled prefix is refused because only one prefix is stripped.
  - Optionally, give r(199) "command X is unrecognized" for the words twoway itself does not recognise.
- `dash twoway` with nothing after it stays "empty plot specification", r(198). twoway draws an empty graph, rc 0; record that as a residual.
- dash.sthlp Syntax (:45-52): one sentence saying that `twoway`, `tw`, `two` or `graph twoway` may precede the plot specs, as in twoway.

### c, d. One saving() grammar for both routes

- Add the Mata function `_dash_saving_split(string scalar s)` in dash_parse.mata. It sets the locals `_sv_file`, `_sv_replace`, `_sv_asis` and `_sv_err`, and handles text by value.
  - It splits at the first top-level comma that is outside `"..."` and compound quotes.
  - It strips one pair of quotes from the file part.
  - It reads sub-options only as the full words `replace` and `asis`, each at most once. Anything else is r(198) "option <w> not allowed", which is twoway's message.
  - An empty file part becomes `Graph`, as twoway's default.
- Add a wrapper program `_dash_saving_parse` that maps the `.gph` suffix and appends the extension (`.html`, or `.py` for `server`). Both `_dash_render_immediate` (replacing dash.ado:6467-6484) and `_dash_build` (before :8142) call it. `asis` is accepted and has no effect, because a saved page is already frozen; the help says so.
- `_dash_plot`'s fold of a trailing `replace` (dash.ado:5561-5563) appends ` replace` when saving() already holds a comma, and `, replace` otherwise. The parser then never sees `n, asis, replace`.
- `_dash_build`: `saving(f, replace)` sets `replace`. `saving(b2)` becomes b2.html, and with `server` app becomes app.py. `saving(x.gph)` becomes x.html with the one-line form's note. This is one rule for both routes.
- Keep `saving(my file.html)` (an unquoted name with a space) accepted. twoway refuses it, but nothing is wrong there; record it as a residual.
- Register the new function in `_dash_require_mata`'s `_needed` list (dash.ado:237-253), in dash_parse.mata's header (:40ff, which test_file_headers.py reads) and in test/program_coverage_map.py.

### e. Only sink-tied path checks (GAPS2-I14 plan steps 1 and 3)

- `_dash_path_badchar`: the list becomes `"`, backquote, `$`, and every control character (1-31 and 127), matching Python. `; & | < >` are removed.
- `_dash_validate_path`: delete the `..` segment check (dash.ado:498-505) and the `[;&|<>]` check (:536-539).
  - Keep the `~/` expansion, the leading `-` refusal, the suffix rule and the quote check.
  - The leading `-` refusal still guards argparse's `--output` and the opener.
- `_validate_output_path` (dash_render.py:36710-36716): refuse a `..` segment only when `launch=True`. That is dash serve's private app path, where `..` never occurs legitimately. Update the docstring.
- Help: state the character rule next to saving(). This is the same paragraph P1.29 adds `%` and `!` to (see Conflicts).
- Security rationale for BUGS.md and CHANGELOG:
  - saving() is the user's own command, and absolute paths are already accepted (PV-07), so the `..` refusal guarded nothing.
  - The one shell sink single-quotes the path (measured above).
  - JSON writing escapes it (`_dash_json_str`).
  - Python writes it with open(), not a shell.

## 6. Decisions only the maintainer can make

- **D1: browser in batch and under `set graphics off`.**
  - Options: (a) suppress in both, as twoway displays nothing; (b) suppress only under `set graphics off`; (c) keep opening and document it.
  - Implication: (a) changes behaviour for anyone who runs `stata -b` and expects tabs. Windows `/e` and GUI c(mode) are UNCLEAR.
  - Recommendation: **(a)**. Interactive console keeps opening.
- **D2: relax the `..` and `; & | < >` refusals (rule 1 tension).** This reverses a pinned security test (P2-80, PV-04/05/14).
  - Options: (a) allow all of them, keeping only the sink-tied checks; (b) allow only the named `..` and `&`; (c) keep the refusals and document them.
  - Implication: (a) gives twoway parity. Analysis finds no sink: absolute paths are already accepted, and the one opener single-quotes the path (measured).
  - Recommendation: **(a)**. Keep `"`, backquote, `$`, control characters and a leading `-`, and keep `..` refused on the internal `--launch` route.
- **D3: an unknown saving() sub-option.** This is an instance of §4 "Refuse vs note".
  - Options: refuse with r(198), as twoway does; or note it and ignore it.
  - Recommendation: **refuse**. A file name is at stake, and dash already refuses a repeated saving() with twoway's message.

The plan can settle these without the maintainer:

- `asis` is accepted and has no effect.
- `saving(, replace)` writes Graph.html.
- `dash build` appends a missing extension, as the one-line form does.

Unquoted names with spaces stay accepted. A leading `-` stays refused; it is a residual that could be lifted by making the path absolute in the opener and passing `--output=<path>`.
