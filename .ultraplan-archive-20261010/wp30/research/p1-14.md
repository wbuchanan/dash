## 2. twoway truth (StataNow 19.5, batch, graph object `.Graph.plotregion1.plotK.style.*`, plus SVG export)

Method: `twoway <cmd>, nodraw`, then read `style.marker.{fillcolor.rgb, linestyle.color.rgb, linestyle.width.val, symbol.stylename, size.val}`, `style.line.{color.rgb, width.val, pattern.stylename}`, `style.area.{shadestyle.color.rgb, shadestyle.intensity.val, linestyle.*}` and `style.dots.*`. Every case had rc 0 unless stated otherwise.

### 2.1 What each option is (twoway_yxview_parse.class `factor`, lines 543-760)

- `pstyle(X)` sets `style(X)`, the seriesstyle. seriesstyle p# (style/seriesstyle-p#.style) is: marker = markerstyle p#, line = linestyle p#connect (falls back to linestyle p#), area = areastyle p#, label = p#.
- `lstyle(X)` sets `line(X)` and `area(linestyle(X))`.
- `clstyle(X)` sets `line(X)`.
- `mstyle(X)` sets `marker(X)`.
- `mlstyle(X)` sets `marker(linestyle(X))`.
- `astyle(X)` and `bstyle(X)` set `area(X)`. They are identical.
- `alstyle(X)` and `blstyle(X)` set `area(linestyle(X))`.
- `dstyle(X)` sets `dots(X)`.
- A type's default seriesstyle carries a suffix (`_type_suffix`, class lines 1040-1048): line, rline and pcline take p#line; bar and rbar take p#bar; area and rarea take p#area; pcarrow and pcbarrow take p#arrow. Fits (lfit, lowess, kdensity, function, tsline) are line views. histogram uses the `histogram` style.

### 2.2 `pstyle(p3)` against the type's own plot 3 (t2.do, 3 schemes × 19 types)

Identical for scatter, connected, spike, rcap, dot, area, rarea, mspline and mband in stcolor, s2color and s1mono. They differ where the default seriesstyle has a suffix:

```
s1mono line|lfit|kdensity|rline|pcarrow|function|tsline|lowess: lc 128 128 128 solid -> 0 0 0 vshortdash   (connect chain)
all 3 schemes bar|rbar: area outline width .2 -> .3                  (areastyle p# not p#bar)
stcolor histogram: fill 26 133 255 @90, outline 95 170 255 w .15 -> fill/outline 0 191 127 @80, w .3
s2color histogram: fill 202 194 126 @100 -> 85 117 47 @80
stcolor pcarrow: arrowhead size 1.52778 -> 1.04166
```

So `pstyle(p#)` is equivalent to `mstyle(p#)` + `lstyle(p#)` (line) + `astyle(p#)` + the p# label style. It is NOT just "draw as plot #". dash's `_ci_line_restyle` "p" branch (connected colour, width `p#`, connect pattern) is already the correct line half.

### 2.5 Precedence follows twoway's factor order, not the typed order (t3.do, t5.do)

The factor program applies, in this order: PSTYle, COLor, LStyle, LColor, LWidth, LAlign, LPattern, CLStyle, CL*, MSTyle, Msymbol, MColor, MFColor, MSIze, MLstyle, ML*, ..., ASTyle, AColor, AFColor, AFIntensity, ALstyle, AL*, BSTyle, BColor, BFColor, BFIntensity, BLstyle, BL*, FColor, FIntensity, DSTyle, D*. A later factor overrides an earlier one, whatever order the user typed:

```
scatter pstyle(p3) mcolor(red) == mcolor(red) pstyle(p3)  -> red marker, p3 otherwise
scatter pstyle(p3) mstyle(p4)  == mstyle(p4) pstyle(p3)   -> p4 marker, p3 line/area
scatter color(red) mstyle(p4)    -> p4 marker (mstyle beats color())
scatter mlcolor(red) mstyle(p4)  -> p4 fill, red outline
area lcolor(red) astyle(p4)      -> outline p4 (astyle beats lcolor on the area)
area acolor(red) bstyle(p4)      -> p4 (bstyle beats acolor)
area fcolor(red) astyle(p4)      -> red fill, p4 outline;  fintensity(30) astyle(p4) -> intensity 30
area astyle(p4) alstyle(p3)      -> fill p4, outline p3 (either order)
line lwidth(thick) lstyle(p3)    -> width .8, p3 colour
bar bcolor(red) bstyle(p4)       -> red;  blcolor(red) bstyle(p4) -> p4 fill, red outline
scatter pstyle(p3) pstyle(p4)    -> p4 (rightmost)
```

### 2.6 Numbering, lists and abbreviations (t4.do)

- `(scatter, pstyle(p3)) (scatter)`: plot 2 is still p2 (212 17 89 under stcolor). pstyle does not renumber.
- `scatter mpg turn weight, pstyle(p3 p4)`: plot 1 is p3, plot 2 is p4. On a single y, `pstyle(p3 p4)` uses p3. `mstyle(p3 p4) lstyle(p5 p6)` splits the same way.
- Accepted minimums: `psty` and `p` (pstyle), `ls`, `mst`, `mls`, `ast`, `al`, `bst`, `bl`, `dst`, `cls`.
- Refused r(198): `pst()`, `ps()`, `as()`.
- Other meanings: `ms()` is msymbol, `bs()` bsymbol and `ds()` dsymbol (each gives "named style p3 not found in class symbol"). `ml(p3)` is mlabel (r(111)).
- s1.do: Stata `syntax` with `ALstyle ALColor ASTyle ASPectratio BSTyle BLstyle BLColor BLABEL DSTyle CLStyle P() PSTYle` resolves al, alc, ast, bst, bl, blc, dst, cls, p and psty exactly as twoway does. `as()`, `ds()` and `pst()` fall into `*`.

## 3. Approach (closes the item in both modes)

Core idea: every p# named style reduces to three bundles at index i, all of which dash's `SchemeParser` already parses:
- marker(i): `p_mark_colors`, `p_symbols`, `p_marker_sizes`, `plot_line_width(i,"mark")`, mark alpha.
- line(i), linestyle p#: `p_line_colors`, `plot_line_width(i,"")`, `p_line_patterns`, `p_line_alphas`.
- area(i), areastyle p#: `p_other_band_styles[i]`, the structure the CI band already uses.

`pstyle(p#)` = marker(i) + line(i) + area(i) + the style index i for the rest (labels, arrowheads).

### Section A: p1-p15 on every type and option, both modes (M/L)

1. **dash.ado `_dash_parse_plot_opts` (syntax at :924-990).**
   - Declare `ASTyle(string) ALstyle(string) BSTyle(string) BLstyle(string) DSTyle(string) CLStyle(string) P(string)`, with twoway's minimums (verified in s1.do).
   - Fold `p` into `pstyle` the same way `mlg` folds into `mlabgap` (:1024-1033).
   - Add the new keys to `_dash_plot_opts_to_json`'s foreach list (:3144-3156).
   - Remove `pstyle lstyle mstyle mlstyle` (:1074, :1082-1085) from `_dash_pending`, and do not add the new ones.
   - `_dash_fold_typed` (:1792-1798): drop the CI-only special case for pstyle.
2. **dash_render.py `SchemeParser.style_bundle(cls, name)`**, new. cls is one of marker, line, area. It returns a resolved dict for `p1`..`p15`, and None otherwise. Names are matched exactly (case-sensitive), as Stata does. It never uses the name to build a path.
3. **`_dash_named_style_plan(options)`**, a new module function in the served-app copy list (:33129). It reads the named-style options and the explicit options and, following twoway's factor order (§2.5), returns for each role (marker fill, marker outline, marker symbol and size, line, area fill, area outline, dots) the bundle that applies and the set of explicit options that bundle shadows. A style list takes its first word (twoway's single-y rule) until P1.1 splits lists per y.
4. **pstyle index.** In `_dash_add_glyph` and `_dash_add_pc_glyph` (:28955, :29006), when pstyle is p#, pass `color_idx = # - 1`. `_dash_plot_style_indices` (:26709) is unchanged, because numbering is not affected (§2.6).
5. **Apply bundles before the user's options**, in the three central appliers (39 call sites; no per-mapper edits):
   - `_apply_marker_opts` (:8622), `_apply_line_opts` (:8540) and `_apply_fill_opts` (:8807) each first restyle the glyph from the plan's bundle for their role, then apply only the explicit options the plan did not shadow.
   - The area outline applies `lstyle`, then `alstyle`/`blstyle`.
   - `_ci_band_style` (:8307) gets `astyle`/`bstyle`/`alstyle`/`blstyle` merged into its documented order (fill: pstyle < color < astyle < acolor < bstyle < bcolor < fcolor; outline: pstyle < color < lstyle < lcolor < astyle < acolor < alstyle < alcolor < ... < blstyle < blcolor).
   - Generalise `_ci_line_restyle` into the line(i) bundle.
   - A colorvar() layer keeps its mapped fill (the bundle never replaces a colour mapper).
6. **Non-p# names in Section A** keep the current behaviour: one note through `_dash_warn_once`/`_dash_display`, and the layer's own default is drawn. CI pstyle keeps ci/ci2 and its p1 fallback.
7. **dstyle in Section A** is declared and serialized but stays named until P2.9 draws dot rows. dash draws `dot` as a plain scatter, so there is nothing for it to style.
8. **dash.sthlp:**
   - Rewrite "Named styles" (:3647-3655) and the band paragraph (:2596-2600).
   - Document the factor order and `p()`.
   - The Unsupported list loses these options; test_help_conformance.py enforces that.
9. **Security (rule 1):**
   - Names stay data: matched against a fixed set, never used as file paths, and echoed only through `_dash_display`.
   - The spec still writes values via `_dash_json_str`.
   - Add a hostile-name test: SMCL, quotes, `../x`, 10k characters, unicode.

## 7. Decisions for the maintainer

1. **Scope of names.**
   - (a) p1-p15 only, with other names noted and drawn in the layer's default.
   - (b) (a) plus a curated table of Stata-known names and twoway's default attributes for unknown names.
   - (c) A general resolver for all 161 Stata style files (XL; it needs the style files and full scheme transcription).
   - Recommend (a) for Section A, then (b) as Section B.
2. **Precedence.** Match twoway's factor order, under which `color(red) mstyle(p4)` and `acolor(red) bstyle(p4)` draw p4, or let explicit options always win. Recommend matching twoway (drop-in parity), documented in the help.
3. **Unknown names.** Draw twoway's default attributes (lstyle(bogus) black thin, astyle(bogus) white), or keep the layer's own look and print a note. Recommend matching twoway with a note, as the CI pstyle already does.
4. **blstyle/clstyle** (not in the item's list). Recommend including them, since the mechanism is the same.
5. **dstyle.** Plumb it now and keep it named until P2.9 (recommended), or wait.
6. Ties to DROPIN §4 "79 accepted-but-ignored options" (`mstyle`/`lstyle` are in the high-value subset) and "Refuse vs note" (`pst()`/`as()`).
