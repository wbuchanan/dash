## 4. Proposed approach (two sections)

### 4A: opacity, histogram style and the symbol cycle reach every layer (dash_render.py, scripts/extract_scheme_truth.py, 20 `dash-*.scheme`, dash.sthlp)

1. **`GlyphMapper._scheme_alpha_kw(color_idx, plot_type, fill=True, line=True) -> dict`**: a new helper next to `_scheme_alpha`.
   - It returns `{}` when `scheme.default_alpha()` is None. 19 of 20 shipped schemes then draw byte-identically.
   - Otherwise it returns `{"line_alpha": a}` / `{"fill_alpha": a}`.
   - Pass it at glyph construction in map_lfit, map_qfit, the line of map_lfitci/qfitci/lpolyci/fpfitci, map_lowess, map_lpoly, map_fpfit, map_kdensity, map_function, map_mspline, map_mband, `_empty_fit_line`, map_spike, map_dropline, map_rspike, map_rcap, map_rcapsym, map_rline, map_tsrline, map_rscatter, map_scatteri, map_pci_literal, map_pcspike, map_pcarrow (segments and heads), map_pcbarrow, map_pccapsym, map_pcscatter, map_pcarrowi, map_rbar (fill) and map_rarea.
   - The existing option appliers run afterwards. A user `%NN` still wins, and a colour without one keeps the scheme opacity, as measured.
   - **Do not touch the CI band VArea.** It reads `ci_area`, which carries no opacity.
2. **map_rarea**: replace `fill_alpha=0.5` with `self._scheme_alpha(color_idx, "rarea", self.scheme.area_alpha)`, map_area's rule.
3. **Histogram style.**
   - Add `color histogram`, `color histogram_line`, `intensity histogram` and `linewidth histogram` to the extractor's key table (`extract()`, :1180-1240, beside ci_area) and to `expected_directives`.
   - Regenerate the 20 shipped files and `test/fixtures/scheme_truth.json`. The extractor already folds `stc1*0.7` (`_apply_intensity`).
   - `SchemeParser._init_properties` gains `histogram_color`, `histogram_line_color`, `histogram_alpha` (declared opacity, else the intensity approximation that bar uses until P1.2 lands) and `histogram_line_width`. A missing key falls back to today's values for a user scheme.
   - `_histogram_quads` draws with them for every layer index. `color()`, `fcolor()` and `lcolor()` still win, as measured.
   - This also closes the empty histogram key.
4. **Symbol traits.**
   - `OptionTranslator.symbol_traits(value) -> (marker, hollow, size_factor)`. sm* gets 0.7071; everything else 1.0. `translate_msymbol` stays a wrapper.
   - SchemeParser keeps `p_symbol_hollow` and `p_symbol_factor` beside `p_symbols` (same `_first_present` chain), with an accessor `default_symbol_traits(i)`.
   - map_scatter and the five non-cycling marker mappers (scatteri, rscatter, pcscatter, dropline, rcapsym) take marker, size × factor and hollow from it when no `msymbol()` is given.
   - Hollow is applied last in `_apply_marker_opts`, after malpha, so `mfcolor()` and `malpha()` cannot refill it (measured). This also fixes side finding (i).
   - P2.11 later extends `symbol_traits` for point, V, pipe and arrow.
5. **dash.sthlp** (Series paragraph :3357-3378):
   - Remove "not yet its opacity". Say the CI band takes `color ci_area` and its opacity.
   - Add a histogram sentence (scheme histogram style, the same for every histogram layer).
   - Add the symbol traits.

### 4B: label and key chrome from the scheme, and naming unread directives

1. **Marker labels.**
   - SchemeParser adds `p_label_colors[15]` (`color p#label` → `color plabel` → p# colour) and `p_label_sizes[15]` (`_gsize` of `gsize p#label` → `gsize plabel`). The extractor and the 20 files gain `color plabel` and `gsize plabel`.
   - `_apply_mlabel_opts` uses them as defaults. `mlabcolor()` and `mlabsize()` still win. `mcolor()` does not change the label colour.
   - The size unit depends on decision 1.
2. **ColorBar chrome** in `_apply_colorvar`, at construction:
   - `background_fill_alpha=0`, so it sits on the graph region as Stata draws it;
   - `major_label_text_font_size`/`_color` from `tick_label_font_size`/`tick_label_color`;
   - `title_text_font_size`/`_color` from `axis_title_*`;
   - `major_tick_line_color` and `bar_line_color` from `axis_line_color`.
   - `_dash_apply_z_options` runs afterwards, so `ztitle()` and `zlabel()` still win. The discrete colorvar Legend already goes through the legend chrome.
3. **Unread-directive note.**
   - `_parse_lines` records which keys came from a file that is not one of the shipped `dash-<name>.scheme` files.
   - `_init_properties` runs with `_props` wrapped in a read-recording dict. Most reads happen there or in helpers it calls.
   - One reader runs at render time, not in init: `plot_line_width` (:7338) calls `_plot_lwidth_of` (:7317, the `_props.get` at :7324). The `linewidth p#…` keys it can reach must therefore be added as a declared "read lazily" family, or the recorder must stay attached for the whole build. The first option is simpler and works in served mode, where the build does not render.
   - Unread user keys, minus a curated table of non-twoway families (bar/box/pie/dot/matrix/combine/sts/fp…), produce one UserWarning per build.
   - The note names up to 10 directives as plain text through `_dash_display`, then "and N more".
   - It is raised in the Stata-side parse in both modes: `DashRenderer._scheme_for` and `ServerAppBuilder.__init__` :32830. It is never raised inside the emitted app, whose `_dash_build_scheme` uses `__new__`.
   - Shipped schemes never note.
4. **Side finding (h).** Read `color p#markfill` for a marker's fill and `color p#markline` for its outline, falling back to p#. Stop reading `p#mark`. There is no rendered change on shipped schemes.
5. dash.sthlp: the Text paragraph gains marker labels and the colour key; a new sentence describes the unread-directive note.

Both sections need BUGS.md entries, written first (rule 7). Add CHANGELOG entries.
