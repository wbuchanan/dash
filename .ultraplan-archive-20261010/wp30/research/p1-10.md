## 2. twoway's truth (StataNow 19.5)

Source of the rule: `ado/base/t/twowaygraph_g.class:686-800` (`ParseAndLogText`, `_parse_log_1textbox`).
- Each `text()`/`ttext()` copy is parsed on its own, with its own sub-options.
- Sub-options: `AXes()` (undocumented), `YAXis(#)`, `XAXis(#)`, `TSTYle()`, then the textbox options via `_fr_sztextbox_parse_and_log`.
- A point is checked with `numlist "x y", max(2) min(2)`. For `ttext()` only, x may instead pass `_confirm_number_or_date`, and it is then converted by `_date2elapsed, format(<axis time format>) datelist(x)` (pos_textbox.class:31-32).

- Help (added_text_options.sthlp) calls both options *merged-implicit*. The default style is `scheme text_option`.

## 3. Proposed approach (closes it in both modes)

### 3a. Stata side (dash.ado, dash_parse.mata): parse the way twoway does, and hand the renderer structured copies

1. **Declare `TTEXT(string asis)`** next to `TEXT(string asis)`:
   - in both syntax blocks (`_dash_parse_graph_opts` dash.ado:713-735 and `_dash_parse_plot_opts` :924-950);
   - in the sreturn blocks (:859, :1278);
   - in the seven `foreach gk/gkey` lists (:4274, :5066, :5100, :5200, :5272, :5304, :5602).
   Do it through `scripts/regen_option_surface.py`: add `("ttext", None)`, put it in ASIS, and change `("text","S09")` to `("text", None)`. Neither name has an abbreviation (twowaygraph_g.class:128).
2. **Remove `text`** from both `_dash_pending` blocks (:807, :1110).
3. **Fix the merge (S4)**:
   - In `_dash_rep_merge` (dash_parse.mata:5715), category "A" must keep copies apart. Join them with a separator the copy parser can split on. The safest is a record separator that Stata text cannot contain, e.g. `char(30)`, rejected on input if present. The alternative is `", "` plus the rule "a number after a top-level comma starts a copy", as `_dash_refline_instances` does for xline. Do NOT reuse `_dash_by_tokens_commas`: it toggles on every `"`, so compound quotes holding a comma would split wrongly.
   - `ttext` gets the same category "A" in `_dash_rep_cat` (:4680).
4. **New program `_dash_added_text`** (dash.ado; Mata helpers in dash_parse.mata), run once per graph at JSON assembly, after the plots are known (next to `gopts_json`, :5598-5617). For each copy of `text` and then `ttext`, in order, it walks the copy with Stata's own tokenizer: `gettoken ..., quotes` exactly as `_parse_log_1textbox` does.
   - **Points.** Check y and x with `numlist "x y", max(2) min(2)`. For ttext, when that fails, check y with `numlist` and x with `_confirm_number_or_date`. On failure: `di as error "invalid point, x y"`, exit 198 (verbatim from twoway).
   - **Dates.** For ttext, convert x with `_date2elapsed, format(<fmt>) datelist(<x>)`.
     - `<fmt>` is xlabel's `format()` when it is %t/%d. Otherwise it is the FIRST plot's x variable format when that is %t/%d (tsline: the tsset time variable).
     - `_date2elapsed` raises twoway's own `"<x> is not a number"` r(198).
   - **Axes.** Read yaxis(#), xaxis(#) and axes(# #). Refuse an axis pair the graph does not have with twoway's message: `text() option invalid, specified axis pair (Y X) not in graph`, r(198). dash already tracks the axes in use (`_dash_axreq_*`, `_g_ys`/`_g_xs`). dash draws axes 1-2 only; `yaxis(3)` is refused already by the `yaxis(3)` rule.
   - **Output.** Emit one JSON array key, `"added_text":[{"y":30,"x":3000,"yaxis":1,"xaxis":1,"lines":["AAA"],"opts":"color(red)"},...]`, written with `_dash_json_str` per string. Empty `lines` are dropped, as twoway draws nothing for them. Remove the raw `text` and `ttext` keys from `gopts_json`, so there is one source of truth.
   - **Cap.** Refuse more than N added texts per graph with a clear message (see Decision D3). Rule 1: 10,000 triplets would otherwise become 10,000 Bokeh models per panel.

### 3b. Renderer (dash_render.py): one shared helper, called by both modes

1. New `_dash_added_text(fig, graph_opts, seen, key, scheme)`, next to `_dash_reference_lines` (dash_render.py:26224). On `yaxis(2)`/`xaxis(2)`: `y_range_name="y2"`, `x_range_name="x2"` (the names `_dash_reference_lines` uses), and the numbers are read as they stand.
   - `text` is the lines joined with `"\n"` (multi-line `Label` is already relied on: test_textbox_multiline.py docstring).
   - `placement()` maps to `anchor`: n `bottom_center`, ne `bottom_left`, e `center_left`, se `top_left`, s `top_center`, sw `top_right`, w `center_right`, nw `bottom_right`, c `center`. Accept every compassdirstyle synonym (north/n/12/top/t, neast/ne/1/2, east/e/3/right/r, ...). An unknown name gets a note worded like twoway's and draws east (measured).
   - `justification()` maps to `text_align` for multi-line text.
   - `orientation()`: vertical gives angle +pi/2, rvertical -pi/2, rhorizontal pi; accept the `orient` minimum.
   - `size()`/`color()` go through `_textbox_size`/`_textbox_color` (unchanged).

   - Name the rest in the note with `_dash_report_suboptions`: `linegap`, `width`, `height`, `alignment`, `tstyle`, `bmargin`, `bexpand`, `lpattern`, `lstyle`, `lalign`. Use a separate honoured set; do NOT widen `_DASH_TEXTBOX_HONOURED`, which titles use.

## 5. Decisions for the maintainer

- **D1 Refusals.** twoway refuses malformed points, a missing axis pair and unknown sub-options inside text(), r(198).
  - Options: (a) refuse all of them as twoway does; (b) refuse points and axis pairs, and name unknown sub-options in the note (as titles do now); (c) note everything.
  - Points and axis pairs are parse errors, and WP-29 already refuses like cases (function `pi`, r(111)). Unknown sub-options fall under §4's open "Refuse vs note".
  - **Recommendation: (b)**, with the sub-option behaviour following the §4 decision when it is made.
- **D2 Sub-options dash will not draw** (`linegap`, `width`, `height`, `alignment`, `tstyle`, `bmargin`, `bexpand`).
  - **Recommendation:** name them in the note and list them in the help. `tstyle()` could map to scheme textbox styles later.
- **D3 Cap on added texts.** twoway has none. dash's other caps are 100 plots per graph and 100 by() groups.
  - **Recommendation:** refuse more than 1,000 added texts per graph, with the limit in the help. Without a cap, panels × texts grow without bound (rule 1).
- **D4 Encoding of copies.**
  - Options: (a) a structured `added_text` JSON array built in Stata; (b) a joined string re-parsed in Python.
  - **Recommendation: (a).** Stata's own tokenizer handles compound quotes exactly, and the renderer receives validated numbers.

## 6. Effort, risk, split, feasibility

- **Effort: L.** The parse needs twoway-exact refusals and date conversion; then the merge fix, the renderer helper in both modes, scheme keys in 20 files, the truth fixture, about 25 pytest tests, a cscript and the help. DROPIN's M undercounts ttext and the scheme defaults.
- **Risk: yellow.** The changes are additive in the renderer. The merge-rule edit is shared by every repeated option, but only category A changes. The touched figure-building functions are CRITICAL or HIGH in GitNexus.
- **Split: yes, in two.**
  - **P1.10a `text()`** (M): parse, refusals, merge fix, renderer `Label` in both modes (placement, orientation, size, colour, box, axis 2, numeric dates, by(), filter move), scheme defaults, help.
  - **P1.10b `ttext()`** (S-M): declaration, `_date2elapsed` conversion with the first-plot or xlabel format rule, and the date refusals. Batch it with P1.6, which needs the same date-literal machinery and edits the same option-surface blocks.
- **Feasibility here: high.** All the twoway truth was measured in StataNow 19.5. Bokeh 3.9 `Label` supports every mapped property. The only unmeasurable parts are other OSes, Stata < 19.5 (rules forbid running them) and browser-side clipping (needs a screenshot test).
