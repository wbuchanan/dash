## 3. Approach (closes the item in both modes)

Split into two plan sections (see §6).

### 3.1 P1.29a: CSP without `'unsafe-inline'` in script-src

**Saved page: hashes.** In dash_render.py:
- `_DASH_CSP_STANDALONE` becomes the base policy with `script-src 'unsafe-eval'`. A new `_dash_csp_standalone(hashes)` inserts the sorted, de-duplicated `'sha256-…'` sources ahead of `'unsafe-eval'`, and `_dash_csp_meta` writes it (no whitelist change).
- A new `_dash_script_hashes(fragment)` returns the sha256 base64 of each *executable* inline `<script>` in a fragment. Executable means no `type`, a JavaScript MIME type, or `module`. `src=` scripts and `application/json` data blocks are skipped. The hash is over the UTF-8 text between the tags, in LF form.
- Hash only Bokeh's own output, before dash splices any HTML of its own:
  - `_assemble_layout` (:32585): hash `file_html(...)`'s whole output, then insert the meta. All user text there is inside Bokeh's escaped JSON.
  - `_render_bootstrap_html` (:30985-30989): hash `_extracted_head` and `script_tag` from `components()`. Do not hash the page after `header_html`, the filter bar, tabs or grid HTML are spliced in. Hashing the final page would bless any script that an escaping bug let into dash's own HTML.
- Replace the module constant `_CSP_META` (:4459) at both sites (:31107, :32594) with the per-page meta. Keep a module-level `_DASH_VIEWPORT_META` for the tests that read `_CSP_META` (test_served_bs_layout.py:877, test_help_claims_4.py:1787 flip to the new helper).
- Fail closed (decision D2): after assembly, count the page's executable inline scripts. If any is not in the hash set, raise a named error and write nothing.
- Drop `'unsafe-inline'` from script-src rather than keeping it as a CSP1 fallback. CSP2+ browsers ignore it once a hash is present, and dropping it lets the tests assert its absence. `style-src 'unsafe-inline'` stays (884 violations measured without it).

**Served page: nonce.**
- `_dash_served_template(nonce)` validates `nonce` against `[A-Za-z0-9_-]{22,64}` and builds the meta with `_dash_csp_served(nonce)` (`script-src 'self' 'nonce-N' 'unsafe-eval'`, no `'unsafe-inline'`). It then overrides two more FILE blocks, `{% block js_resources %}{{ super() | replace("<script", "<script nonce=\"N\"") }}{% endblock %}` and the same for `inner_body`, alongside the existing `preamble`.
  - This was measured on bokeh 3.8.0 (`file.html`) and 3.9.0 (`file.html.jinja`).
  - The replace is safe: the only user text in those blocks is the escaped title (not in them) and `escape()`d docs JSON (`{}` for a session).
- Generated `make_document` (dash_render.py:34724): `doc.template = _dash_served_template(_dash_new_nonce())`, with `secrets.token_urlsafe(18)`. One nonce per document, so one per page, because Bokeh renders one page per new session. A refused (keyless) session is served under the same template.
- `ServerAppBuilder` copy lists (:32952 constants, :33286 helpers): add `_dash_csp_served`, `_dash_new_nonce` and the base constant. A name left out is a NameError in the app; `test_the_helpers_are_the_renderers_own_text` catches it.
- `_DASH_SECURITY_HEADERS` keeps `'unsafe-inline'` (decision D3). The header cannot carry the per-page nonce, and without the source the header policy would block the page's own nonce'd scripts. The meta's nonce rule is what refuses injected code. This was measured under the launcher (header plus meta) and under `bokeh serve` (meta only).

**Help.** Rewrite dash.sthlp:1728-1737 to say:
- The saved page runs only the scripts dash wrote, each named by its SHA-256 hash.
- The served page runs only BokehJS from its own server and scripts carrying that page's one-time nonce.
- `'unsafe-eval'` stays because Bokeh compiles CustomJS with `new Function`.
- Styles stay `'unsafe-inline'` because BokehJS writes styles at run time.
- `python app.py`'s header keeps `'unsafe-inline'` so that the page's nonce'd scripts pass it.
- Fix the docstrings that describe the old policy: test_html_output.py:1917, test_label_sinks.py:1189, test_csp.py header.

## 5. Decisions for the maintainer

- **D1: Windows opener for a path holding `%` or `!`.**
  - (A) Write the page, do not open it, and print a line naming it. Logic-only, fully testable here with `os(Windows) dryrun` and stubs.
  - (B) Open it through Python `os.startfile(path)` (ShellExecute, path as data, no cmd.exe). Better user experience, but not measurable in WP-30 (M4 defers Windows); only a stubbed call can be tested.
  - (C) Refuse such paths in saving(). This breaks twoway parity: twoway accepts `%` and `!` (measured rc 0).
  - **Recommend A** now, and revisit B with P1.34.
- **D2: an executable inline script on the saved page that dash did not hash** (only possible through an escaping bug in dash's own HTML).
  - (a) Raise and write nothing.
  - (b) Leave it unhashed; the browser blocks it.
  - **Recommend (a)** (fail closed, rule 1), with a named error.
- **D3: `python app.py`'s header policy.**
  - (a) Keep `'unsafe-inline'` in the header. The meta's nonce governs, as measured.
