## 2. twoway's behaviour (StataNow 19.5, measured)

### 2.1 Which types take operators (m1; sp500, `gen t=_n`, `tsset t`)

Command form: `capture noisily twoway <type> D.close L.close, nodraw` (the range types use `L.low L.high t`, the pc types `L.close L.t close t`).

```
rc 0   : scatter line connected area bar spike dropline dot lfit qfit lfitci qfitci mspline mband
         rarea rbar rspike rcap rline rconnected rcapsym rscatter
         pcspike pcarrow pcbarrow pcscatter pccapsym  tsline (D.close)  tsrline (L.low L.high)
rc 101 : fpfit fpfitci lowess lpoly lpolyci histogram kdensity
         "factor-variable and time-series operators not allowed"
```

dash today returns r(101) for every one of these types.

### 2.2 What `syntax varlist(numeric ts)` gives (m4, m7, m8)

These are twoway's own words and codes:

```
tsunab z : l.close DL.close d.l.close L1.close L0.close S1.close L(0/2).close
TSUNAB: L.close LD.close LD.close L.close close S.close close L.close L2.close
tsyn L(1/2).close t        -> SYN: L.close L2.close t
tsyn L.(mpg weight) t      -> SYN: L.mpg L.weight t
tsyn L.mp t                -> SYN: L.mpg t   (abbreviation expanded; twoway rc 0 too)
tsyn L.close t (no tsset)  -> "time variable not set" r(111)
tsyn L.make mpg            -> "make:  may not use time-series operators on string variables" r(109)
tsyn i.foreign mpg         -> "factor-variable operators not allowed" r(101)
tsyn L.nosuch mpg          -> "variable nosuch not found" r(111)   (twoway: same)
tsyn X.mpg t               -> "X:  operator invalid" r(198)       (twoway: same)
```

The varlist that reaches dash is therefore already normalised: operators in canonical order and case, `L0.` dropped, abbreviations and `L(1/2).`/`L.(a b)` expanded.

Rule: when the base variable has a label, the text is that label + ", " + the normalised operator. When it has none, the text is the normalised expression `OP.name`.

### 2.4 Values, type, format and value label

- **Values are computed over the full data; `if` and `in` only select rows** (m2). `twoway scatter D.close t if t>5 & t<9` puts D_close = 4.940063 at t=6 in the serset, and `close[6]-close[5]` = 4.9400635. The lag reaches the excluded row 5.
- **Panels** (m3): with `xtset id tt` (2 panels × 10), the serset of `scatter L.y tt` holds 2 missing L.y values, one at the start of each panel.
- **Gaps**: with `tsset date` on sp500, D.close is non-missing on 192 of 248 rows (m2, `A_nonmiss_Dclose_tsset_date = 192 of 248`).
- **Storage type follows tsrevar** (m7, m8). The serset types matched tsrevar's: `D.x` (double) is double, `D.xf` (float) is float. The serset values are identical to `gen double = D.x` (sum |diff| 0), and `gen double = D.xf` differs from them by 0.000845 in total. tsrevar's types on auto: `D.price` (int) float, `L.big` (long) long, `D.b` (byte) float, `L.mpg` (int) int. So dash should copy `tsrevar`'s temporary variable (`generate <its type>`) rather than generate a double.
- **Display format is the base variable's** (m5, m7):
  - `format volume %12.0fc`: `scatter L.volume t` ticks read "5,000 … 25,000", as volume's do.
  - `format close %9.2f`: `scatter D.close t` ticks read "-50.00 0.00 50.00 100.00".
  - `scatter close L.date`: dates "01jan2001 …".
  - `scatter close D.date`: x ticks "02jan1960 … 08jan1960", that is, a day difference drawn in %td.
- **Value label is the base variable's** (m5). `scatter L.foreign t, ylabel(, valuelabel)` draws "Domestic", "Foreign" and the title "Car origin, L". `gen double z = L.foreign` carries no value label, so dash must attach it explicitly.

### 2.5 twoway refusals that dash must copy once operators are accepted

- **Unsorted data** (m5): `sort mpg` then `twoway scatter L.mpg t` gives "not sorted" r(5). `gen double z2 = L.mpg` gives the same message and code, so generating the column at build reproduces this naturally.
- **by()**: any `by()` with an operated variable in any layer is refused, "not sorted" r(5). This was measured for:
  - `scatter D.close t, by(g)` (tsset t);
  - `scatter L.y tt, by(id)` and `line L.y tt, by(id)` on xtset panel data, data sorted;
  - `tsline D.close, by(g)`;
  - the mixed `(scatter close t) (line D.close t), by(g)`.

  The plain `tsline close, by(g)` and `scatter close t, by(g)` draw (m4, m9). The likely cause, inferred and not measured: bygraph re-sorts by `byvars (obsnum)`, which drops the tsset sort mark.
- **Bare `sort` with an operated x** (m9) prints two lines, "factor-variable and time-series operators not allowed" and "option sort() incorrectly specified", r(198).
  - Refused on scatter, line, connected, area, bar, spike, dropline, dot, mspline, mband, and on rarea, rbar, rspike, rcap, rline, rconnected, rcapsym and rscatter (`low high L.t`).
  - Accepted (rc 0) on lfit, qfit, lfitci, qfitci, the five pc types, tsline and tsrline.
  - An operated y with `sort` is always accepted.
  - `sort(L.t)` is "L.t invalid name" r(198) in twoway, and dash already gives the same (m5).
- **Option variables**:
  - twoway refuses `mlabel(L.make)` with "variable L not found" r(111), and `by(L.foreign)` and `colorvar(L.mpg)` with r(101).
  - dash refuses all three with r(198) "not a time-series expression" (test_help_claims_2.cscript HC2-10d..i).
  - This is not P1.7 (option variables, not plot variables); it is out of scope.
- **Weights**: `twoway lfit mpg t [aw=L.weight]` gives rc 0, while dash refuses with "[aweight=L.weight] must name one variable; dash cannot evaluate a weight expression. Generate it first: generate double w = L.weight", r(198) (m5). That is GAPS2 G17, tracked under P1.14 ("weight expressions"), not P1.7.

## 3. Why the renderer cannot take `L.close` as a column name

- The data writer runs `unab` on its varlist (dash.ado:4544), which refuses operators.
- `_dash_take_qual_columns` (dash_render.py:27657) refuses or drops every `__dash*` column the spec does not name as a qualifier. Probe: `dr._dash_take_qual_columns(df_with___dasht1, spec)` gives `ValueError: dash: the data hold a column named '__dasht1'; names beginning with __dash are reserved…`.
- Tooltip fields are admitted only for Stata names (dash_render.py:27243, 27337; `_dash_is_stata_name('L.close')` is False). A dotted column would be left out of every tooltip.

So each operator expression must become a Stata-named column (`__dasht<k>`) that the spec maps back to the expression and to twoway's text.

## 4. Proposed approach (both routes, both modes)

The design mirrors the qualifier columns (`__dashq<k>`, `_dash_qual_gen`) and WP-29's join-order columns (`__dashs<k>`, `_dash_sort_gen`, `_dash_take_sort_columns`). It is the same lifecycle: rewrite the spec in Mata, make the columns in Stata inside the export block, export them, drop them at once, and have the renderer validate them on load.

### 4.1 Registration (dash.ado)

1. **Parsers.**
   - `_dash_parse_varpart_3v` (1388) and `_dash_parse_varpart_4v` (1420) declare `syntax varlist(numeric ts)`.
   - `_dash_parse_varpart_1v` (1353) is unchanged: histogram and kdensity keep refusing in twoway's words.
   - For the std family, add `_dash_parse_varpart_ts`, a copy of `_dash_parse_varpart_std` with `varlist(numeric ts)`, and dispatch at 3797: types in `fpfit fpfitci lowess lpoly lpolyci` keep `_std`, every other std type uses `_ts`.
   - A separate program is preferred to a leading mode word, so the macro-safe `0` handling that JSE-44/46/47/66/69 certify is left untouched.
   - Every refusal in 2.2 then comes from `syntax` itself, in twoway's words.
2. **by() refusal** in `_dash_plot`, after the segment loop (around 5210, where `_byq_vv_<k>` is gathered). When the graph has `by()` and any plot variable of any segment contains ".", print `display as error "not sorted"` and exit 5, before anything is registered (see Decision D1). Every y of a multi-y segment needs checking: `_seg_vars_out` (4386) holds only word 1 of yvarlist plus x, so add a `_seg_hasts_out` flag.
3. **Bare-sort refusal** in `_dash_process_segment`, once x is known (3843 std, 3601ff range). If `s(sort)` is set (bare `sort`, dash.ado:1209), the type is in the 18-type set of 2.5, and x contains ".", print the two twoway lines and exit 198.

### 4.2 Build and export (dash_parse.mata and dash.ado)

4. **Mata, beside `_dash_qual_*` and `_dash_sort_*`:**
   - `_dash_ts_reset()`.
   - `_dash_ts_rewrite(json, errmacro)`: scans the plot-variable keys yvar, xvar, yvar1, yvar2, y1var, x1var, y2var and x2var (never var, mlabel, colorvar or wexp). It treats a value containing "." as an operator expression, assigns `__dasht<k>` per distinct expression across the whole dashboard, and replaces the value.
   - `_dash_ts_export()`: fills `_dts_n` and `_dts_e<k>` like `_dash_qual_export`.
   - `_dash_ts_meta()`: builds, by value and JSON-escaped, the `formats` entries (`st_varformat(base)`) and the `ts_cols` map `{"__dasht<k>": {"expr": "L.close", "label": "<twoway text>"}}`. The label is `st_varlabel(base) != "" ? label + ", " + op : expr`, computed by value so the 80-character limit never truncates it.
   - **Security:** the registry is ordinary globals that a do-file can edit. Before an expression reaches `tsrevar`, check it against the canonical form syntax produces, `^([LFDS][1-9][0-9]*|[LFDS])+\.<Stata name>$`, and check the base against `_st_varindex`. Anything else is refused r(198) "registry entry … holds a variable dash cannot read" (as `_dash_qual_rewrite` does).
5. **Stata `_dash_ts_gen <cmdname>`**, run after `_dash_qual_gen` (whose `__dash*` clash check, 4777, already covers `__dasht*`) and `_dash_sort_gen`:
   - If `_dta[_TStvar]` is empty, print "time variable not set" and exit 111.
   - For each k: `tsrevar <expr>` (r(5) "not sorted" and r(111) pass through), `local ty : type <tempvar>`, `quietly generate <ty> __dasht<k> = <tempvar>`, copy the base's value label (`label values`).
   - On any error, drop what was made. Return `c_local _dash_ts_vars`.
6. **Wiring.**
   - In `_dash_render_immediate`, after `_dash_qual_rewrite` (6524): rewrite, subtract the ts names from `needed_vars`, append the ts formats to `_dash_fmt_json` (6696, skipped today because the columns do not yet exist), add `_dts_n` to `_dash_cell_cap` (beside `_dq_n + _ds_n`), generate after `_dash_sort_gen` (6730), pass to `_dash_write_data` (6741), drop with the qualifier and sort columns, and add `"ts_cols":{…}` beside `_ds_json` in master_json (6769).
   - In `_dash_prepare_spec`, do the same: per-graph rewrite beside `_qg_<k>` (7606), `row_vars`/`comp_cells` accounting, the export block (7873-7886) and master_json (8049).
   - `dash serve` inherits through `_dash_prepare_spec`.
7. The reserved-prefix messages (4781 and the `__dashs` copy around 4914) also name "its time-series columns __dasht#".

### 4.3 Renderer (dash_render.py)

8. **Validation.**
   - Add `_DASH_TS_PREFIX = "__dasht"` and `_DASH_TS_NAME_RE`.
   - `_dash_ts_cols_named(spec)` validates `build_options.ts_cols`: name regex, the expression against the canonical regex, label text ≤ 244 characters.
   - `_dash_take_ts_columns(df, spec)` checks each named column is present and numeric, and keeps it in the frame. It runs before `_dash_take_qual_columns`, which gains an exemption for the names it validated (a `keep` argument). Every other reserved column stays refused.
9. **Labels in both modes.** `_dash_ts_labels(spec)` merges `{col: label}` into `variable_labels`. Call it in `DashboardRenderer._load_data` (29293, saved) and in the generated app (34586, served).
   - Axis titles, legend keys (`_dash_legend_key`) and tooltip labels then read twoway's text with no change to `_dash_axis_labels` or `_dash_legend_key`.
   - Formats come from the spec's formats map, so `_dash_load_columns` turns `L.date` into a date axis.
   - Value labels come from the data file.
   - Storage types come from the writer, so a float column shows float32 digits.
10. **Filter moves.** No refit code changes. The ts columns are fixed at build like any variable, so a filter move selects rows of an already computed series. That is twoway's `if` semantics (2.4) in both modes.
    - The served app refits computed layers (lfit on L.close) over the kept rows.
    - The saved page keeps decision M3 (no JS refit).
11. **No internal names reach the user.**
    - `_dash_csv_meta` gains an optional `display_names`, so the CSV header reads the expression (Decision D2); this covers the saved JS writer and the served `_send_csv` at 36200.
    - Audit the 51 `_dash_display(` call sites for a column name in a note, and route those through a `_dash_col_display` helper.
    - Add the new helpers to the served-app name list (around 33093) so `TestTheServedAppCarriesEveryName` holds.

### 4.4 Help and records

## 8. Decisions for the maintainer

- **D1. by() with an operated variable.**
  - Options: (a) refuse it as twoway does, "not sorted" r(5), plus one dash hint line ("generate the variable first"); (b) draw the panels (dash's own extension, documented).
  - Implications: (a) keeps drop-in parity and is cheap. (b) needs ts columns made before the by() sort and a help exception, and some users would get a graph twoway refuses.
  - **Recommend (a).**
- **D2. CSV header of an operator column.**
  - Options: (a) the expression `L.close`; (b) twoway's serset name `L_close`; (c) leave operator columns out of the CSV.
  - Implications: (a) is what the user typed, but `import delimited` renames it. (b) can collide with a real variable. (c) loses drawn data.
  - **Recommend (a).**
- **D3. Weights `[aw=L.x]`.** Scope them to P1.14 (G17) with the shared generator, not to P1.7. **Recommend P1.14.**
