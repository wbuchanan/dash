**M2. Stata facts (p1_env.do).**
```
ENV os=Unix osdtl= machine_type=Mac (Apple Silicon)
ENV stata_version=19.5 version=19.5 edition=MP mode=batch console=console
ENV sysdir_base=/Applications/StataNow/ado/base/
ENV sysdir_plus=/Users/billy/Library/Application Support/Stata/ado/plus/
ENV python_exec=/opt/anaconda3/bin/python3          (lipo: arm64 only)
ENV DASH_PROBE_REPO via : environment = [/tmp/some repo/with space]
```
`: environment` passes a path with spaces intact. `c()` has no value naming the running do-file, so the root must be passed in.

**M3. Hazards in an environment root (p2/p3).** Run with `DASH_PROBE_DOLLAR='/tmp/a$S_PROBE/b'` and `global S_PROBE "EXPANDED"`:
```
P2 dollar raw=[/tmp/aEXPANDED/b]          <- a $name inside the value is expanded on use
P2 backtick len=8                         <- '/tmp/a`x'/b' lost its `x' (11 chars raw)
P2 quote=[/tmp/a"b]  rc=0
P3 dollar macval=[/tmp/a$S_PROBE/b]  has-dollar=1
P3 btick has-backtick=1 len=11
```
The root must therefore be checked through `macval()` and refused when it holds `$`, a backtick or `"`. This mirrors `_stata_path_ok` in measure_stata_coverage.py.

**M4. Batch log naming rules out passing the root as an argument.** Commit d285cf7 measured that Stata's batch mode names the log "after the command line's text past its last /". So GAPS2's plan (`do run_all_cscripts.do "$REPO"`) would rename `run_all_cscripts.log`, which `run_cert_suite.sh:19` reads by that name. An environment variable avoids this, as well as any quoting problem with spaces.

**M5. The suite with Stata's tree elsewhere.** The `_STATA_BASE` constants were pointed at a missing directory by a scratch plugin:
```
PYTHONPATH=<scratch> python3 -m pytest -q -n0 -p relocate_plugin test/test_help_claims_1.py::TestTheHeader test/test_help_claims_8.py -k "TestTheHeader or other_commands_named"
FAILED test_help_claims_1.py::TestTheHeader::test_stata_is_installed_where_the_links_are_checked
FAILED test_help_claims_1.py::TestTheHeader::test_every_see_also_link_opens_a_current_help_file
2 failed, 4 passed, 1 skipped          (unpatched: 7 passed)
```
Under `DASH_STRICT=1` the skip also fails `make test`.

**M6. Arch detection: `uname -m` lies under Rosetta.**
```
native:            uname -m=arm64   hw.optional.arm64=1  proc_translated=0
arch -x86_64 sh:   uname -m=x86_64  hw.optional.arm64=1  proc_translated=1
arch -x86_64 sh -c 'arch -arm64 uname -m'  -> arm64
sysctl -n hw.optional.no_such_key -> "unknown oid", rc=1   (stand-in for an Intel Mac, which lacks the key: inferred)
arch -x86_64 /opt/homebrew/bin/python3 -> "Bad CPU type in executable"   (what arch -arm64 does to a binary without the slice)
```
GAPS2 proposed using `arch -arm64` only when `uname -m` is arm64. Under a Rosetta parent (an x86_64 terminal or make), that rule drops the prefix, and Stata starts its x86_64 slice, which cannot load the arm64-only `/opt/anaconda3` libpython. That is exactly the failure the prefix exists to prevent (run_all_cscripts.do:6-13). The rule must use `sysctl -n hw.optional.arm64`.

**M7. Binary slices, read with `file -L` only (nothing run).**

| Stata | Slices of `stata-mp` |
|---|---|
| Stata 14, Stata 15 | x86_64 only |
| Stata 16, 17, 18.0, 18.5 (`/Applications/Stata`) and StataNow 19.5 | x86_64 and arm64 |

So `arch -arm64` on an x86_64-only binary fails "Bad CPU type". The wrapper also checks the binary's slices.

## 3. Approach (runner slice only, per M4)

This item draws nothing, so the saved/served-mode question does not apply. No product file changes: no edits to dash.ado, dash_parse.mata, dash_render.py or the help files.

1. **New `scripts/stata_batch.sh`** (POSIX sh), the only place that may name `arch`.
   - It execs `$STATA` (default `/usr/local/bin/stata-mp`) with `"$@"` unchanged, so batch log names are unchanged.
   - It refuses, rc 2, a `STATA` whose basename is not a console Stata (`stata`, `stata-mp`, `stata-se`, `stata-be`, `stata-ic`). This rejects `StataMP`/`stataMP` (the GUI that parks on a modal alert) and Linux `xstata*`.
   - `STATA_ARCH` is auto by default. Auto means `arch -arm64` only when `uname -s` = Darwin, `sysctl -n hw.optional.arm64` = 1, and `file -L "$STATA"` lists arm64. `none`, `arm64` and `x86_64` force a choice; anything else is refused with rc 2.
2. **Route every runner through it.**
   - `run_cert_suite.sh:17`, `run_release_gate.sh:34,42`, `stata_python_exec.sh:17` and `stata_slot.sh:10` become `sh "$REPO/scripts/stata_batch.sh" -b do ...`.
   - `stata_slot.sh` gains `STATA="${STATA:-...}"` and keeps its `<dir> <file.do>` interface and lock directories. It is in use by WP-30 agents, so land this change while no slot is held.
   - `measure_stata_coverage.STATA` becomes `["sh", <REPO>/scripts/stata_batch.sh, "-b", "do"]`.
3. **Root from the environment, not the checkout.** In `test/run_all_cscripts.do:15-28`, drop the two literals. The new header:
   - reads `local dashdir : environment DASH_REPO`;
   - if it is empty, uses `c(pwd)` (the documented "run from the dash/ directory" form);
   - refuses `$`, a backtick or `"` through `macval()` (r(198));
   - strips trailing `/` or `\`;
   - confirms `dash.ado` and `test/run_all_cscripts.do` exist (r(601) otherwise). Without this check a wrong root would silently test a PLUS-installed dash;
   - then runs `adopath ++` and `cd` as now, and adds a self-check that `findfile dash.ado` equals `` `dashdir'/dash.ado `` (exit 9 otherwise).
   - `run_cert_suite.sh` exports `DASH_REPO="$REPO"` and refuses a `$REPO` holding `$`, a backtick or `"`.
   - `measure_stata_coverage.runner_do` stops regex-rewriting `adopath ++ "..."` and `local dashdir "..."`. It keeps the setup insertion after `` cd "`dashdir'" ``, and `_stata()` sets `env["DASH_REPO"] = tree`.
4. **Extractors and generators.** The 15 `scripts/extract_*_truth.do` with literals and `test/fixtures/twoway_corpus.do` get the same 8-line DASH_REPO stanza in place of `global Z?_REPO "/Users/..."`. It refuses (r(198)) when the root is unset and `c(pwd)` is not a tree, and never falls back to the main checkout. This includes `extract_join_order_truth.do`, `extract_filter_truth.do` and `extract_embedded_rows_truth.do`, which do fall back today.
   - The StataJSON adopath and the `ZQ_JSONIO_*` globals (`extract_abbrev_truth.do:39`, `extract_date_truth.do:64-71`, `twoway_corpus.do:53`) read `: environment STATAJSON_DIR`. When it is empty, the adopath line is skipped and extract_date_truth's jsonio probe (section D) writes a "not run" record.
   - Header "Run with" comments become `DASH_REPO=<repo> sh scripts/stata_batch.sh -b do scripts/<file>.do`.
   - `regen_option_surface.py:17` and `wire_option_reporting.py:9` take `REPO` from `__file__`, as measure_stata_coverage.py:62 does.
   - Committed fixtures are NOT regenerated. Their provenance strings stay, because they are records of where the measurements ran.
5. **The pytest suite's Stata tree.** `_STATA_BASE` and `_STATA_PLUS` in test_help_claims_1.py and `_STATA_BASE` in test_help_claims_8.py become `os.environ.get("DASH_STATA_BASE"/"DASH_STATA_PLUS") or <current macOS default>`. The Makefile is unchanged; a machine with Stata elsewhere sets the variables.
6. **Records.**
   - Two BUGS.md entries, each written failing first: "make cert from a worktree or copy tests the main checkout" (K1-a) and "the runners force arch -arm64 on every machine and miss it under Rosetta" (K1-b).
   - The deferred remainder is filed as a new P2 residual or ROADMAP package: Linux, Windows (`/e` batch flag, cmd.exe), Intel Mac, GUI Stata, and the WP-29 S08/S09/S13 paths.
   - The 4 pinned tests are FLIPPED with the reason, never deleted (WP-29 precedent).
